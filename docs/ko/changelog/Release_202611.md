# 변경 로그 – 릴리스 2026.11  

릴리스 2026.11은 세 가지 주요 추가 기능을 중심으로 구성됩니다:

- **digna Data Reconciliation (Beta)**: 데이터가 시스템 간에 이동하는 동안 일관성을 유지하는지 검사합니다  
- **digna Agentic (Beta)**: digna MCP Server를 통해 AI 에이전트에게 digna를 개방합니다  
- **digna Engine**: 선택적으로 digna 내부에서 데이터를 프로파일링하고, 서로 다른 데이터베이스 기술 간의 참조 무결성 검사를 가능하게 합니다  

---

## 새로운 기능  

### digna Data Reconciliation (Beta) – 소스에서 대상까지의 일관성  
데이터는 보고서에 도달하기 전에 여러 시스템을 거치는 경우가 많습니다. digna Data Reconciliation (Beta)은 **대상** 데이터 소스를 그것이 만들어진 **소스**와 비교하고, 둘이 더 이상 일치하지 않으면 알림을 보냅니다.

- 대상 데이터 소스의 새 **Data Reconciliation** 탭에서 이름이 지정된 규칙으로 구성합니다  
- Data Reconciliation이 활성화된 프로젝트의 모든 데이터 소스를 소스로 사용할 수 있습니다  
- 표준 대사(reconciliation) 절차와 ETL 프로세스 결과 검증 등에 활용할 수 있습니다  
- 규칙 유형은 **Exact**와 **AI** 두 가지입니다  

**Exact 규칙 – 데이터 품질 규칙으로서의 대사**: 데이터 품질 규칙처럼 하나의 소스와 하나의 대상 사이에서 무엇이 일치해야 하는지를 정확히 정의합니다.

  - 하나의 소스 데이터 소스와 하나의 대상 데이터 소스를 비교  
  - 통계와 속성을 기준으로 대상 검사와 소스 검사를 짝지음(예: 행 수 또는 금액 열의 합계)  
  - **absolute** 허용 오차(예: ± 10) 또는 **relative** 허용 오차(예: 소스의 ± 0.5 %)로 차이를 허용  
  - 타임라인에 매일의 차이가 허용 오차와 함께 표시됩니다  

**AI 규칙 – 데이터 관측성으로서의 대사**: digna는 다른 모듈에서 데이터를 관측하는 방식과 마찬가지로 대상이 소스를 어떻게 따르는지 학습하고, 그 관계가 깨지면 알림을 보냅니다.

  - 여러 소스 데이터 소스의 검사를 하나의 대상의 검사와 결합  
  - 둘 사이의 로직(조인, 필터, 집계)을 알거나 작성할 필요가 없습니다  
  - 모델이 이력에서 대상이 같은 날의 소스를 어떻게 따르는지 학습  
  - 각 대상 검사는 해당 일의 소스 값으로 예측되며, 대상이 규칙 자체의 과거 오차 범위를 벗어나면 digna가 알림을 보냅니다  
  - 각 규칙에는 고유한 **Model settings**(**Sensitivity**, **Memory**, **Model Complexity**)가 있습니다  

대사 검사는 규칙별 타임라인과 함께 대시보드에 표시됩니다. 전체 검사 상태에 반영되며 알림을 트리거합니다.

**영향:** 대사의 양쪽 측면을 모두 다룹니다. Exact 규칙은 소스와 대상 간의 알려진 통제를 적용하고, AI 규칙은 ETL 프로세스와 같은 복잡한 흐름을 모니터링하므로, 수작업으로 작성한 대사 SQL 없이도 도중에 유실되거나 변경된 데이터를 포착합니다.

---

### digna Agentic (Beta) – AI 에이전트를 위한 digna  
digna Agentic (Beta)의 첫 번째 버전입니다. 이제 AI 에이전트가 digna와 함께 작업하고, 데이터에 대한 비즈니스 질문에 답하며, 구성 개선을 도울 수 있습니다.

**digna MCP Server**: Claude 및 기타 AI 에이전트가 Model Context Protocol을 통해 digna와 함께 작업할 수 있게 합니다.

  - 프로젝트, 데이터 소스, 규칙, 검사 일정 및 구독 관리  
  - 알림을 조사하기 위해 검사 상태를 개별 검사 단위까지 조회  

**데이터 소스 및 속성 설명**: 데이터 소스나 속성에 무엇이 들어 있는지 평이한 언어로 설명합니다.

  - AI 에이전트는 설명을 사용해 데이터를 해석합니다  
  - 데이터에 대한 비즈니스 질문을 하면, AI 에이전트가 digna가 모니터링하는 내용을 바탕으로 답합니다  
  - digna의 현재 구성으로 질문에 답할 수 없는 경우, AI 에이전트가 가능한 범위에서 데이터 소스와 그 속성에 대한 변경(예: 새 데이터셋 추가)을 제안합니다  

**영향:** 데이터에 대한 비즈니스 질문을 평이한 언어로 할 수 있게 하고, AI 에이전트가 digna 구성과 데이터 품질 문제 조사를 돕게 합니다.

---

### digna Engine – 원하는 곳에서 프로파일링  
기본적으로 digna는 데이터가 있는 곳, 즉 소스 데이터베이스에서 데이터를 프로파일링합니다. digna Engine은 또 하나의 선택지를 추가합니다. digna가 소스에서 데이터를 내보내 digna Engine 내부에서 프로파일링합니다.

- 필수가 아닌 선택 사항: 소스 데이터베이스에서의 프로파일링도 계속 사용할 수 있습니다  
- 데이터베이스 연결마다 **프로파일링 위치**(profiling location)로 **Source Database** 또는 **digna Engine**을 선택합니다  
- 지원되는 모든 소스 기술에서 사용할 수 있습니다  

**연결 간 참조 무결성**: 일부 검사는 데이터를 내보내야 합니다. digna Engine은 이러한 경우를 위해 **digna Data Validation**을 확장합니다.

  - **서로 다른 데이터베이스 연결**에 있는 데이터 소스 간의 **참조 무결성 검사**, 서로 다른 데이터베이스 기술(예: Oracle과 PostgreSQL) 간 포함  
  - 두 프로파일링 위치 모두에서 작동: Source Database의 경우 키 열만 digna Engine으로 내보냅니다  
  - 검사가 두 연결에 걸쳐 실행되면 대시보드에 표시됩니다  

**영향:** 데이터를 어디에서 프로파일링할지 선택할 수 있게 하고, 서로 다른 데이터베이스 기술에서 실행되는 시스템 간의 관계를 보장합니다.

## 프로파일링 개선사항  

이번 릴리스는 무엇을 어떻게 프로파일링할지에 대해서도 사용자에게 더 많은 제어권을 제공합니다.

### 쿼리 속성(Query Attributes) – 사용자 정의 열  
- 인공 열 정의: 데이터 소스의 하나 이상의 열에 대한 SQL 표현식  
- 각 쿼리 속성에는 고유한 이름이 있습니다  
- 다른 속성과 마찬가지로 프로파일링되고 검사됩니다  

### DATE 열 범주  
- 속성을 위한 새 **Date** 범주  
- 검사 대상 날짜를 기준으로 한 메트릭  

### 온디맨드 프로파일링  
- 검사를 실행하지 않고도 임의의 속성을 특정 날짜의 전체 스냅샷에 대해 프로파일링  
- 속성의 열 유형(**Numerical**, **Categorical**, **Date**, **Unspecified**)을 설정하는 데 도움이 됩니다

## 이 릴리스의 혜택 대상  

- **데이터 엔지니어:** digna Data Reconciliation (Beta)을 통한 ETL 결과 검증  
- **재무, 리스크 및 컨트롤링 팀:** digna Data Reconciliation (Beta)의 Exact 규칙으로 구현하는 표준 대사 절차  
- **데이터 품질 및 거버넌스 팀:** digna Engine을 통한 데이터베이스 기술 간 참조 무결성  
- **비즈니스 사용자:** digna Agentic (Beta)으로 AI 에이전트가 답하는 데이터 관련 비즈니스 질문  
- **AI 및 자동화 팀:** digna Agentic (Beta)을 통해 digna와 함께 작업하는 AI 에이전트
