# Журнал изменений – релиз 2026.11  

Релиз 2026.11 построен вокруг трёх крупных дополнений:

- **digna Data Reconciliation (Beta)**: проверяет, что данные остаются согласованными при перемещении между системами  
- **digna Agentic (Beta)**: открывает digna для ИИ-агентов через digna MCP Server  
- **digna Engine**: при необходимости профилирует данные внутри digna и позволяет выполнять проверки ссылочной целостности между разными технологиями баз данных  

---

## Новые возможности  

### digna Data Reconciliation (Beta) — согласованность от источника до цели  
Прежде чем попасть в отчёт, данные часто проходят через несколько систем. digna Data Reconciliation (Beta) сравнивает **целевой** источник данных с **источниками**, из которых он построен, и оповещает, когда они перестают совпадать.

- Настраивается в виде именованных правил на новой вкладке **Data Reconciliation** целевого источника данных  
- Источником может быть любой источник данных проекта с включённым Data Reconciliation  
- Сценарии использования включают стандартные процедуры сверки и валидацию результатов ETL-процессов  
- Два типа правил: **Exact** и **AI**  

**Правила Exact — сверка как правило качества данных**: Вы точно задаёте, что должно совпадать между одним источником и одной целью, как в правиле качества данных.

  - Сравнение одного исходного источника данных с одним целевым источником данных  
  - Сопоставление целевой проверки с исходной проверкой по статистике и атрибуту, например количество строк или сумма денежного столбца  
  - Допустимое расхождение с **absolute** допуском (например, ± 10) или **relative** допуском (например, ± 0.5 % от источника)  
  - Временная шкала показывает расхождение за каждый день относительно допуска  

**Правила AI — сверка как наблюдаемость данных**: digna изучает, как цель следует за своими источниками, так же как digna наблюдает за данными в других модулях, и оповещает, когда эта связь нарушается.

  - Объединение проверок из нескольких исходных источников данных с проверками одной цели  
  - Не нужно знать или описывать логику между ними (соединения, фильтры, агрегации)  
  - Модель учится на истории тому, как цель следует за своими источниками в тот же день  
  - Каждая целевая проверка прогнозируется по значениям источников за этот день, и digna оповещает, когда цель выходит за пределы полосы собственных прошлых ошибок правила  
  - У каждого правила есть собственные **Model settings**: **Sensitivity**, **Memory** и **Model Complexity**  

Проверки сверки отображаются на дашборде с временной шкалой для каждого правила. Они учитываются в общем статусе инспекции и запускают уведомления.

**Влияние:** Охватывает обе стороны сверки. Правила Exact обеспечивают известные контроли между источником и целью, а правила AI отслеживают сложные потоки, например ETL-процессы, поэтому данные, потерянные или изменённые по пути, обнаруживаются без написанного вручную SQL для сверки.

### digna Agentic (Beta) — digna для ИИ-агентов  
Первая версия digna Agentic (Beta). Теперь ИИ-агенты могут работать с digna, отвечать на бизнес-вопросы о ваших данных и помогать улучшать вашу конфигурацию.

**digna MCP Server**: Позволяет Claude и другим ИИ-агентам работать с digna через Model Context Protocol.

  - Управление проектами, источниками данных, правилами, расписаниями инспекций и подписками  
  - Чтение статусов инспекций вплоть до отдельной проверки для расследования оповещений  

**Описания источников данных и атрибутов**: Опишите простым языком, что содержит источник данных или атрибут.

  - ИИ-агенты используют описания, чтобы интерпретировать ваши данные  
  - Задавайте бизнес-вопросы о своих данных, и ИИ-агенты ответят на них на основе того, что отслеживает digna  
  - Если текущая конфигурация digna не позволяет ответить на вопрос, ИИ-агент по возможности предлагает изменения источника данных и его атрибутов, например добавление нового набора данных  

**Влияние:** Позволяет задавать бизнес-вопросы о своих данных простым языком, а ИИ-агентам — помогать настраивать digna и расследовать проблемы качества данных.

### digna Engine — профилирование там, где вы выберете  
По умолчанию digna профилирует данные там, где они хранятся, — в исходной базе данных. digna Engine добавляет ещё один вариант: digna экспортирует данные из источника и профилирует их внутри digna Engine.

- Опционально, а не обязательно: профилирование в исходной базе данных остаётся доступным  
- Выбирается для каждого подключения к базе данных как его **место профилирования** (profiling location): **Source Database** или **digna Engine**  
- Доступно для каждой поддерживаемой технологии источников  

**Ссылочная целостность между подключениями**: Некоторым проверкам нужен экспорт данных. Для таких случаев digna Engine расширяет **digna Data Validation**.

  - **Проверки ссылочной целостности** между источниками данных на **разных подключениях к базам данных**, в том числе с разными технологиями баз данных (например, Oracle и PostgreSQL)  
  - Работает с обоими местами профилирования: для Source Database в digna Engine экспортируются только ключевые столбцы  
  - Дашборд показывает, когда проверка выполняется между двумя подключениями  

**Влияние:** Позволяет выбирать, где профилируются данные, и обеспечивает соблюдение связей между системами, работающими на разных технологиях баз данных.

## Улучшения профилирования  

Этот релиз также даёт пользователям больше контроля над тем, что и как профилируется.

### Атрибуты запроса (Query Attributes) — пользовательские столбцы  
- Определяйте искусственные столбцы: SQL-выражение над одним или несколькими столбцами источника данных  
- У каждого атрибута запроса есть собственное имя  
- Профилируется и проверяется, как любой другой атрибут  

### Категория столбцов DATE  
- Новая категория **Date** для атрибутов  
- Метрики относительно даты инспекции  

### Профилирование по запросу  
- Профилируйте любой атрибут на полном снимке данных за одну дату без запуска инспекции  
- Помогает задать тип столбца атрибута: **Numerical**, **Categorical**, **Date** или **Unspecified**

## Кому будет полезен этот релиз  

- **Data Engineers:** валидация результатов ETL с помощью digna Data Reconciliation (Beta)  
- **Команды финансов, рисков и контроллинга:** стандартные процедуры сверки в виде правил Exact в digna Data Reconciliation (Beta)  
- **Команды качества данных и управления:** ссылочная целостность между технологиями баз данных с помощью digna Engine  
- **Бизнес-пользователи:** ответы ИИ-агентов на бизнес-вопросы о данных с digna Agentic (Beta)  
- **Команды ИИ и автоматизации:** ИИ-агенты, работающие с digna через digna Agentic (Beta)
