# digna CLI Reference 2026.01
**2026-01-15**

यह पृष्ठ ***digna*** CLI रिलीज़ **2026.01** में उपलब्ध सभी कमांड्स का पूरा संदर्भ दस्तावेज़ करता है, जिसमें उपयोग के उदाहरण और विकल्प शामिल हैं।

---

## CLI बेसिक्स

---

### help
`--help` विकल्प उपलब्ध कमांड्स और उनके उपयोग के बारे में जानकारी प्रदान करता है। इस विकल्प का उपयोग करने के दो मुख्य तरीके हैं:

1. **सामान्य सहायता दिखाना:**
   
   कीवर्ड के तुरंत बाद `--help` का उपयोग करें:
   ```bash
   dignacli --help
   ```

2. **विशिष्ट कमांड के लिए सहायता प्राप्त करना:**  
  
   किसी विशिष्ट कमांड के बारे में विस्तृत जानकारी के लिए उस कमांड के साथ `--help` जोड़ें।  
   उदाहरण के लिए, `add-user` कमांड की मदद प्राप्त करने के लिए चलाएँ:
   ```bash
   dignacli add-user --help
   ```

   ### आउटपुट:
      
   - **कमांड विवरण:** बताता है कि कमांड क्या करता है।  
   - **सिंटेक्स:** सटीक सिंटेक्स दिखाता है, जिसमें आवश्यक और वैकल्पिक आर्ग्युमेंट शामिल हैं।  
   - **विकल्प:** किसी कमांड से संबंधित विकल्पों की सूची और उनके विवरण।  
   - **उदाहरण:** कमांड को प्रभावी ढंग से चलाने के उदाहरण प्रदान करता है।

### check-config

`check-config` कमांड ***digna*** CLI टूल में एक उपयोगिता है जो ***digna*** की कॉन्फ़िगरेशन का परीक्षण करने के लिए डिज़ाइन की गई है। यह कमांड यह सुनिश्चित करती है कि ***digna*** के घटक config.toml में आवश्यक कॉन्फ़िगरेशन तत्व पा सकें।

#### विकल्प

- `--configpath`, `-cp`: वह फ़ाइल या निर्देशिका जिसमें कॉन्फ़िगरेशन होता है। यदि प्रदान नहीं किया गया तो ../config.toml का उपयोग किया जाएगा।
      
#### कमांड उपयोग
```bash
dignacli check-config
```

सफलतापूर्वक निष्पादन पर, कमांड कॉन्फ़िगरेशन की पूर्णता की पुष्टि दिखाती है।  
  
यदि कॉन्फ़िगरेशन अधूरा प्रतीत होता है, तो लापता कॉन्फ़िगरेशन तत्व सूचीबद्ध किए जाएंगे।

  
### check-repo-connection

`check-repo-connection` कमांड ***digna*** CLI टूल में एक उपयोगिता है जो निर्दिष्ट ***digna*** रिपोजिटरी से कनेक्टिविटी और पहुँच का परीक्षण करने के लिए उपयोग की जाती है। यह कमांड सुनिश्चित करती है कि CLI रिपोजिटरी के साथ इंटरैक्ट कर सकता है।
      
#### कमांड उपयोग
```bash
dignacli check-repo-connection
```

सफलतापूर्वक निष्पादन पर, कमांड कनेक्शन की पुष्टि के साथ रिपोजिटरी के बारे में विवरण दिखाती है: Repository version, Host, Database और Schema।  
  
यदि रिपोजिटरी कनेक्शन सफल नहीं है, तो सही कॉन्फ़िगरेशन सेटिंग्स के लिए config.toml फ़ाइल की जाँच करें।


### version

इंस्टॉल की गई *dignacli* का संस्करण देखने के लिए `--version` विकल्प का उपयोग करें।  
  
#### कमांड उपयोग
```bash
dignacli --version
```
  
#### उदाहरण आउटपुट
```bash
dignacli version 2026.01
```

### लॉगिंग विकल्प
  
डिफ़ॉल्ट रूप से, ***digna*** कमांड्स का कंसोल आउटपुट न्यूनतम जानकारी देने के लिए डिज़ाइन किया गया है। अधिकतर कमांड अतिरिक्त जानकारी प्रदान करने के विकल्प देते हैं, जो निम्नलिखित विकल्पों का उपयोग करके सक्षम किए जा सकते हैं:  
  
-- verbose (-v)  
-- debug (-d)  
-- logfile (lf)  
 
“verbose” और “debug” विवरण के स्तर को परिभाषित करते हैं, जबकि “logfile” स्विच आउटपुट को कंसोल विंडो के बजाय किसी फ़ाइल में स्ट्रीम करने की अनुमति देता है।

## उपयोगकर्ता प्रबंधन

### add-user
  
***digna*** CLI में `add-user` कमांड का उपयोग नए उपयोगकर्ता को ***digna*** सिस्टम में जोड़ने के लिए किया जाता है।
  
#### कमांड उपयोग
```bash
dignacli add-user [OPTIONS] USER_NAME USER_FULL_NAME USER_PASSWORD
```
  
#### Arguments

- **USER_NAME**: नए उपयोगकर्ता के लिए उपयोगकर्ता नाम (आवश्यक)।
- **USER_FULL_NAME**: नए उपयोगकर्ता का पूरा नाम (आवश्यक)।
- **USER_PASSWORD**: नए उपयोगकर्ता का पासवर्ड (आवश्यक)।

#### विकल्प

- `--is_superuser`, `-su`: नए उपयोगकर्ता को एडमिन के रूप में निर्दिष्ट करने वाला फ़्लैग।
- `--valid_until`, `-vu`: उपयोगकर्ता खाते के लिए समाप्ति तिथि `YYYY-MM-DD HH:MI:SS` प्रारूप में सेट करता है। यदि सेट नहीं किया गया तो खाते की कोई समाप्ति तिथि नहीं होगी।

#### उदाहरण

उपयोगकर्ता नाम `jdoe`, पूरा नाम `John Doe`, और पासवर्ड `password123` के साथ नया उपयोगकर्ता जोड़ने के लिए:

```bash
dignacli add-user [OPTIONS] USER_NAME USER_FULL_NAME USER_PASSWORD
```
  
एक नया उपयोगकर्ता जोड़ने और खाते की समाप्ति तिथि सेट करने के लिए:
```bash
dignacli add-user jdoe "John Doe" password123 --valid_until "2024-12-31 23:59:59"
```

### delete-user
  
`delete-user` कमांड का उपयोग ***digna*** CLI में किसी मौजूदा उपयोगकर्ता को ***digna*** सिस्टम से हटाने के लिए किया जाता है।
  
#### कमांड उपयोग
```bash
dignacli delete-user USER_NAME
```
  
#### Arguments
- **USER_NAME**: उस उपयोगकर्ता का उपयोगकर्ता नाम जिसे हटाना है (आवश्यक)। यह कमांड द्वारा आवश्यक एकमात्र आर्ग्युमेंट है।

#### उदाहरण
```bash
dignacli delete-user jdoe
```
  
इस कमांड को चलाने पर उपयोगकर्ता `jdoe` को ***digna*** सिस्टम से हटा दिया जाएगा, उनकी पहुँच रद्द हो जाएगी और रिपोजिटरी से उनके संबंधित डेटा और अनुमतियाँ हट जाएँगी।

### modify-user

`modify-user` कमांड का उपयोग ***digna*** CLI में किसी मौजूदा उपयोगकर्ता का विवरण अपडेट करने के लिए किया जाता है।

#### कमांड उपयोग
  
```bash
dignacli modify-user <USER_NAME> <USER_FULL_NAME> [options]
```
  
#### Arguments
  
- **USER_NAME**: उस उपयोगकर्ता का उपयोगकर्ता नाम जिसे संशोधित करना है (आवश्यक)।
- **USER_FULL_NAME**: उपयोगकर्ता के लिए नया पूरा नाम (आवश्यक)।
  
#### विकल्प  
  
- `--is_superuser`, `-su`: उपयोगकर्ता को सुपरयूज़र के रूप में सेट करता है, जो उन्नत विशेषाधिकार देता है। इस फ़्लैग को किसी वैल्यू की आवश्यकता नहीं होती।  
- `--valid_until`, `-vu`: उपयोगकर्ता खाते के लिए समाप्ति तिथि सेट करता है, प्रारूप YYYY-MM-DD HH:MI:SS। यदि प्रदान नहीं किया गया तो खाता अनिश्चितकाल तक मान्य रहेगा।  
  
#### उदाहरण
  
उपयोगकर्ता `jdoe` का पूरा नाम “Johnathan Doe” में बदलने और उसे सुपरयूज़र बनाने के लिए:
```bash
dignacli modify-user jdoe "Johnathan Doe" --is_superuser
```

### modify-user-pwd
  
`modify-user-pwd` कमांड का उपयोग ***digna*** CLI में किसी मौजूदा उपयोगकर्ता का पासवर्ड बदलने के लिए किया जाता है।
  
#### कमांड उपयोग
```bash
dignacli modify-user-pwd <USER_NAME> <USER_PWD>
```
  
#### Arguments
  
- **USER_NAME**: उस उपयोगकर्ता का उपयोगकर्ता नाम जिसका पासवर्ड बदलना है (आवश्यक)।
- **USER_PWD**: उपयोगकर्ता के लिए नया पासवर्ड (आवश्यक)।
  
#### उदाहरण
  
उपयोगकर्ता `jdoe` का पासवर्ड `newpassword123` में बदलने के लिए:
```bash
dignacli modify-user-pwd jdoe newpassword123
```

### list-users

`list-users` कमांड ***digna*** CLI में सिस्टम में पंजीकृत सभी उपयोगकर्ताओं की सूची प्रदर्शित करता है।

#### कमांड उपयोग

```bash
dignacli list-users
```

इस कमांड को चलाने पर ***digna*** रिपोजिटरी से कनेक्ट होकर सभी उपयोगकर्ताओं की सूची दिखाई जाएगी, जिसमें उनका ID, उपयोगकर्ता नाम, पूरा नाम, सुपरयूज़र स्थिति, और समाप्ति समयस्टैम्प शामिल होंगे।

## रिपोजिटरी प्रबंधन

### upgrade-repo
  
`upgrade-repo` कमांड का उपयोग ***digna*** CLI में ***digna*** रिपोजिटरी को अपग्रेड या इनिशियलाइज़ करने के लिए किया जाता है। यह कमांड अपडेट लागू करने या पहली बार रिपोजिटरी इन्फ़्रास्ट्रक्चर सेटअप करने के लिए आवश्यक है।
  
#### कमांड उपयोग

```bash
dignacli upgrade-repo [options]
```
  
#### विकल्प
  
- `--simulation-mode`, `-s`: सक्षम होने पर यह विकल्प कमांड को सिमुलेशन मोड में चलाता है, जो उन SQL स्टेटमेंट्स को प्रिंट करता है जो निष्पादित किए जाते, पर वास्तविक रूप से उन्हें लागू नहीं करता। यह रिपोजिटरी में बदलाव किए बिना परिवर्तन पूर्वावलोकन के लिए उपयोगी है।  

  
#### उदाहरण
  
***digna*** रिपोजिटरी को अपग्रेड करने के लिए आप बिना किसी विकल्प के कमांड चला सकते हैं:
  
```bash
dignacli upgrade-repo
```  
अपग्रेड को सिमुलेशन मोड में चलाने के लिए (SQL स्टेटमेंट्स देखकर, लागू किए बिना):
  
```bash
dignacli upgrade-repo --simulation-mode
```
  
यह कमांड ***digna*** सिस्टम के रखरखाव के लिए महत्वपूर्ण है, यह सुनिश्चित करती है कि डेटाबेस स्कीमा और अन्य रिपोजिटरी घटक सॉफ़्टवेयर के नवीनतम संस्करण के साथ अद्यतित हों।

### encrypt
  
`encrypt` कमांड का उपयोग पासवर्ड को एन्क्रिप्ट करने के लिए किया जाता है।
  
#### कमांड उपयोग
  
```bash
dignacli encrypt <PASSWORD>
```
    
#### Arguments
- **PASSWORD**: वह पासवर्ड जिसे एन्क्रिप्ट करना है (आवश्यक)।
  
#### उदाहरण
  
किसी पासवर्ड को एन्क्रिप्ट करने के लिए पासवर्ड को आर्ग्युमेंट के रूप में देना होगा।  
उदाहरण के लिए, पासवर्ड `mypassword123` को एन्क्रिप्ट करने के लिए:
```bash
dignacli encrypt mypassword123
```
यह कमांड प्रदान किए गए पासवर्ड का एन्क्रिप्टेड स्वरूप आउटपुट करेगी, जिसे सुरक्षित संदर्भों में उपयोग किया जा सकता है। यदि पासवर्ड आर्ग्युमेंट प्रदान नहीं किया जाता है, तो CLI एक त्रुटि प्रदर्शित करेगा जो गायब आर्ग्युमेंट की ओर संकेत करेगी।

### generate-key
  
`generate-key` कमांड Fernet key जनरेट करने के लिए उपयोग किया जाता है, जो कि ***digna*** रिपोजिटरी में संग्रहीत पासवर्ड को सुरक्षित रखने के लिए आवश्यक है।
  
#### कमांड उपयोग
```bash
dignacli generate-key
```
  
## डेटा प्रबंधन

### clean-up

`clean-up` कमांड का उपयोग ***digna*** CLI में एक या अधिक डेटा स्रोतों के लिए किसी निर्दिष्ट प्रोजेक्ट के भीतर प्रोफ़ाइल, प्रेडिक्शन्स, और ट्रैफ़िक लाइट सिस्टम डेटा को हटाने के लिए किया जाता है। यह कमांड डेटा लाइफसाइकल प्रबंधन के लिए आवश्यक है, पुराने या अनावश्यक डेटा को साफ़ करके एक व्यवस्थित और कुशल डेटा वातावरण बनाए रखने में मदद करता है।

#### कमांड उपयोग

```bash
dignacli clean-up <PROJECT_NAME> <FROM_DATE> <TO_DATE> [options]
```
  
#### Arguments
  
- **PROJECT_NAME**: वह प्रोजेक्ट जिसका डेटा हटाना है (आवश्यक)। इस आर्ग्युमेंट में keyword `all-projects` का उपयोग करने पर ***digna*** सभी मौजूदा प्रोजेक्ट्स पर क्रमशः यह कमांड लागू करेगा।
- **FROM_DATE**: डेटा हटाने की आरंभिक तिथि और समय। स्वीकृत फ़ॉर्मैट में %Y-%m-%d, %Y-%m-%dT%H:%M:%S, या %Y-%m-%d %H:%M:%S शामिल हैं (आवश्यक)।
- **TO_DATE**: डेटा हटाने की अंतिम तिथि और समय, FROM_DATE के समान फ़ॉर्मैट का पालन करता है (आवश्यक)।
  
#### विकल्प
  
- `--table-name`, `-tn`: क्लीन-अप ऑपरेशन को प्रोजेक्ट के किसी विशिष्ट टेबल तक सीमित करता है।
- `--table-filter`, `-tf`: ऐसे फ़िल्टर जो उन टेबलों तक क्लीन-अप को सीमित करते हैं जिनके नाम में निर्दिष्ट उपस्ट्रिंग होती है।
- `--timing`, `-tm`: क्लीन-अप प्रक्रिया पूरी होने के बाद समय अवधि दिखाता है।
- `--help`: clean-up कमांड की मदद जानकारी दिखाता है और बाहर निकलता है।
  
#### उदाहरण
  
प्रोजेक्ट ProjectA से 1 जनवरी 2023 और 30 जून 2023 के बीच का डेटा हटाने के लिए:
  
```bash
dignacli clean-up ProjectA 2023-01-01 2023-06-30
```
  
केवल `Table1` नामक एक विशिष्ट टेबल का डेटा हटाने के लिए:
  
```bash
dignacli clean-up ProjectA 2023-01-01 2023-06-30 --table-name Table1
```
  
यह कमांड डेटा स्टोरेज प्रबंधन में मदद करती है और सुनिश्चित करती है कि रिपोजिटरी में केवल संबंधित जानकारी ही बनी रहे।

### remove-orphans
  
`remove-orphans` कमांड ***digna*** रिपोजिटरी में हाउस-कीपिंग के लिए उपयोग किया जाता है।  
जब कोई उपयोगकर्ता प्रोजेक्ट्स या डेटा स्रोत हटाता है, तो प्रोफ़ाइल और प्रेडिक्शन्स अक्सर रिपोजिटरी में रह जाते हैं। इस कमांड के साथ, ऐसे orphaned rows को रिपोजिटरी से हटाया जाएगा।
  
#### कमांड उपयोग
  
```bash
dignacli list-projects
```

### list-projects

यह कमांड विशेष रूप से उन प्रशासकों और उपयोगकर्ताओं के लिए उपयोगी है जो कई प्रोजेक्ट्स का प्रबंधन करते हैं, क्योंकि यह ***digna*** रिपोजिटरी में उपलब्ध प्रोजेक्ट्स का त्वरित अवलोकन प्रदान करता है।

`list-ds` कमांड का उपयोग किसी निर्दिष्ट प्रोजेक्ट के भीतर उपलब्ध सभी डेटा स्रोतों की सूची प्रदर्शित करने के लिए किया जाता है। यह कमांड विश्लेषण और प्रबंधन के लिए उपलब्ध डेटा एसेट्स को समझने में उपयोगी है।

```bash
dignacli list-ds <PROJECT_NAME>
```

#### Arguments
- **PROJECT_NAME**: वह प्रोजेक्ट जिसका डेटा स्रोत सूचीबद्ध किए जा रहे हैं (आवश्यक)।
  
#### उदाहरण
  
प्रोजेक्ट `ProjectA` में सभी डेटा स्रोतों को सूचीबद्ध करने के लिए:

```bash
dignacli list-ds ProjectA
```
  
यह कमांड उपयोगकर्ताओं को किसी प्रोजेक्ट में उपलब्ध डेटा स्रोतों का अवलोकन प्रदान करती है, जिससे वे डेटा परिदृश्य को अधिक प्रभावी ढंग से नेविगेट और प्रबंधित कर सकें।

### inspect

`inspect` कमांड का उपयोग किसी निर्दिष्ट प्रोजेक्ट में एक या अधिक डेटा स्रोतों के लिए प्रोफ़ाइल, प्रेडिक्शन्स, और ट्रैफ़िक लाइट सिस्टम डेटा बनाने के लिए किया जाता है। यह कमांड एक परिभाषित अवधि के दौरान डेटा का विश्लेषण और निगरानी करने में मदद करती है। निरीक्षण पूरा होने पर, गणना किए गए ट्रैफ़िक लाइट सिस्टम का मान लौटाया जाता है:  
- 0: OK  
- 1: INFO  
- 2: WARNING

#### कमांड उपयोग

```bash
dignacli inspect <PROJECT_NAME> <FROM_DATE> <TO_DATE> [options]
```
  
#### Arguments
  
- **PROJECT_NAME**: वह प्रोजेक्ट जिसका डेटा निरीक्षण किया जाना है (आवश्यक)। इस आर्ग्युमेंट में keyword `all-projects` का उपयोग करने पर ***digna*** सभी मौजूदा प्रोजेक्ट्स पर यह कमांड लागू करेगा।
- **FROM_DATE**: डेटा निरीक्षण की प्रारंभ तिथि और समय। स्वीकृत फ़ॉर्मैट %Y-%m-%d, %Y-%m-%dT%H:%M:%S, या %Y-%m-%d %H:%M:%S हैं (आवश्यक)।
- **TO_DATE**: डेटा निरीक्षण की अंतिम तिथि और समय, FROM_DATE के समान फ़ॉर्मैट का पालन करता है (आवश्यक)।
  
#### विकल्प

- `--table-name`, `-tn`: निरीक्षण को प्रोजेक्ट के किसी विशिष्ट टेबल तक सीमित करता है।
- `--table-filter`, `-tf`: केवल उन टेबलों का निरीक्षण करने के लिए फ़िल्टर करता है जिनके नामों में निर्दिष्ट उपस्ट्रिंग हो।
- `--enable_notification`, `-en`: अलर्ट होने पर नोटिफिकेशन भेजना सक्षम करता है।
- `--bypass-backend`, `-bb`: बैकएंड को बाइपास करके सीधे CLI से निरीक्षण चलाता है (केवल परीक्षण उद्देश्यों के लिए!)。
  
#### उदाहरण
  
प्रोजेक्ट `ProjectA` के लिए 1 जनवरी 2024 से 31 जनवरी 2024 तक डेटा का निरीक्षण करने के लिए:
  
```bash
dignacli inspect ProjectA 2024-01-01 2024-01-31
```
  
केवल किसी विशेष टेबल का निरीक्षण करने और प्रेडिक्शन्स के पुनर्गणना को ज़बरदस्ती करने के लिए:
  
```bash
dignacli inspect ProjectA 2024-01-01 2024-01-31 --table-name Table1 --force-prediction
```
यह कमांड अद्यतन प्रोफ़ाइल और प्रेडिक्शन्स जनरेट करने, डेटा अखंडता की निगरानी करने, और किसी निर्दिष्ट प्रोजेक्ट समयावधि के भीतर अलर्ट सिस्टम का प्रबंधन करने में उपयोगी है।

### export-ds

`export-ds` कमांड का उपयोग ***digna*** रिपोजिटरी से डेटा स्रोतों का एक्सपोर्ट बनाने के लिए किया जाता है। डिफ़ॉल्ट रूप से, किसी दिए गए प्रोजेक्ट के सभी डेटा स्रोत एक्सपोर्ट किए जाते हैं।

#### कमांड उपयोग
  
```bash
dignacli export-ds <PROJECT_NAME> [options]
```

#### Arguments
- **PROJECT_NAME**: वह प्रोजेक्ट जिसका डेटा स्रोत एक्सपोर्ट किया जाएगा।

#### विकल्प

- `--table_name`, `-tn`: किसी प्रोजेक्ट से किसी विशेष डेटा स्रोत का एक्सपोर्ट करने के लिए।
- `--exportfile`, `-ef`: एक्सपोर्ट के लिए फ़ाइलनाम निर्दिष्ट करने के लिए।
    
#### उदाहरण
  
प्रोजेक्ट `ProjectA` के सभी डेटा स्रोतों को एक्सपोर्ट करने के लिए:
  
```bash
dignacli export-ds ProjectA
```
  
यह कमांड `ProjectA` के सभी डेटा स्रोतों को एक JSON दस्तावेज़ के रूप में एक्सपोर्ट करती है जिसे किसी अन्य प्रोजेक्ट या ***digna*** रिपोजिटरी में इम्पोर्ट किया जा सकता है।


### import-ds

`import-ds` कमांड का उपयोग डेटा स्रोतों को लक्षित प्रोजेक्ट में इम्पोर्ट करने और एक इम्पोर्ट रिपोर्ट बनाने के लिए किया जाता है।

#### कमांड उपयोग
  
```bash
dignacli import-ds <PROJECT_NAME> <EXPORT_FILE> [options]
```

#### Arguments
- **PROJECT_NAME**: वह प्रोजेक्ट जिसमें डेटा स्रोत इम्पोर्ट किए जाएंगे।
- **EXPORT_FILE**: इम्पोर्ट करने के लिए डेटा स्रोतों के एक्सपोर्ट की फ़ाइल का नाम।

#### विकल्प

- `--output-file`, `-o`: इम्पोर्ट रिपोर्ट को सेव करने के लिए फ़ाइल (यदि निर्दिष्ट नहीं किया गया तो रिपोर्ट टर्मिनल में तालिकात्मक रूप में प्रिंट होती है)।
- `--output-format`, `-f`: इम्पोर्ट रिपोर्ट को सहेजने का फ़ॉर्मैट (json, csv)।
    
#### उदाहरण
  
एक्सपोर्ट फ़ाइल `my_export.json` से सभी डेटा स्रोतों को `ProjectB` में इम्पोर्ट करने के लिए:
  
```bash
dignacli import-ds ProjectB my_export.json
```
  
इम्पोर्ट के बाद, यह कमांड इम्पोर्ट किए गए और स्किप किए गए ऑब्जेक्ट्स की रिपोर्ट भी दिखाएगा। केवल नए डेटा स्रोत `ProjectB` में इम्पोर्ट किए जाएंगे। यह पता करने के लिए कि कौन से ऑब्जेक्ट्स इम्पोर्ट और स्किप होंगे, आप `plan-import-ds` कमांड का उपयोग कर सकते हैं।

### plan-import-ds

`plan-import-ds` कमांड का उपयोग लक्षित प्रोजेक्ट में डेटा स्रोतों को इम्पोर्ट करने से पहले इम्पोर्ट रिपोर्ट (योजना) बनाने के लिए किया जाता है।

#### कमांड उपयोग
  
```bash
dignacli plan-import-ds <PROJECT_NAME> <EXPORT_FILE> [options]
```

#### Arguments
- **PROJECT_NAME**: वह प्रोजेक्ट जिसमें डेटा स्रोत इम्पोर्ट किए जाने की योजना है।
- **EXPORT_FILE**: इम्पोर्ट से पहले विश्लेषण करने के लिए डेटा स्रोतों के एक्सपोर्ट की फ़ाइल का नाम।

#### विकल्प

- `--output-file`, `-o`: इम्पोर्ट रिपोर्ट को सेव करने के लिए फ़ाइल (यदि निर्दिष्ट नहीं किया गया तो रिपोर्ट टर्मिनल में तालिकात्मक रूप में प्रिंट होती है)।
- `--output-format`, `-f`: इम्पोर्ट रिपोर्ट को सहेजने का फ़ॉर्मैट (json, csv)।
    
#### उदाहरण
  
यह जाँचने के लिए कि एक्सपोर्ट फ़ाइल `my_export.json` से `ProjectB` में कौन से डेटा स्रोत इम्पोर्ट किए जाएंगे और कौन से स्किप होंगे:
  
```bash
dignacli plan-import-ds ProjectB my_export.json
```
  
यह कमांड केवल उन ऑब्जेक्ट्स का इम्पोर्ट प्लान दिखाएगा जिन्हें इम्पोर्ट या स्किप किया जाएगा।
