# digna CLI संदर्भ 2026.04
**2026-04-08**

यह पृष्ठ ***digna*** CLI रिलीज **2026.04** में उपलब्ध सभी कमांड्स का पूरा वर्णन दर्शाता है, जिसमें उपयोग के उदाहरण और विकल्प शामिल हैं।

---

## CLI बुनियादी बातें

---

### help
`--help` विकल्प उपलब्ध कमांड्स और उनके उपयोग के बारे में जानकारी प्रदान करता है। इस विकल्प का उपयोग करने के दो मुख्य तरीके हैं:

1. **सामान्य हेल्प दिखाना:**
   
    कीवर्ड ***digna*** के तुरंत बाद `--help` का उपयोग करें  
   ```bash
   dignacli --help
   ```

2. **विशिष्ट कमांड के लिए हेल्प प्राप्त करना:**  
  
    किसी विशिष्ट कमांड के विस्तृत विवरण के लिए उस कमांड के बाद `--help` जोड़ें।  
    उदाहरण के लिए, `add-user` कमांड के बारे में मदद प्राप्त करने के लिए चलाएँ:
     ```bash
     dignacli add-user --help
     ```

     ### output:
      
     - **कमांड विवरण:** बताता है कि कमांड क्या करता है।  
     - **Syntax:** सटीक सिंटैक्स दिखाता है, जिसमें आवश्यक और वैकल्पिक आर्गुमेंट शामिल हैं।  
     - **विकल्प (Options):** उस कमांड के विशिष्ट विकल्पों की सूची और उनका वर्णन।  
     - **उदाहरण (Examples):** कमांड को प्रभावी ढंग से कैसे चलाया जाए, इसके उदाहरण।

### check-config

check-config कमांड ***digna*** CLI टूल का एक यूटिलिटी है जो ***digna*** की कॉन्फ़िगरेशन का परीक्षण करने के लिए डिजाइन किया गया है। यह कमांड सुनिश्चित करता है कि ***digna*** घटक config.toml में आवश्यक कॉन्फ़िगरेशन तत्वों को पा सकें।

#### Options

- `--configpath`, `-cp`: वह फ़ाइल या डायरेक्टरी जो कॉन्फ़िगरेशन रखती है। यदि छोड़ा जाए तो ../config.toml उपयोग किया जाएगा।
      
#### Command Usage
```bash
dignacli check-config
```

सफल निष्पादन पर, यह कमांड कॉन्फ़िगरेशन की पूर्णता की पुष्टि आउटपुट करता है।  
  
यदि कॉन्फ़िगरेशन अधूरी प्रतीत होती है, तो गायब कॉन्फ़िगरेशन तत्वों की सूची दी जाएगी।

  
### check-repo-connection

check-repo-connection कमांड ***digna*** CLI टूल में एक यूटिलिटी है जो किसी निर्दिष्ट ***digna*** रिपॉज़िटरी से कनेक्टिविटी और एक्सेस की जांच करने के लिए डिजाइन की गई है। यह कमांड सुनिश्चित करता है कि CLI रिपॉज़िटरी के साथ इंटरैक्ट कर सके।
      
#### Command Usage
```bash
dignacli check-repo-connection
```

सफल निष्पादन पर, कमांड कनेक्शन की पुष्टि के साथ रिपॉज़िटरी के बारे में विवरण आउटपुट करता है: Repository version, Host, Database और Schema।  
  
यदि रिपॉज़िटरी कनेक्शन सफल नहीं है, तो सही कॉन्फ़िगरेशन सेटिंग्स के लिए config.toml फ़ाइल की जाँच करें।

#### Command Usage
```bash

```
  
#### Example Output
```bash
dignacli version 2026.04
```

### logging options
  
डिफ़ॉल्ट रूप से, ***digna*** कमांड्स का कंसोल आउटपुट मिनिमलिस्टिक डिजाइन किया गया है। अधिकांश कमांड्स अतिरिक्त जानकारी देने का विकल्प प्रदान करते हैं, जिनके लिए निम्नलिखित विकल्प उपयोग किए जा सकते हैं:  
  
-- verbose (-v)  
-- debug (-d)  
-- logfile (lf)  
 
“verbose” और “debug” डिटेल का स्तर निर्धारित करते हैं, जबकि “logfile” स्विच आउटपुट को कंसोल विंडो के बजाय किसी फ़ाइल में रीडायरेक्ट करने की अनुमति देता है।

## उपयोगकर्ता प्रबंधन (User Management)

### add-user
  
add-user कमांड ***digna*** CLI में नए उपयोगकर्ता को ***digna*** सिस्टम में जोड़ने के लिए प्रयोग होता है।
  
#### Command Usage
```bash
dignacli add-user [OPTIONS] USER_NAME USER_FULL_NAME USER_PASSWORD
```
  
#### Arguments

- **USER_NAME**: नए उपयोगकर्ता के लिए यूज़रनेम (आवश्यक)।
- **USER_FULL_NAME**: नए उपयोगकर्ता का पूरा नाम (आवश्यक)।
- **USER_PASSWORD**: नए उपयोगकर्ता का पासवर्ड (आवश्यक)।

#### Options

- `--is_superuser`, `-su`: नए उपयोगकर्ता को एडमिन के रूप में चिन्हित करने का फ़्लैग।
- `--valid_until`, `-vu`: उपयोगकर्ता खाते के लिए समाप्ति तिथि सेट करता है, फ़ॉर्मेट `YYYY-MM-DD HH:MI:SS`। यदि सेट नहीं किया गया, तो खाते की कोई समाप्ति तिथि नहीं होगी।

#### Example

उदाहरण के लिए, यूज़रनेम `jdoe`, पूरा नाम `John Doe`, और पासवर्ड `password123` के साथ नया उपयोगकर्ता जोड़ने के लिए:

```bash
dignacli add-user [OPTIONS] USER_NAME USER_FULL_NAME USER_PASSWORD
```
  
खाते की समाप्ति तिथि सेट करते हुए नया उपयोगकर्ता जोड़ने के लिए:
```bash
dignacli add-user jdoe "John Doe" password123 --valid_until "2024-12-31 23:59:59"
```

### delete-user
  
`delete-user` कमांड ***digna*** CLI में मौजूदा उपयोगकर्ता को ***digna*** सिस्टम से हटाने के लिए उपयोग होता है।
  
#### Command Usage
```bash
dignacli delete-user USER_NAME
```
  
#### Arguments
- **USER_NAME**: हटाए जाने वाले उपयोगकर्ता का यूज़रनेम (आवश्यक)। यह कमांड द्वारा आवश्यक एकमात्र आर्गुमेंट है।

#### Example
```bash
dignacli delete-user jdoe
```
  
इस कमांड के निष्पादन से उपयोगकर्ता `jdoe` को ***digna*** सिस्टम से हटा दिया जाएगा, उनकी एक्सेस रद्द हो जाएगी और रिपॉज़िटरी से संबंधित डेटा और अनुमतियाँ हटाई जाएँगी।

### modify-user

`modify-user` कमांड ***digna*** CLI में मौजूदा उपयोगकर्ता के विवरण अपडेट करने के लिए उपयोग होता है।

#### Command Usage
  
```bash
dignacli modify-user <USER_NAME> <USER_FULL_NAME> [options]
```
  
#### Arguments
  
- **USER_NAME**: संशोधित किए जाने वाले उपयोगकर्ता का यूज़रनेम (आवश्यक)।
- **USER_FULL_NAME**: उपयोगकर्ता का नया पूरा नाम (आवश्यक)।
  
#### Options  
  
- `--is_superuser`, `-su`: उपयोगकर्ता को सुपरयूज़र के रूप में सेट करता है, जिससे उन्नत अधिकार मिलते हैं। इस फ़्लैग को किसी मान की आवश्यकता नहीं होती।  
- `--valid_until`, `-vu`: उपयोगकर्ता खाते के लिए समाप्ति तिथि सेट करता है, फ़ॉर्मेट YYYY-MM-DD HH:MI:SS। यदि प्रदान नहीं किया गया तो खाता अनिश्चितकाल तक मान्य रहेगा।  
  
#### Example
  
उदाहरण के लिए, उपयोगकर्ता `jdoe` का पूरा नाम “Johnathan Doe” में बदलने और उसे सुपरयूज़र सेट करने के लिए:
```bash
dignacli modify-user jdoe "Johnathan Doe" --is_superuser
```

## रिपॉज़िटरी प्रबंधन (Repository Management)

### upgrade-repo
  
`upgrade-repo` कमांड ***digna*** CLI में ***digna*** रिपॉज़िटरी को अपग्रेड या इनिशियलाइज़ करने के लिए उपयोग होता है। यह कमांड अपडेट्स लागू करने या पहली बार रिपॉज़िटरी इन्‍स्टॉल करने के लिए आवश्यक है।
  
#### Command Usage

```bash
dignacli upgrade-repo [options]
```
  
#### Options
  
- `--simulation-mode`, `-s`: सक्षम होने पर यह विकल्प कमांड को सिमुलेशन मोड में चलाता है, जो उन SQL स्टेटमेंट्स को प्रिंट करता है जो निष्पादित किए जाएंगे पर वास्तव में उन्हें निष्पादित नहीं करता। यह बिना रिपॉज़िटरी में परिवर्तन किए बदलावों का पूर्वावलोकन करने के लिए उपयोगी है।  

  
#### Example
  
***digna*** रिपॉज़िटरी को अपग्रेड करने के लिए बिना किसी विकल्प के कमांड चलाएँ:
  
```bash
dignacli upgrade-repo
```  
SQL स्टेटमेंट्स देखे बिना उन्हें लागू किए बिना अपग्रेड सिमुलेट करने के लिए:
  
```bash
dignacli upgrade-repo --simulation-mode
```
  
यह कमांड ***digna*** सिस्टम के रखरखाव के लिए महत्वपूर्ण है, यह सुनिश्चित करता है कि डेटाबेस स्कीमा और अन्य रिपॉज़िटरी घटक सॉफ़्टवेयर के नवीनतम संस्करण के अनुरूप हों।

### encrypt
  
`encrypt` कमांड ***digna*** CLI में पासवर्ड को एन्क्रिप्ट करने के लिए उपयोग होता है।
  
#### Command Usage
  
```bash
dignacli encrypt <PASSWORD>
```
    
#### Arguments
- **PASSWORD**: वह पासवर्ड जिसे एन्क्रिप्ट करना है (आवश्यक)।
  
#### Example
  
पासवर्ड एन्क्रिप्ट करने के लिए पासवर्ड को आर्गुमेंट के रूप में प्रदान करें।  
उदाहरण के लिए, पासवर्ड `mypassword123` को एन्क्रिप्ट करने के लिए:
```bash
dignacli encrypt mypassword123
```
यह कमांड प्रदान किए गए पासवर्ड का एन्क्रिप्टेड रूप आउटपुट करेगा, जिसे सुरक्षित संदर्भों में उपयोग किया जा सकता है। यदि पासवर्ड आर्गुमेंट नहीं दिया गया है, तो CLI एक त्रुटि प्रदर्शित करेगा जो गायब आर्गुमेंट का संकेत देगी।

#### Command Usage

## डेटा प्रबंधन (Data Management)

### clean-up

`clean-up` कमांड ***digna*** CLI में एक या अधिक डेटा स्रोतों के प्रोफाइल, भविष्यवाणियाँ (predictions), और ट्रैफिक लाइट सिस्टम डेटा को निर्दिष्ट प्रोजेक्ट के भीतर हटाने के लिए उपयोग होता है। यह कमांड डेटा लाइफ़साइकल प्रबंधन के लिए आवश्यक है, जिससे अप्रासंगिक या पुराने डेटा को हटाकर डेटा पर्यावरण सुव्यवस्थित और कुशल रहता है।

#### Command Usage

```bash
dignacli clean-up <PROJECT_NAME> <FROM_DATE> <TO_DATE> [options]
```
  
#### Arguments
  
- **PROJECT_NAME**: वह प्रोजेक्ट जिससे डेटा हटाना है (आवश्यक)। इस आर्गुमेंट में keyword `all-projects` का उपयोग करने पर ***digna*** सभी मौजूदा प्रोजेक्ट्स पर इस कमांड को लागू करेगा।
- **FROM_DATE**: डेटा हटाने की प्रारम्भिक तिथि और समय। स्वीकार्य फ़ॉर्मैट में %Y-%m-%d, %Y-%m-%dT%H:%M:%S, या %Y-%m-%d %H:%M:%S शामिल हैं (आवश्यक)।
- **TO_DATE**: डेटा हटाने की समाप्ति तिथि और समय, FROM_DATE जैसे फ़ॉर्मैट का पालन करते हुए (आवश्यक)।
  
#### Options
  
- `--table-name`, `-tn`: क्लीन-अप ऑपरेशन को प्रोजेक्ट के किसी विशिष्ट टेबल तक सीमित करता है।
- `--table-filter`, `-tf`: उन टेबल्स को फ़िल्टर करता है जिनके नाम में दिए गए सबस्ट्रिंग मौजूद हो।
- `--timing`, `-tm`: पूर्ण होने के बाद क्लीन-अप प्रक्रिया का समयावधि दिखाता है।
- `--help`: clean-up कमांड की मदद जानकारी दिखाता है और बाहर निकलता है।
  
#### Example
  
ProjectA प्रोजेक्ट से 1 जनवरी 2023 से 30 जून 2023 के बीच का डेटा हटाने के लिए:
  
```bash
dignacli clean-up ProjectA 2023-01-01 2023-06-30
```
  
केवल `Table1` नामक एक विशेष टेबल का डेटा हटाने के लिए:
  
```bash
dignacli clean-up ProjectA 2023-01-01 2023-06-30 --table-name Table1
```
  
यह कमांड डेटा संग्रहण प्रबंधन में मदद करता है और सुनिश्चित करता है कि रिपॉज़िटरी केवल प्रासंगिक जानकारी ही रखे।

### remove-orphans
  
`remove-orphans` कमांड ***digna*** CLI में रिपॉज़िटरी की हाउसकीपिंग के लिए उपयोग होता है।

#### Command Usage
  
```bash

```

### list-ds

#### Example
  
ProjectA नामक प्रोजेक्ट में सभी डेटा सोर्सेज़ की सूची देखने के लिए:
  
```bash
dignacli list-ds ProjectA
```

यह कमांड यूज़र्स को प्रोजेक्ट में उपलब्ध डेटा सोर्सेज़ का एक अवलोकन देता है, जिससे वे डेटा परिदृश्य को अधिक प्रभावी ढंग से नेविगेट और प्रबंधित कर सकें।


### inspect

`inspect` कमांड ***digna*** CLI में एक या अधिक डेटा स्रोतों के लिए प्रोफाइल, भविष्यवाणियाँ और ट्रैफिक लाइट सिस्टम डेटा बनाने के लिए उपयोग होता है। यह कमांड निर्दिष्ट अवधि में डेटा का विश्लेषण और मॉनिटरिंग करने में मदद करता है। निरीक्षण पूरा होने के बाद, गणना किए गए ट्रैफिक लाइट सिस्टम का मान वापस किया जाता है:  
- 0: OK  
- 1: INFO  
- 2: WARNING

#### Command Usage

```bash
dignacli inspect <PROJECT_NAME> <FROM_DATE> <TO_DATE> [options]
```
  
#### Arguments
  
- **PROJECT_NAME**: वह प्रोजेक्ट जिसके लिए डेटा का निरीक्षण किया जाना है (आवश्यक)। इस आर्गुमेंट में `all-projects` कीवर्ड का उपयोग करने से ***digna*** सभी मौजूदा प्रोजेक्ट्स पर यह कमांड लागू करेगा।
- **FROM_DATE**: डेटा निरीक्षण की प्रारम्भिक तिथि और समय। स्वीकार्य फ़ॉर्मैट में %Y-%m-%d, %Y-%m-%dT%H:%M:%S, या %Y-%m-%d %H:%M:%S शामिल हैं (आवश्यक)।
- **TO_DATE**: डेटा निरीक्षण की समाप्ति तिथि और समय, FROM_DATE जैसे फ़ॉर्मैट का पालन करते हुए (आवश्यक)।
  
#### Options

- `--table-name`, `-tn`: निरीक्षण को प्रोजेक्ट के किसी विशिष्ट टेबल तक सीमित करता है।
- `--table-filter`, `-tf`: केवल उन टेबल्स का निरीक्षण करता है जिनके नाम में निर्दिष्ट सबस्ट्रिंग मौजूद हो।
- `--enable_notification`, `-en`: अलर्ट की स्थिति में नोटिफिकेशन भेजने को सक्षम करता है।
- `--bypass-backend`, `-bb`: बैकएंड को बाईपास करके CLI से सीधे निरीक्षण चलाता है (केवल परीक्षण उद्देश्यों के लिए!)।

  
#### Example
  
Project `ProjectA` के लिए 1 जनवरी 2024 से 31 जनवरी 2024 तक का डेटा निरीक्षण करने के लिए:
  
```bash
dignacli inspect ProjectA 2024-01-01 2024-01-31
```
  
केवल किसी विशिष्ट टेबल का निरीक्षण करने और भविष्यवाणियों की पुनर्गणना बाध्य करने के लिए:
  
```bash
dignacli inspect ProjectA 2024-01-01 2024-01-31 --table-name Table1 --force-prediction
```
यह कमांड अद्यतन प्रोफाइल और भविष्यवाणियाँ जनरेट करने, डेटा अखंडता की मॉनिटरिंग करने, और निर्दिष्ट प्रोजेक्ट समयसीमा के भीतर अलर्ट सिस्टम का प्रबंधन करने के लिए उपयोगी है।

### export-ds

`export-ds` कमांड ***digna*** CLI में ***digna*** रिपॉज़िटरी से डेटा सोर्सेज़ का एक्सपोर्ट बनाने के लिए उपयोग होता है। डिफ़ॉल्ट रूप से, किसी दिए गए प्रोजेक्ट के सभी डेटा सोर्सेज़ एक्सपोर्ट किए जाएँगे।

#### Command Usage
  
```bash
dignacli export-ds <PROJECT_NAME> [options]
```

#### Arguments
- **PROJECT_NAME**: वह प्रोजेक्ट जिसका डेटा सोर्सेज़ एक्सपोर्ट किया जाएगा।

#### Options

- `--table_name`, `-tn`: किसी प्रोजेक्ट से किसी विशेष डेटा सोर्स का एक्सपोर्ट।
- `--exportfile`, `-ef`: एक्सपोर्ट के लिए फ़ाइलनाम निर्दिष्ट करना।
    
#### Example
  
ProjectA नामक प्रोजेक्ट से सभी डेटा सोर्सेज़ एक्सपोर्ट करने के लिए:
  
```bash
dignacli export-ds ProjectA
```
  
यह कमांड `ProjectA` से सभी डेटा सोर्सेज़ को एक JSON दस्तावेज़ के रूप में एक्सपोर्ट करता है जिसे किसी अन्य प्रोजेक्ट या ***digna*** रिपॉज़िटरी में इम्पोर्ट किया जा सकता है।


### import-ds

`import-ds` कमांड ***digna*** CLI में डेटा सोर्सेज़ को लक्ष्य प्रोजेक्ट में इम्पोर्ट करने और एक इम्पोर्ट रिपोर्ट बनाने के लिए उपयोग होता है।

#### Command Usage
  
```bash
dignacli import-ds <PROJECT_NAME> <EXPORT_FILE> [options]
```

#### Arguments
- **PROJECT_NAME**: वह प्रोजेक्ट जिसमें डेटा सोर्सेज़ इम्पोर्ट किए जाएँगे।
- **EXPORT_FILE**: इम्पोर्ट करने के लिए डेटा सोर्सेज़ के एक्सपोर्ट की फ़ाइल का नाम।

#### Options

- `--output-file`, `-o`: इम्पोर्ट रिपोर्ट सहेजने के लिए फ़ाइल (यदि निर्दिष्ट नहीं है तो टर्मिनल में तालिकात्मक रूप में प्रिंट होता है)।
- `--output-format`, `-f`: इम्पोर्ट रिपोर्ट सेव करने के लिए फ़ॉर्मैट (json, csv)।
    
#### Example
  
एक्सपोर्ट फ़ाइल `my_export.json` से सभी डेटा सोर्सेज़ को `ProjectB` में इम्पोर्ट करने के लिए:
  
```bash
dignacli import-ds ProjectB my_export.json
```
  
इम्पोर्ट के बाद, यह कमांड इम्पोर्ट किए गए और स्किप किए गए ऑब्जेक्ट्स की रिपोर्ट भी दिखाएगा। केवल नए डेटा सोर्सेज़ ही `ProjectB` में इम्पोर्ट किए जाएँगे। यह पता लगाने के लिए कि किन ऑब्जेक्ट्स को इम्पोर्ट और स्किप किया जाएगा, आप `plan-import-ds` कमांड का उपयोग कर सकते हैं।

### plan-import-ds

`plan-import-ds` कमांड ***digna*** CLI में डेटा सोर्सेज़ को लक्ष्य प्रोजेक्ट में इम्पोर्ट करने से पहले इम्पोर्ट रिपोर्ट तैयार करने और इम्पोर्ट योजना दिखाने के लिए उपयोग होता है।

#### Command Usage
  
```bash
dignacli plan-import-ds <PROJECT_NAME> <EXPORT_FILE> [options]
```

#### Arguments
- **PROJECT_NAME**: वह प्रोजेक्ट जिसमें डेटा सोर्सेज़ इम्पोर्ट किए जाने की योजना बनाई जा रही है।
- **EXPORT_FILE**: इम्पोर्ट से पहले विश्लेषण करने के लिए डेटा सोर्सेज़ के एक्सपोर्ट की फ़ाइल का नाम।

#### Options

- `--output-file`, `-o`: इम्पोर्ट रिपोर्ट सहेजने के लिए फ़ाइल (यदि निर्दिष्ट नहीं है तो टर्मिनल में तालिकात्मक रूप में प्रिंट होता है)।
- `--output-format`, `-f`: इम्पोर्ट रिपोर्ट सेव करने के लिए फ़ॉर्मैट (json, csv)।
    
#### Example
  
एक्सपोर्ट फ़ाइल `my_export.json` से यह जाँचने के लिए कि `ProjectB` में इम्पोर्ट करने पर कौन से डेटा सोर्सेस इम्पोर्ट होंगे और कौन से स्किप किए जाएँगे:
  
```bash
dignacli plan-import-ds ProjectB my_export.json
```
  
यह कमांड केवल इम्पोर्ट की योजना दिखाएगा कि किन ऑब्जेक्ट्स को इम्पोर्ट और किन्हें स्किप किया जाएगा।
