# digna CLI Reference 2025.04
**2025-04-01**

Αυτή η σελίδα τεκμηριώνει το πλήρες σύνολο εντολών που είναι διαθέσιμες στο CLI του ***digna*** έκδοσης **2025.04**, συμπεριλαμβανομένων παραδειγμάτων χρήσης και επιλογών.

## Χρήση της επιλογής `--help`

Η επιλογή `--help` παρέχει πληροφορίες για τις διαθέσιμες εντολές και τη χρήση τους. Υπάρχουν δύο βασικοί τρόποι χρήσης αυτής της επιλογής:

1. **Εμφάνιση γενικής βοήθειας:**
   
    Χρησιμοποιήστε `--help` αμέσως μετά την εντολή `dignacli`  
   ```bash
   dignacli --help
   ```

2. **Λήψη βοήθειας για συγκεκριμένες εντολές:**  
  
    Για λεπτομερείς πληροφορίες σχετικά με μια συγκεκριμένη εντολή, προσθέστε `--help` σε αυτήν την εντολή.
    Για παράδειγμα, για βοήθεια με την εντολή `add-user`, εκτελέστε:
     ```bash
     dignacli add-user --help
     ```

     ### Έξοδος:
      
     - **Περιγραφή Εντολής:** Παρέχει λεπτομερή περιγραφή του τι κάνει η εντολή.  
     - **Σύνταξη:** Εμφανίζει την ακριβή σύνταξη, συμπεριλαμβανομένων των απαιτούμενων και προαιρετικών ορισμάτων.  
     - **Επιλογές:** Λίστα με τις επιλογές που αφορούν την εντολή, μαζί με τις εξηγήσεις τους.  
     - **Παραδείγματα:** Παρέχει παραδείγματα για το πώς να εκτελεστεί αποτελεσματικά η εντολή.  

  
## Χρήση της εντολής `check-repo-connection`

Η εντολή `check-repo-connection` είναι ένα βοηθητικό εργαλείο στο CLI του ***digna*** σχεδιασμένο να ελέγχει τη συνδεσιμότητα και την πρόσβαση σε ένα συγκεκριμένο αποθετήριο ***digna***. Αυτή η εντολή διασφαλίζει ότι το CLI μπορεί να αλληλεπιδράσει με το αποθετήριο.
      
#### Χρήση εντολής
```bash
dignacli check-repo-connection
```

Μετά από επιτυχή εκτέλεση, η εντολή εμφανίζει μια επιβεβαίωση της σύνδεσης, μαζί με λεπτομέρειες για το αποθετήριο: έκδοση αποθετηρίου, Host, Database και Schema.  
  
Εάν η σύνδεση με το αποθετήριο δεν είναι επιτυχής, ελέγξτε το αρχείο config.toml για τις σωστές ρυθμίσεις διαμόρφωσης.

## Χρήση της εντολής `--version`

Για να ελέγξετε την εγκατεστημένη έκδοση του *dignacli*, χρησιμοποιήστε την επιλογή `--version`.  
  
#### Χρήση εντολής
```bash
dignacli --version
```
  
#### Παράδειγμα εξόδου
```bash
dignacli version 2025.04
```

## Χρήση επιλογών καταγραφής (logging)
  
Κατά προεπιλογή, η έξοδος στην κονσόλα των εντολών του ***digna*** είναι σχεδιασμένη να είναι μινιμαλιστική. Οι περισσότερες εντολές προσφέρουν τη δυνατότητα παροχής επιπλέον πληροφοριών, χρησιμοποιώντας τις ακόλουθες επιλογές:  
  
--verbose (-v)  
--debug (-d)  
--logfile (lf)  
 
Οι επιλογές “verbose” και “debug” ορίζουν το επίπεδο λεπτομέρειας, ενώ η επιλογή “logfile” επιτρέπει τη δρομολόγηση της εξόδου ώστε να καταγράφεται σε αρχείο αντί για το παράθυρο της κονσόλας.

## Διαχείριση Χρηστών

### Χρήση της εντολής `add-user`
  
Η εντολή `add-user` στο CLI του ***digna*** χρησιμοποιείται για την προσθήκη ενός νέου χρήστη στο σύστημα του ***digna***.
  
#### Χρήση εντολής
```bash
dignacli add-user [OPTIONS] USER_NAME USER_FULL_NAME USER_PASSWORD
```
  
##### Ορίσματα

- **USER_NAME**: Το όνομα χρήστη για τον νέο χρήστη (απαιτείται).
- **USER_FULL_NAME**: Το πλήρες όνομα του νέου χρήστη (απαιτείται).
- **USER_PASSWORD**: Ο κωδικός πρόσβασης για τον νέο χρήστη (απαιτείται).

#### Επιλογές

- `--is_superuser`, `-su`: Σημαία για ορισμό του νέου χρήστη ως διαχειριστή.
- `--valid_until`, `-vu`: Ορίζει ημερομηνία λήξης για τον λογαριασμό χρήστη στο format `YYYY-MM-DD HH:MI:SS`. Εάν δεν οριστεί, ο λογαριασμός δεν έχει ημερομηνία λήξης.

#### Παράδειγμα

Για να προσθέσετε έναν νέο χρήστη με username `jdoe`, πλήρες όνομα `John Doe` και κωδικό `password123`:

```bash
dignacli add-user [OPTIONS] USER_NAME USER_FULL_NAME USER_PASSWORD
```
  
Για να προσθέσετε έναν νέο χρήστη και να ορίσετε ημερομηνία λήξης λογαριασμού:
```bash
dignacli add-user jdoe "John Doe" password123 --valid_until "2024-12-31 23:59:59"
```

### Χρήση της εντολής `delete-user`
  
Η εντολή `delete-user` στο CLI του ***digna*** χρησιμοποιείται για την αφαίρεση ενός υπάρχοντος χρήστη από το σύστημα του ***digna***.
  
#### Χρήση εντολής
```bash
dignacli delete-user USER_NAME
```
  
##### Ορίσματα
- **USER_NAME**: Το όνομα χρήστη του χρήστη που θα διαγραφεί (απαιτείται). Αυτό είναι το μοναδικό απαιτούμενο όρισμα για την εντολή.

#### Παράδειγμα
```bash
dignacli delete-user jdoe
```
  
Η εκτέλεση αυτής της εντολής θα αφαιρέσει τον χρήστη `jdoe` από το σύστημα του ***digna***, ανακαλώντας την πρόσβασή του και διαγράφοντας τα συνδεδεμένα δεδομένα και τα δικαιώματά του από το αποθετήριο.

### Χρήση της εντολής `modify-user`

Η εντολή `modify-user` στο CLI του ***digna*** χρησιμοποιείται για την ενημέρωση των στοιχείων ενός υπάρχοντος χρήστη στο σύστημα του ***digna***.

#### Χρήση εντολής
  
```bash
dignacli modify-user <USER_NAME> <USER_FULL_NAME> [options]
```
  
##### Ορίσματα
  
- **USER_NAME**: Το όνομα χρήστη του χρήστη που θα τροποποιηθεί (απαιτείται).
- **USER_FULL_NAME**: Το νέο πλήρες όνομα για τον χρήστη (απαιτείται).
  
#### Επιλογές  
  
- `--is_superuser`, `-su`: Ορίζει τον χρήστη ως superuser, παρέχοντας ανυψωμένα προνόμια. Αυτή η σημαία δεν απαιτεί τιμή.  
- `--valid_until`, `-vu`: Ορίζει ημερομηνία λήξης για τον λογαριασμό χρήστη στο format YYYY-MM-DD HH:MI:SS. Εάν δεν παρασχεθεί, ο λογαριασμός παραμένει έγκυρος επ’ αόριστον.  
  
#### Παράδειγμα
  
Για να τροποποιήσετε το πλήρες όνομα του χρήστη `jdoe` σε “Johnathan Doe” και να ορίσετε τον χρήστη ως superuser:
```bash
dignacli modify-user jdoe "Johnathan Doe" --is_superuser
```

### Χρήση της εντολής `modify-user-pwd`
  
Η εντολή `modify-user-pwd` στο CLI του ***digna*** χρησιμοποιείται για την αλλαγή του κωδικού πρόσβασης ενός υπάρχοντος χρήστη στο σύστημα του ***digna***.
  
#### Χρήση εντολής
```bash

```
  
##### Ορίσματα
  
- **USER_NAME**: Το όνομα χρήστη του χρήστη του οποίου θα αλλάξει ο κωδικός (απαιτείται).
- **USER_PWD**: Ο νέος κωδικός για τον χρήστη (απαιτείται).
  
#### Παράδειγμα
  
Για να αλλάξετε τον κωδικό του χρήστη `jdoe` σε `newpassword123`:
```bash
dignacli modify-user-pwd jdoe newpassword123
```

### Χρήση της εντολής `list-users`

Η εντολή `list-users` στο CLI του ***digna*** εμφανίζει λίστα με όλους τους χρήστες καταχωρημένους στο σύστημα του ***digna***.

#### Χρήση εντολής

```bash
dignacli list-users
```

Η εκτέλεση αυτής της εντολής στο CLI του ***digna*** θα συνδεθεί στο αποθετήριο του ***digna*** και θα απαριθμήσει όλους τους χρήστες, δείχνοντας το ID τους, το username, το πλήρες όνομα, την κατάσταση superuser και τις χρονικές σφραγίδες λήξης.

## Διαχείριση Αποθετηρίου

### Χρήση της εντολής `upgrade-repo`
  
Η εντολή `upgrade-repo` στο CLI του ***digna*** χρησιμοποιείται για την αναβάθμιση ή την αρχικοποίηση του αποθετηρίου του ***digna***. Αυτή η εντολή είναι απαραίτητη για την εφαρμογή ενημερώσεων ή για την εγκατάσταση της υποδομής του αποθετηρίου για πρώτη φορά.
  
#### Χρήση εντολής

```bash
dignacli upgrade-repo [options]
```
  
#### Επιλογές
  
- `--simulation-mode`, `-s`: Όταν είναι ενεργοποιημένη, αυτή η επιλογή εκτελεί την εντολή σε λειτουργία προσομοίωσης, εκτυπώνοντας τις δηλώσεις SQL που θα εκτελούνταν χωρίς να τις εφαρμόζει πραγματικά. Αυτό είναι χρήσιμο για την προεπισκόπηση αλλαγών χωρίς τροποποίηση του αποθετηρίου.  

  
#### Παράδειγμα
  
Για να αναβαθμίσετε το αποθετήριο του ***digna***, μπορείτε να εκτελέσετε την εντολή χωρίς επιλογές:
  
```bash
dignacli upgrade-repo
```  
Για να εκτελέσετε την αναβάθμιση σε λειτουργία προσομοίωσης (για να δείτε τις δηλώσεις SQL χωρίς να τις εφαρμόσετε):
  
```bash
dignacli upgrade-repo --simulation-mode
```
  
Αυτή η εντολή είναι κρίσιμη για τη συντήρηση του συστήματος του ***digna***, διασφαλίζοντας ότι το σχήμα της βάσης δεδομένων και άλλα στοιχεία του αποθετηρίου είναι ενημερωμένα με την τελευταία έκδοση του λογισμικού.

### Χρήση της εντολής `encrypt`
  
Η εντολή `encrypt` στο CLI του ***digna*** χρησιμοποιείται για την κρυπτογράφηση ενός κωδικού πρόσβασης.
  
#### Χρήση εντολής
  
```bash
dignacli encrypt <PASSWORD>
```
    
#### Ορίσματα
- **PASSWORD**: Ο κωδικός που χρειάζεται να κρυπτογραφηθεί (απαιτείται).
  
#### Παράδειγμα
  
Για να κρυπτογραφήσετε έναν κωδικό, πρέπει να παρέχετε τον κωδικό ως όρισμα.   
Για παράδειγμα, για να κρυπτογραφήσετε τον κωδικό `mypassword123`, θα χρησιμοποιούσατε:
```bash
dignacli encrypt mypassword123
```
Αυτή η εντολή επιστρέφει την κρυπτογραφημένη έκδοση του παρεχόμενου κωδικού, η οποία μπορεί στη συνέχεια να χρησιμοποιηθεί σε ασφαλείς περιβάλλοντες. Εάν το όρισμα του κωδικού δεν παρέχεται, το CLI θα εμφανίσει σφάλμα που υποδεικνύει το ελλείπον όρισμα.

## Χρήση της εντολής `clean-up`

Η εντολή `clean-up` στο CLI του ***digna*** χρησιμοποιείται για την αφαίρεση profiles, predictions και δεδομένων του συστήματος Traffic Light για μία ή περισσότερες πηγές δεδομένων εντός ενός συγκεκριμένου έργου. Αυτή η εντολή είναι απαραίτητη για τη διαχείριση του κύκλου ζωής των δεδομένων, βοηθώντας στη διατήρηση ενός οργανωμένου και αποδοτικού περιβάλλοντος με την εκκαθάριση παρωχημένων ή μη απαραίτητων δεδομένων.

#### Χρήση εντολής

```bash
dignacli clean-up <PROJECT_NAME> <FROM_DATE> <TO_DATE> [options]
```
  
#### Ορίσματα
  
- **PROJECT_NAME**: Το όνομα του έργου από το οποίο θα αφαιρεθούν δεδομένα (απαιτείται). Η χρήση της λέξης-κλειδί `all-projects` σε αυτό το όρισμα υποδεικνύει στο ***digna*** να επαναλάβει την εντολή σε όλα τα υπάρχοντα έργα.
- **FROM_DATE**: Η ημερομηνία και ώρα έναρξης για την αφαίρεση δεδομένων. Αποδεκτά formats περιλαμβάνουν %Y-%m-%d, %Y-%m-%dT%H:%M:%S, ή %Y-%m-%d %H:%M:%S (απαιτείται).
- **TO_DATE**: Η ημερομηνία και ώρα λήξης για την αφαίρεση δεδομένων, με τα ίδια formats όπως το FROM_DATE (απαιτείται).
  
#### Επιλογές
  
- `--table-name`, `-tn`: Περιορίζει την ενέργεια clean-up σε ένα συγκεκριμένο πίνακα εντός του έργου.
- `--table-filter`, `-tf`: Φίλτρο για περιορισμό του clean-up μόνο σε πίνακες που περιέχουν τη συγκεκριμένη υποσειρά στο όνομά τους.
- `--timing`, `-tm`: Εμφανίζει τη διάρκεια του clean-up μετά την ολοκλήρωση.
- `--help`: Εμφανίζει πληροφορίες βοήθειας για την εντολή clean-up και τερματίζει.
  
#### Παράδειγμα
  
Για να αφαιρέσετε δεδομένα από το έργο ProjectA μεταξύ 1 Ιανουαρίου 2023 και 30 Ιουνίου 2023:
  
```bash
dignacli clean-up ProjectA 2023-01-01 2023-06-30
```
  
Για να αφαιρέσετε δεδομένα μόνο από έναν συγκεκριμένο πίνακα με όνομα `Table1`:
  
```bash
dignacli clean-up ProjectA 2023-01-01 2023-06-30 --table-name Table1
```
  
Αυτή η εντολή βοηθά στη διαχείριση του χώρου αποθήκευσης και διασφαλίζει ότι το αποθετήριο περιέχει μόνο σχετικές πληροφορίες.

## Χρήση της εντολής `inspect`

Η εντολή `inspect` στο CLI του ***digna*** χρησιμοποιείται για τη δημιουργία profiles, predictions και δεδομένων του συστήματος Traffic Light για μία ή περισσότερες πηγές δεδομένων εντός ενός συγκεκριμένου έργου. Αυτή η εντολή βοηθά στην ανάλυση και την παρακολούθηση των δεδομένων για μια ορισμένη περίοδο.

#### Χρήση εντολής

```bash
dignacli inspect <PROJECT_NAME> <FROM_DATE> <TO_DATE> [options]
```
  
#### Ορίσματα
  
- **PROJECT_NAME**: Το όνομα του έργου για το οποίο θα πραγματοποιηθεί η επιθεώρηση των δεδομένων (απαιτείται). Η χρήση της λέξης-κλειδί `all-projects` σε αυτό το όρισμα υποδεικνύει στο ***digna*** να επαναλάβει την εντολή σε όλα τα υπάρχοντα έργα.
- **FROM_DATE**: Η αρχική ημερομηνία και ώρα για την επιθεώρηση των δεδομένων. Αποδεκτά formats περιλαμβάνουν %Y-%m-%d, %Y-%m-%dT%H:%M:%S, ή %Y-%m-%d %H:%M:%S (απαιτείται).
- **TO_DATE**: Η τελική ημερομηνία και ώρα για την επιθεώρηση των δεδομένων, με τα ίδια formats όπως το FROM_DATE (απαιτείται).
  
#### Επιλογές

- `--table-name`, `-tn`: Περιορίζει την επιθεώρηση σε έναν συγκεκριμένο πίνακα εντός του έργου.
- `--table-filter`, `-tf`: Φίλτρο για επιθεώρηση μόνο των πινάκων που περιέχουν τη συγκεκριμένη υποσειρά στο όνομά τους.
- `--do-profile`: Ενεργοποιεί την επανασυλλογή των profiles. Η προεπιλογή είναι do-profile.
- `--no-do-profile`: Αποτρέπει την επανασυλλογή των profiles.
- `--do-prediction`: Ενεργοποιεί την επανυπολογισμό των predictions. Η προεπιλογή είναι do-prediction.
- `--no-do-prediction`: Αποτρέπει τον επανυπολογισμό των predictions.
- `--do-alert-status`: Ενεργοποιεί την επανυπολογισμό της κατάστασης των alerts. Η προεπιλογή είναι do-alert-status.
- `--no-do-alert-status`: Αποτρέπει τον επανυπολογισμό της κατάστασης των alerts.
- `--iterative`: Ενεργοποιεί την επιθεώρηση μιας περιόδου χρησιμοποιώντας ημερήσιες επαναλήψεις. Η προεπιλογή είναι iterative.
- `--no-iterative`: Εκτελεί την επιθεώρηση ολόκληρης της περιόδου σε μία φορά.
- `--enable_notification`, `-en`: Ενεργοποιεί την αποστολή ειδοποιήσεων σε περίπτωση alerts.
- `--timing`, `-tm`: Εμφανίζει τη διάρκεια της διαδικασίας επιθεώρησης μετά την ολοκλήρωση.
  
#### Παράδειγμα
  
Για να επιθεωρήσετε δεδομένα για το έργο `ProjectA` από την 1 Ιανουαρίου 2024 έως την 31 Ιανουαρίου 2024:
  
```bash
dignacli inspect ProjectA 2024-01-01 2024-01-31
```
  
Για να επιθεωρήσετε μόνο έναν συγκεκριμένο πίνακα και να αναγκάσετε επανυπολογισμό των predictions:
  
```bash
dignacli inspect ProjectA 2024-01-01 2024-01-31 --table-name Table1 --force-prediction
```
Αυτή η εντολή είναι χρήσιμη για τη δημιουργία ενημερωμένων profiles και predictions, την παρακολούθηση της ακεραιότητας των δεδομένων και τη διαχείριση του συστήματος ειδοποιήσεων εντός ενός καθορισμένου χρονικού διαστήματος έργου.

## Χρήση της εντολής `tls-status`

Η εντολή `tls-status` στο CLI του ***digna*** χρησιμοποιείται για να ερωτηθεί η κατάσταση του Traffic Light System (TLS) για έναν συγκεκριμένο πίνακα εντός ενός έργου σε μια δεδομένη ημερομηνία. Το Traffic Light System παρέχει πληροφορίες για την υγεία και την ποιότητα των δεδομένων, υποδεικνύοντας τυχόν προβλήματα ή ειδοποιήσεις που ενδέχεται να απαιτούν προσοχή.
  
#### Χρήση εντολής
  
```bash
dignacli tls-status <PROJECT_NAME> <TABLE_NAME> <DATE>
```
  
#### Ορίσματα
  
- **PROJECT_NAME**: Το όνομα του έργου για το οποίο ζητείται η κατάσταση TLS (απαιτείται).
- **TABLE_NAME**: Ο συγκεκριμένος πίνακας εντός του έργου για τον οποίο απαιτείται η κατάσταση TLS (απαιτείται).
- **DATE**: Η ημερομηνία για την οποία ζητείται η κατάσταση TLS, συνήθως στο format %Y-%m-%d (απαιτείται).
  
#### Παράδειγμα
  
Για να ελέγξετε την κατάσταση TLS για έναν πίνακα με όνομα UserData στο έργο ProjectA την 1 Ιουλίου 2024:

```bash
dignacli tls-status ProjectA UserData 2024-07-01
```

Αυτή η εντολή βοηθά τους χρήστες να παρακολουθούν και να διατηρούν την ποιότητα των δεδομένων παρέχοντας μια σαφή και εφαρμόσιμη αναφορά κατάστασης με βάση προκαθορισμένα κριτήρια.

## Χρήση της εντολής `inspect-async`

Η εντολή `inspect-async` στο CLI του ***digna*** χρησιμοποιείται για να δώσει εντολή στο backend να εκτελέσει ασύγχρονα την επιθεώρηση για μία ή περισσότερες πηγές δεδομένων για ένα συγκεκριμένο έργο. Εάν το PROJECT_NAME οριστεί σε `all-projects`, η επιθεώρηση θα επαναληφθεί σε όλα τα διαθέσιμα έργα και θα εκτελεστεί ασύγχρονα. Η εντολή επιστρέφει ένα request id που μπορεί να χρησιμοποιηθεί για την παρακολούθηση της προόδου της επιθεώρησης.

#### Χρήση εντολής

```bash
dignacli inspect-async <PROJECT_NAME> <FROM_DATE> <TO_DATE> [options]
```
  
#### Ορίσματα
  
- **PROJECT_NAME**: Το όνομα του έργου για το οποίο θα πραγματοποιηθεί η επιθεώρηση των δεδομένων (απαιτείται). Η χρήση της λέξης-κλειδί `all-projects` σε αυτό το όρισμα υποδεικνύει στο ***digna*** να επαναλάβει την εντολή σε όλα τα υπάρχοντα έργα.
- **FROM_DATE**: Η αρχική ημερομηνία και ώρα για την επιθεώρηση των δεδομένων. Αποδεκτά formats περιλαμβάνουν %Y-%m-%d, %Y-%m-%dT%H:%M:%S, ή %Y-%m-%d %H:%M:%S (απαιτείται).
- **TO_DATE**: Η τελική ημερομηνία και ώρα για την επιθεώρηση των δεδομένων, με τα ίδια formats όπως το FROM_DATE (απαιτείται).
  
#### Επιλογές

- `--table-name`, `-tn`: Περιορίζει την επιθεώρηση σε έναν συγκεκριμένο πίνακα εντός του έργου.
- `--table-filter`, `-tf`: Φίλτρο για επιθεώρηση μόνο των πινάκων που περιέχουν τη συγκεκριμένη υποσειρά στο όνομά τους.

  
#### Παράδειγμα
  
Για να επιθεωρήσετε δεδομένα για το έργο `ProjectA` από 1 Ιανουαρίου 2024 έως 31 Ιανουαρίου 2024:
  
```bash
dignacli inspect-async ProjectA 2024-01-01 2024-01-31
```
  
## Χρήση της εντολής `inspect-status`

Η εντολή `inspect-status` στο CLI του ***digna*** χρησιμοποιείται για να ελέγξει την πρόοδο μιας ασύγχρονης επιθεώρησης με βάση το request ID.

#### Χρήση εντολής

```bash
dignacli inspect-status <REQUEST ID> [options]
```
  
#### Ορίσματα
  
- **REQUEST_ID**: Το request id που επιστράφηκε από την εντολή `inspect-async`. 
  
#### Επιλογές

- `--report_level`, `-rl`: Ορίζει το επίπεδο αναφοράς: 'task' ή 'step' [default: task]
  
#### Παράδειγμα
  
Για να ελέγξετε την πρόοδο μιας επιθεώρησης με request ID 12345 σε λεπτομερές επίπεδο βημάτων:
  
```bash
dignacli inspect-status 12345 --report-level step
```
  
## Χρήση της εντολής `export-ds`

Η εντολή `export-ds` στο CLI του ***digna*** χρησιμοποιείται για τη δημιουργία εξαγωγής (export) των πηγών δεδομένων από το αποθετήριο του ***digna***. Από προεπιλογή, όλες οι πηγές δεδομένων ενός δοθέντος έργου θα εξαχθούν.

#### Χρήση εντολής
  
```bash
dignacli export-ds <PROJECT_NAME> [options]
```

#### Ορίσματα
- **PROJECT_NAME**: Το όνομα του έργου από το οποίο θα εξαχθούν οι πηγές δεδομένων.

#### Επιλογές

- `--table_name`, `-tn`: Εξάγει μια συγκεκριμένη πηγή δεδομένων από ένα έργο.
- `--exportfile`, `-ef`: Καθορίζει το όνομα αρχείου για την εξαγωγή.
    
#### Παράδειγμα
  
Για να εξάγετε όλες τις πηγές δεδομένων από το έργο με όνομα `ProjectA`:
  
```bash
dignacli export-ds ProjectA
```
  
Αυτή η εντολή εξάγει όλες τις πηγές δεδομένων από το `ProjectA` ως έγγραφο JSON που μπορεί να εισαχθεί σε άλλο έργο ή αποθετήριο του ***digna***.


## Χρήση της εντολής `import-ds`

Η εντολή `import-ds` στο CLI του ***digna*** χρησιμοποιείται για την εισαγωγή πηγών δεδομένων σε ένα στόχο έργο και για τη δημιουργία αναφοράς εισαγωγής.

#### Χρήση εντολής
  
```bash
dignacli import-ds <PROJECT_NAME> <EXPORT_FILE> [options]
```

#### Ορίσματα
- **PROJECT_NAME**: Το όνομα του έργου στο οποίο θα εισαχθούν οι πηγές δεδομένων.
- **EXPORT_FILE**: Το όνομα αρχείου της εξαγωγής των πηγών δεδομένων που θα εισαχθεί.

#### Επιλογές

- `--output-file`, `-o`: Αρχείο για αποθήκευση της αναφοράς εισαγωγής (εάν δεν καθοριστεί, εκτυπώνεται στο τερματικό σε μορφή πίνακα).
- `--output-format`, `-f`: Μορφή για αποθήκευση της αναφοράς εισαγωγής (json, csv).
    
#### Παράδειγμα
  
Για να εισαγάγετε όλες τις πηγές δεδομένων από το αρχείο εξαγωγής `my_export.json` στο `ProjectB`:
  
```bash
dignacli import-ds ProjectB my_export.json
```
  
Μετά την εισαγωγή, αυτή η εντολή θα εμφανίσει επίσης μια αναφορά των εισαχθέντων και παραληφθέντων αντικειμένων. Μόνο νέες πηγές δεδομένων θα εισαχθούν στο `ProjectB`. Για να μάθετε ποια αντικείμενα θα εισαχθούν και ποια θα παραλειφθούν, μπορείτε να χρησιμοποιήσετε την εντολή `plan-import-ds`.

## Χρήση της εντολής `plan-import-ds`

Η εντολή `plan-import-ds` στο CLI του ***digna*** χρησιμοποιείται για την ανάλυση μιας εξαγωγής πηγών δεδομένων πριν την πραγματική εισαγωγή και για τη δημιουργία αναφοράς σχεδίου εισαγωγής.

#### Χρήση εντολής
  
```bash
dignacli plan-import-ds <PROJECT_NAME> <EXPORT_FILE> [options]
```

#### Ορίσματα
- **PROJECT_NAME**: Το όνομα του έργου στο οποίο θα εισαγούν οι πηγές δεδομένων (προσομοίωση του τι θα γίνει).
- **EXPORT_FILE**: Το όνομα αρχείου της εξαγωγής των πηγών δεδομένων που θα αναλυθεί πριν την εισαγωγή.

#### Επιλογές

- `--output-file`, `-o`: Αρχείο για αποθήκευση της αναφοράς σχεδίου εισαγωγής (εάν δεν καθοριστεί, εκτυπώνεται στο τερματικό σε μορφή πίνακα).
- `--output-format`, `-f`: Μορφή για αποθήκευση της αναφοράς σχεδίου (json, csv).
    
#### Παράδειγμα
  
Για να ελέγξετε ποιες πηγές δεδομένων θα εισαχθούν και ποιες θα παραλειφθούν από το αρχείο εξαγωγής `my_export.json` όταν θα εισαχθεί στο `ProjectB`:
  
```bash
dignacli plan-import-ds ProjectB my_export.json
```
  
Αυτή η εντολή θα εμφανίσει μόνο ένα σχέδιο εισαγωγής των αντικειμένων που θα εισαχθούν και αυτών που θα παραλειφθούν.
