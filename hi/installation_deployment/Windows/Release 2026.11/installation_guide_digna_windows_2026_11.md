## परिचय {: #introduction }

### digna के बारे में

digna एक व्यापक AI-चालित प्लेटफ़ॉर्म है जो डेटा वेयरहाउस, लेक्स और लेकहाउस जैसे विभिन्न डेटा परिवेशों में डेटा क्वालिटी प्रबंधन को अनुकूलित करने के लिए डिज़ाइन किया गया है। उच्च स्केलेबिलिटी और अनुकूलनशीलता के साथ बनाया गया, digna स्वचालन, रीयल-टाइम मॉनिटरिंग और एनॉमली डिटेक्शन के माध्यम से आधुनिक डेटा चुनौतियों का समाधान करता है।

digna मुख्य रूप से दो घटकों से मिलकर बनता है:

- **digna**: एप्लिकेशन का केंद्र, जो डेटा संसाधित करने और गुणवत्ता जाँच चलाने के लिए ज़िम्मेदार है। यह बैकएंड और कमांड लाइन इंटरफ़ेस को एक ही निष्पादन योग्य फ़ाइल में जोड़ता है और पिछली रिलीज़ के अलग-अलग प्रोग्राम `dignabackend` तथा `dignacli` की जगह लेता है।
- **dignadashboard**: एक वेब-आधारित इंटरफ़ेस जो वेब सर्वर पर होस्ट होता है और digna प्लेटफ़ॉर्म के साथ इंटरैक्ट करने तथा डेटा गुणवत्ता मेट्रिक्स को विज़ुअलाइज़ करने के लिए उपयोगकर्ता-अनुकूल तरीका प्रदान करता है।

### रिलीज़ 2026.11 में नया क्या है

यह रिलीज़ digna Data Reconciliation, digna MCP Server के साथ digna Agentic, और digna Engine जोड़ती है, जो digna के भीतर डेटा को प्रोफाइल कर सकता है और अलग-अलग डेटाबेस तकनीकों के बीच रेफरेंशियल इंटीग्रिटी की जाँच कर सकता है। पूर्ण विवरण के लिए देखें [रिलीज़ नोट्स](../../../changelog/Release_202611.md)।

इंस्टॉलेशन के लिए यह रिलीज़ एक नया रिपॉज़िटरी माइग्रेशन तंत्र, digna Engine के लिए `config.toml` में एक वैकल्पिक `[duckdb]` सेक्शन, और एक नई लाइसेंस फ़ाइल लाती है। [अपग्रेड सेक्शन](#upgrading-to-a-new-release) इनमें से हर एक को कवर करता है।

### macOS या Linux ढूँढ रहे हैं?

यह गाइड Windows के लिए है। अन्य प्लेटफ़ॉर्म के लिए, देखिए [macOS स्थापना मार्गदर्शिका](../../macOS/Release%202026.11/installation_guide_digna_macos_2026_11.md) या [Linux स्थापना मार्गदर्शिका](../../Linux/Release%202026.11/installation_guide_digna_linux_2026_11.md)।

## सिस्टम आवश्यकताएँ {: #system-requirements }

स्थापना शुरू करने से पहले सुनिश्चित करें कि आपका सिस्टम निम्नलिखित न्यूनतम आवश्यकताओं को पूरा करता है:

| आवश्यकता | विशिष्टता |
|---|---|
| **ऑपरेटिंग सिस्टम** | Windows Server या Windows 10/11 |
| **मेमोरी (न्यूनतम सेटअप)** | 16 GB RAM |
| **डिस्क स्थान** | 10 GB उपलब्ध स्टोरेज |
| **डेटाबेस** | PostgreSQL Server 12 या ऊपर |
| **वेब सर्वर** | IIS, Apache Tomcat, या समकक्ष |

!!! info "digna Engine"

    जो डेटाबेस कनेक्शन प्रोफाइलिंग लोकेशन के रूप में digna Engine का उपयोग करते हैं, उन्हें स्वयं
    digna होस्ट पर प्रोफाइल किया जाता है। उनके लिए अतिरिक्त मेमोरी और डिस्क स्थान की योजना बनाएँ, देखें
    [\[duckdb\] सेक्शन](#duckdb-section)।

### डेटाबेस इंस्टॉलेशन विकल्प

**यदि PostgreSQL पहले से स्थापित है:**
आप अपने मौजूदा PostgreSQL Server में digna के लिए एक नया डेटाबेस जोड़ सकते हैं।

**यदि आप PostgreSQL को उसी मशीन पर इंस्टॉल कर रहे हैं जहाँ digna है:**

!!! info "अनुशंसित विनिर्देश"

    - **मेमोरी**: 32 GB RAM (16 GB के बजाय)
    - **डिस्क स्थान**: 50 GB उपलब्ध स्टोरेज (10 GB के बजाय)

    ये उच्चतर विनिर्देश दोनों, digna और PostgreSQL डेटाबेस को एक साथ चलाने के लिए उपयुक्त हैं।

## पूर्व-स्थापना सेटअप {: #pre-installation-setup }

digna स्थापित करने से पहले सुनिश्चित करें कि दो प्रमुख पूर्व-आवश्यकताएँ मौजूद हैं:

यदि ये घटक पहले से सेटअप नहीं हैं, तो उन्हें इंस्टॉल और कॉन्फ़िगर करने के लिए नीचे दिए गए अनुभागों का पालन करें।

## PostgreSQL सर्वर सेटअप {: #postgresql-server-setup }

### यदि आपके पास पहले से PostgreSQL है

यदि PostgreSQL पहले से आपके लोकल मशीन पर इंस्टॉल और चल रहा है या आप मैनज्ड रिमोट PostgreSQL सर्वर का उपयोग कर रहे हैं, तो आप [अगले अनुभाग](#web-server-configuration) पर जा सकते हैं।

### PostgreSQL इंस्टॉल करना

Windows पर PostgreSQL इंस्टॉल करने के लिए निम्न चरणों का पालन करें:

#### चरण 1: PostgreSQL डाउनलोड करें

1. [PostgreSQL Downloads पेज](https://www.postgresql.org/download/) पर जाएँ
2. **Windows** चुनें
3. नवीनतम इंस्टॉलर डाउनलोड करें

#### चरण 2: इंस्टॉलर चलाएँ

1. डाउनलोड किए गए इंस्टॉलर फ़ाइल पर डबल-क्लिक करें
2. सेटअप विज़ार्ड में दिए गए निर्देशों का पालन करें

#### चरण 3: इंस्टॉलेशन डायरेक्टरी चुनें

PostgreSQL किस डायरेक्टरी में इंस्टॉल होगा यह चुनें। डिफ़ॉल्ट लोकेशन आम तौर पर उपयुक्त होती है।

#### चरण 4: कंपोनेंट्स चुनें

मानक सेटअप के लिए, डिफ़ॉल्ट कंपोनेंट विकल्पों को चुन कर रखें।

#### चरण 5: PostgreSQL सुपरयूज़र पासवर्ड सेट करें

PostgreSQL सुपरयूज़र (`postgres`) के लिए एक पासवर्ड दर्ज करें और पुष्टि करें। **इस पासवर्ड को सुरक्षित रखें** — आपको बाद में इसकी आवश्यकता होगी।

#### चरण 6: पोर्ट नंबर कॉन्फ़िगर करें

डिफ़ॉल्ट PostgreSQL पोर्ट `5432` है। आप डिफ़ॉल्ट उपयोग कर सकते हैं या आवश्यकता अनुसार अलग पोर्ट निर्दिष्ट कर सकते हैं।

!!! tip "सुझाव"

    यदि पोर्ट 5432 पहले ही उपयोग में है, तो एक वैकल्पिक पोर्ट चुनें और बाद में कॉन्फ़िगरेशन के लिए उसे नोट कर लें।

#### चरण 7: स्थानीयकरण (Locale) चुनें

अपने डेटाबेस के लिए लोकेल चुनें। अधिकांश इंस्टॉलेशन के लिए डिफ़ॉल्ट सामान्यतः उपयुक्त होता है।

#### चरण 8: इंस्टॉलेशन पूर्ण करें

बचे हुए चरणों में **Next** पर क्लिक करें, फिर **Finish** पर क्लिक करें।

#### चरण 9: इंस्टॉलेशन सत्यापित करें

Command Prompt खोलें और सत्यापित करें कि PostgreSQL इंस्टॉल हुआ है:

```bash
psql --version
```

यदि इंस्टॉलेशन सफल था तो आपको PostgreSQL संस्करण दिखाई देगा।

## वेब सर्वर कॉन्फ़िगरेशन {: #web-server-configuration }

digna को डैशबोर्ड होस्ट करने के लिए एक वेब सर्वर की आवश्यकता होती है। निम्नलिखित विकल्पों में से किसी एक को चुनें:

- [Internet Information Services (IIS)](#iis-setup)
- [Apache Tomcat](#apache-tomcat-setup)

आपको केवल इनमें से **एक** सर्वर इंस्टॉल और कॉन्फ़िगर करना होगा।

### IIS सेटअप {: #iis-setup }

#### अवलोकन

Internet Information Services (IIS) माइक्रोसॉफ्ट का वेब सर्वर है जो वेबसाइट्स और वेब एप्लिकेशन होस्ट करने के लिए उपयोग होता है।

#### IIS सक्षम करना

1. **Control Panel खोलें**
   - `Win + R` दबाएँ
   - टाइप करें `control` और Enter दबाएँ

2. **Windows Features पर जाएँ**
   - **Programs** पर क्लिक करें
   - **Turn Windows features on or off** चुनें

3. **Internet Information Services सक्षम करें**
   - नीचे स्क्रॉल करें और **Internet Information Services (IIS)** ढूँढें
   - इसे सक्षम करने के लिए चेकबॉक्स पर टिक करें
   - विस्तार के लिए **+** पर क्लिक करें और सुनिश्चित करें कि ये सबकंपोनेंट्स चुने गए हैं:
     - **Web Management Tools**
     - **World Wide Web Services**

4. परिवर्तन लागू करने के लिए **OK** पर क्लिक करें

5. **IIS इंस्टॉलेशन सत्यापित करें**
   - अपना ब्राउज़र खोलें
   - `http://localhost` पर जाएँ
   - आपको IIS Welcome पेज दिखाई देना चाहिए

#### आवश्यक: URL Rewrite मॉड्यूल

IIS के लिए URL Rewrite कंपोनेंट आवश्यक है। इसे [आधिकारिक Microsoft पेज](https://www.iis.net/downloads/microsoft/url-rewrite) से डाउनलोड और इंस्टॉल करें।

#### आवश्यक: Markdown फ़ाइलों के लिए MIME प्रकार

यह सुनिश्चित करने के लिए कि Markdown फ़ाइलें (`.md`) IIS द्वारा सही ढंग से सर्व हों:

1. **IIS Manager** खोलें ( `Win + R`, टाइप करें `inetmgr`, Enter दबाएँ )
2. **Your Site > MIME Types** पर नेविगेट करें
3. **Add...** पर क्लिक करें
4. कॉन्फ़िगर करें:
   - **File name extension**: `.md`
   - **MIME type**: `text/markdown`

!!! warning "महत्वपूर्ण"

    इस सेटिंग के बिना, `.md` फ़ाइलें सही ढंग से सर्व नहीं हो सकती हैं।

### Apache Tomcat सेटअप {: #apache-tomcat-setup }

#### अवलोकन

Apache Tomcat एक ओपन-सोर्स Java servlet कंटेनर और वेब सर्वर है।

#### इंस्टॉलेशन

1. **Apache Tomcat डाउनलोड करें**
   - [Apache Tomcat Downloads](https://tomcat.apache.org/download-90.cgi) पर जाएँ
   - Windows ZIP distribution डाउनलोड करें

2. **आर्काइव एक्सट्रैक्ट करें**
   - ZIP फ़ाइल को अपने सिस्टम की किसी डायरेक्टरी में एक्सट्रैक्ट करें
   - उदाहरण: `C:\Program Files\Apache Tomcat`

3. **Tomcat चल रहा है यह सत्यापित करें**
   - अपना ब्राउज़र खोलें
   - `http://localhost:8080` पर जाएँ
   - आपको Apache Tomcat welcome पेज दिखाई देना चाहिए

!!! tip "सुझाव"

    इंस्टॉलेशन के बाद Apache Tomcat सामान्यतः स्वतः शुरू हो जाता है। यदि ऐसा नहीं होता है, तो `bin` फ़ोल्डर में जाएँ और `startup.bat` चलाएँ।

## प्रारंभिक स्थापना {: #initial-installation }

### चरण 1: digna रिपॉज़िटरी सेट करें

digna रिपॉज़िटरी उन सभी मेट्रिक्स को संग्रहीत करती है जो digna द्वारा गणना किए जाते हैं। यह विश्लेषणात्मक और प्रदर्शन डेटा के लिए केंद्रीय डेटाबेस के रूप में कार्य करती है।

#### रिपॉज़िटरी स्कीमा और यूज़र बनाएं

अपना PostgreSQL क्लाइंट (pgAdmin, psql, या समान) खोलें और निम्न SQL कमांड्स चलाएँ:

```sql
CREATE SCHEMA <digna_repo_schema>;

CREATE USER <digna_repo_user> WITH PASSWORD '<digna_repo_password>';

GRANT ALL PRIVILEGES ON SCHEMA <digna_repo_schema> TO <digna_repo_user>;
```

**निम्न प्लेसहोल्डर्स बदलें:**

- `<digna_repo_schema>` — आपका वांछित स्कीमा नाम (उदा., `dignarepo`)
- `<digna_repo_user>` — आपका वांछित उपयोगकर्ता नाम (उदा., `digna_user`)
- `<digna_repo_password>` — इस उपयोगकर्ता के लिए एक सुरक्षित पासवर्ड

**उदाहरण:**

```sql
CREATE SCHEMA dignarepo;

CREATE USER digna_user WITH PASSWORD 'YourSecurePassword123!';

GRANT ALL PRIVILEGES ON SCHEMA dignarepo TO digna_user;
```

!!! tip "सर्वोत्तम अभ्यास"

    डेटाबेस उपयोगकर्ताओं के लिए मजबूत, जटिल पासवर्ड का उपयोग करें। आसानी से अनुमान लगाने योग्य क्रेडेंशियल्स से बचें।

---

### चरण 2: digna इंस्टॉलेशन पैकेज एक्सट्रैक्ट करें

1. आपको दिए गए digna इंस्टॉलेशन ZIP फ़ाइल का स्थान ढूँढें
2. इसे अपनी वांछित इंस्टॉलेशन लोकेशन में एक्सट्रैक्ट करें
3. एक्सट्रैक्शन के बाद आपको निम्न आइटम दिखाई देने चाहिए:
   - `dashboard/` — वेब डैशबोर्ड इंटरफ़ेस
   - `digna` — मुख्य executable (बैकएंड + CLI संयुक्त)

!!! info "कॉन्फ़िगरेशन और लाइसेंस फ़ाइलें पैकेज में नहीं हैं"

    न तो `config.toml` और न ही `dashboard/dashboard_config.toml` इंस्टॉलेशन के साथ आती है — दोनों को आप
    स्वयं बनाते हैं, [बैकएंड कॉन्फ़िगरेशन](#backend-configuration) और
    [डैशबोर्ड कॉन्फ़िगरेशन](#dashboard-configuration) में। `license.toml` भी साथ नहीं आती;
    digna इसे अलग से उपलब्ध कराता है, जैसा कि चरण 3 में बताया गया है।

### चरण 3: लाइसेंस फ़ाइल इंस्टॉल करें

!!! warning "महत्वपूर्ण"

    लाइसेंस फ़ाइल इंस्टॉलेशन पैकेज में शामिल नहीं होती और आपको अलग से digna द्वारा प्रदान की जाएगी।

1. आपको प्रदान की गई `license.toml` फ़ाइल खोजें
2. इसे digna इंस्टॉलेशन के रूट डायरेक्टरी में कॉपी करें (जहाँ `config.toml` और `digna` executable स्थित हैं)

**क्यों यह महत्वपूर्ण है:**
लाइसेंस फ़ाइल में आपका ग्राहक विवरण, लाइसेंस एक्सपायरी तिथि, और डिजिटल सिग्नेचर होती है। **इस फ़ाइल में बदलाव न करें** — किसी भी परिवर्तन से यह अमान्य हो जाएगी।

**सेटअप के बाद निर्देशिका संरचना:**

```
digna_installation/
├── config.toml         (configuration file)
├── license.toml        (YOUR LICENSE FILE - copy here)
├── digna               (main executable)
└── dashboard/          (web interface)
    └── (dashboard files)
```

## बैकएंड कॉन्फ़िगरेशन {: #backend-configuration }

### चरण 1: कॉन्फ़िगरेशन फ़ाइल बनाएं और संपादित करें

आपके digna इंस्टॉलेशन डायरेक्टरी में `config_template.toml` फ़ाइल दी गई है। आपको इसे केवल `config.toml` में नाम बदलने की आवश्यकता है।

**स्थान:** `digna_installation/config.toml`

`config.toml` को किसी टेक्स्ट एडिटर में खोलें और नीचे दिए गए प्रत्येक सेक्शन को कॉन्फ़िगर करें।

#### [app] सेक्शन

यह सेक्शन डैशबोर्ड और बैकएंड के बीच क्रॉस-ओरिजिन रिसोर्स शेयरिंग (CORS) को कॉन्फ़िगर करता है:

```toml
[app]
DIGNA_APP_CORS_ALLOW_ORIGINS = ["http://localhost:5173"]
DIGNA_APP_CORS_ALLOW_CREDENTIALS = true
```

| पैरामीटर | मान | नोट्स |
|---|---|---|
| `DIGNA_APP_CORS_ALLOW_ORIGINS` | डैशबोर्ड URL | वे URL जिनसे डैशबोर्ड सर्व किया जाता है। किसी अन्य origin से आने वाले ब्राउज़र अनुरोध अस्वीकार कर दिए जाते हैं |
| `DIGNA_APP_CORS_ALLOW_CREDENTIALS` | `true` | आवश्यक, ताकि ब्राउज़र हर अनुरोध के साथ सत्र कुकी भेजे |

!!! info "[app] सेक्शन वैकल्पिक है"

    रिलीज़ 2026.11 से दोनों कुंजियाँ, और पूरा `[app]` सेक्शन, छोड़े जा सकते हैं। यह तब सही सेटअप है
    जब कोई रिवर्स प्रॉक्सी डैशबोर्ड और बैकएंड को एक ही origin के अंतर्गत सर्व करता है: तब ब्राउज़र
    कोई क्रॉस-ओरिजिन अनुरोध नहीं करता, और डिफ़ॉल्ट रूप से किसी की अनुमति नहीं होती।

#### [repo] सेक्शन

यह सेक्शन PostgreSQL डेटाबेस से कनेक्शन को कॉन्फ़िगर करता है:

```toml
[repo]
DIGNA_REPO_HOST = "localhost"
DIGNA_REPO_PORT = 5432
DIGNA_REPO_DB = "postgres"
DIGNA_REPO_SCHEMA = "dignarepo"
DIGNA_REPO_USER = "digna_user"
DIGNA_REPO_PASSWORD = "YourSecurePassword123!"
DIGNA_REPO_SSLMODE = "prefer"
DIGNA_REPO_NUM_CONNS = 16
```

| पैरामीटर | मान | नोट्स |
|---|---|---|
| `DIGNA_REPO_HOST` | `localhost` या IP | PostgreSQL सर्वर होस्टनाम/IP |
| `DIGNA_REPO_PORT` | `5432` (डिफ़ॉल्ट) | PostgreSQL पोर्ट |
| `DIGNA_REPO_DB` | `postgres` | डेटाबेस नाम |
| `DIGNA_REPO_SCHEMA` | `dignarepo` | पहले बनाया गया स्कीमा |
| `DIGNA_REPO_USER` | `digna_user` | PostgreSQL सेटअप में बनाया गया उपयोगकर्ता |
| `DIGNA_REPO_PASSWORD` | आपका पासवर्ड | स्कीमा निर्माण के दौरान सेट किया गया पासवर्ड |
| `DIGNA_REPO_SSLMODE` | `prefer` (डिफ़ॉल्ट) | वैकल्पिक। PostgreSQL SSL मोड: `disable`, `allow`, `prefer`, `require`, `verify-ca` या `verify-full` |
| `DIGNA_REPO_NUM_CONNS` | `16` (डिफ़ॉल्ट) | वैकल्पिक। रिपॉज़िटरी से digna द्वारा खुले रखे जाने वाले कनेक्शनों की संख्या |

#### [base] सेक्शन

यह सेक्शन सुरक्षा, कुकी और निरीक्षण सेटिंग्स रखता है:

```toml
[base]
DIGNA_FERNET_KEY = "DU4a0yJ-OqvbKCL4hNQn_CsknH-V1vWmHZqBUl-AY44="
DIGNA_COOKIE_DOMAIN = "localhost"
DIGNA_COOKIE_SECURE = false
DIGNA_COOKIE_HTTPONLY = true
DIGNA_TOKEN_EXPIRES_IN = 86400
DIGNA_MAX_WORKERS = 4
DIGNA_FRONTEND_BASEURL = "http://localhost/"
DIGNA_SOURCE_QUERY_TIMEOUT_SEC = 3600
DIGNA_SOURCE_LOGIN_TIMEOUT_SEC = 30
```

| पैरामीटर | मान | नोट्स |
|---|---|---|
| `DIGNA_FERNET_KEY` | ऊपर दिखाया गया मान | पिछली रिलीज़ द्वारा उपयोग किए गए एन्क्रिप्शन की कुंजी। यह मौजूद होनी चाहिए; दिखाया गया मान ही रखें |
| `DIGNA_COOKIE_DOMAIN` | `localhost` | वह होस्ट जिसके अंतर्गत डैशबोर्ड तक पहुँचा जाता है। `""` कोई डोमेन सेट नहीं करता, जो ऐसे प्रॉक्सी के पीछे सही है जो डैशबोर्ड और बैकएंड को एक ही origin के अंतर्गत सर्व करता है |
| `DIGNA_COOKIE_SECURE` | `false` (HTTP) / `true` (HTTPS) | जब भी digna HTTPS पर सर्व किया जाता है, इसे `true` होना चाहिए |
| `DIGNA_COOKIE_HTTPONLY` | `true` | सत्र कुकी को स्क्रिप्ट्स की पहुँच से बाहर रखता है |
| `DIGNA_TOKEN_EXPIRES_IN` | `86400` (24 घंटे) | सेकंड में सत्र का टाइमआउट |
| `DIGNA_MAX_WORKERS` | CPU कोर की संख्या - 1 | एक ही समय में चल सकने वाले निरीक्षणों की संख्या |
| `DIGNA_FRONTEND_BASEURL` | डैशबोर्ड URL | आवश्यक। सूचना संदेशों के लिंक के लिए उपयोग होता है, इसलिए यह ऐसा URL होना चाहिए जिसे प्राप्तकर्ता खोल सकें |
| `DIGNA_SOURCE_QUERY_TIMEOUT_SEC` | `3600` (डिफ़ॉल्ट) | वैकल्पिक। किसी स्रोत डेटाबेस पर एक क्वेरी रद्द किए जाने से पहले कितने सेकंड चल सकती है; `0` टाइमआउट को अक्षम करता है |
| `DIGNA_SOURCE_LOGIN_TIMEOUT_SEC` | `30` (डिफ़ॉल्ट) | वैकल्पिक। किसी स्रोत डेटाबेस से कनेक्शन के लिए प्रतीक्षा के सेकंड; `0` अनिश्चित काल तक प्रतीक्षा करता है |

#### [encryption] सेक्शन

इस सेक्शन में वह कुंजी होती है जिससे रिपॉज़िटरी में संग्रहीत संवेदनशील मान एन्क्रिप्ट किए जाते हैं। यह **आवश्यक** है — कुंजी न होने पर `config check` सेक्शन `[encryption]` को FAILED बताता है।

```toml
[encryption]
DIGNA_ENCRYPTION_KEY = 'ycELf6IbcO55dYIZHpPv6kQv/bbnUXoIaHLh2bh1kMg='
```

| पैरामीटर | मान | नोट्स |
|---|---|---|
| `DIGNA_ENCRYPTION_KEY` | Base64 में एन्कोड की गई कुंजी | digna रिपॉज़िटरी में संग्रहीत संवेदनशील मानों को एन्क्रिप्ट करती है |

!!! warning "config.toml की सुरक्षा करें"

    यह कुंजी एक निश्चित मान है, जो सभी digna संस्थापनों में एक समान है, और यही आपकी रिपॉज़िटरी के संवेदनशील मानों को डिक्रिप्ट करती है। `config.toml` तक पहुँच उसी खाते तक सीमित रखें जिससे digna चलता है, फ़ाइल को संस्करण नियंत्रण और साझा ड्राइव से बाहर रखें, और उसे हर ऐसे बैकअप से हटा दें जो रिपॉज़िटरी की तुलना में कम सुरक्षित रखा जाता है।

#### [logging] सेक्शन

यह सेक्शन लॉगिंग व्यवहार को कॉन्फ़िगर करता है:

```toml
[logging]
DIGNA_LOGGING_MODE = "INFO"
DIGNA_LOGGING_DIR = "logs"
DIGNA_LOGGING_MAX_FILES = 30
```

| पैरामीटर | मान | नोट्स |
|---|---|---|
| `DIGNA_LOGGING_MODE` | `INFO` या `DEBUG` | प्रोडक्शन के लिए `INFO`, ट्रबलशूटिंग के लिए `DEBUG`। `TRACE`, `WARN` और `ERROR` भी स्वीकार किए जाते हैं |
| `DIGNA_LOGGING_DIR` | `logs` (डिफ़ॉल्ट) | वैकल्पिक। रोटेट होने वाली लॉग फ़ाइलों की डायरेक्टरी, कार्यशील डायरेक्टरी के सापेक्ष |
| `DIGNA_LOGGING_MAX_FILES` | `30` (डिफ़ॉल्ट) | वैकल्पिक। रखी जाने वाली रोटेट की गई लॉग फ़ाइलों की संख्या |

!!! warning "सेवा के रूप में चलाते समय लॉग डायरेक्टरी बनाए रखें"

    Windows सेवा का कोई कंसोल नहीं होता, इसलिए लॉग फ़ाइलें ही इस बात का एकमात्र रिकॉर्ड हैं कि सेवा
    क्या करती है। `DIGNA_LOGGING_DIR` को खाली स्ट्रिंग पर सेट न करें, क्योंकि इससे लॉग फ़ाइलें बंद हो जाती हैं।

#### [duckdb] सेक्शन (वैकल्पिक) {: #duckdb-section }

रिलीज़ 2026.11 में नया। यह सेक्शन **digna Engine** के संसाधन निर्धारित करता है, जो उन डेटाबेस
कनेक्शनों के लिए digna के भीतर डेटा को प्रोफाइल करता है जिनकी प्रोफाइलिंग लोकेशन **digna Engine** है, और
अलग-अलग डेटाबेस कनेक्शनों पर स्थित डेटा स्रोतों के बीच रेफरेंशियल इंटीग्रिटी जाँच चलाता है। देखें
[प्रोफाइलिंग लोकेशन](../../../platform/profiling/profiling_location.md)।

यह सेक्शन वैकल्पिक है। इसके बिना नीचे दिए गए डिफ़ॉल्ट लागू होते हैं।

```toml
[duckdb]
DIGNA_DUCKDB_MEMORY_LIMIT_MB = 1024
DIGNA_DUCKDB_TEMP_DIRECTORY = "C:\\path\\to\\digna\\tmp"
```

| पैरामीटर | मान | नोट्स |
|---|---|---|
| `DIGNA_DUCKDB_MEMORY_LIMIT_MB` | `1024` (डिफ़ॉल्ट) | MB में वह मेमोरी जिसका उपयोग digna Engine का एक रन कर सकता है। एक ही समय में अधिकतम `DIGNA_MAX_WORKERS` रन सक्रिय हो सकते हैं |
| `DIGNA_DUCKDB_TEMP_DIRECTORY` | डिफ़ॉल्ट: digna चलाने वाले खाते की अस्थायी डायरेक्टरी (`%TEMP%`) | अस्थायी फ़ाइलों के लिए डायरेक्टरी, जब डेटा मेमोरी में नहीं समाता |

!!! tip "digna Engine का आकार निर्धारण"

    digna होस्ट पर, digna के अपने उपयोग के अतिरिक्त, अधिकतम `DIGNA_MAX_WORKERS` × `DIGNA_DUCKDB_MEMORY_LIMIT_MB`
    मेमोरी की योजना बनाएँ, और अस्थायी डायरेक्टरी में इतने खाली डिस्क स्थान की, जिसमें digna Engine का
    उपयोग करने वाले डेटा स्रोतों की सबसे बड़ी निरीक्षित तिथि समा सके। `DIGNA_DUCKDB_TEMP_DIRECTORY` को ऐसी
    डिस्क पर इंगित करें जिसमें यह स्थान हो और जिस पर digna चलाने वाला खाता लिख सके:

    ```cmd
    mkdir C:\path\to\digna\tmp
    ```

    आपको इस सेक्शन की आवश्यकता तभी है जब कम से कम एक डेटाबेस कनेक्शन digna Engine का उपयोग करता हो, या
    कोई रेफरेंशियल इंटीग्रिटी जाँच अलग-अलग कनेक्शनों पर स्थित डेटा स्रोतों की तुलना करती हो।

### चरण 2: कॉन्फ़िगरेशन जाँचें

रिपॉज़िटरी आरंभ करने से पहले जाँचें कि `config.toml` पूर्ण और सही ढंग से बना है। अपनी digna संस्थापन निर्देशिका में चलाएँ:

```bash
digna config check
```

प्रत्येक सेक्शन की जाँच अलग से होती है, इसलिए एक अकेली गलती बाकी की स्थिति नहीं छिपाती:

```text
Configuration validation report (source: config.toml):
 - App config: OK
 - Repository config: OK
 - Base config: OK
 - Logging config: OK
 - Encryption config: OK
 - OIDC config(s): OK
 - Template overrides: OK
 - Unknown keys: OK

Overall: OK
```

जो कुछ भी FAILED बताया जाए उसे ठीक करें और आगे बढ़ने से पहले कमांड फिर चलाएँ। **Unknown keys** के अंतर्गत WARNING उन कुंजियों को सूचीबद्ध करता है जो `config.toml` में हैं लेकिन जिन्हें digna नहीं पढ़ता; उनका कोई प्रभाव नहीं होता, इसलिए उन्हें हटाएँ या उनकी वर्तनी ठीक करें। विकल्पों की पूरी सूची [CLI संदर्भ](../../../cli/Command_Line_Interface_202611.md) में है।

### चरण 3: रिपॉज़िटरी इनिशियलाइज़ करें

1. Command Prompt खोलें
2. अपने digna इंस्टॉलेशन डायरेक्टरी में नेविगेट करें (जहाँ `config.toml` और `digna` executable स्थित हैं)
3. कनेक्शन टेस्ट चलाएँ:

```bash
digna repo check
```

नए स्कीमा पर कमांड कनेक्ट होती है और फिर बताती है कि अभी कोई रिपॉज़िटरी इंस्टॉल नहीं है:

```text
Error: No repo installed. Use the 'digna repo upgrade' command to install it.
```

इस चरण पर यही अपेक्षित परिणाम है: यह पुष्टि करता है कि digna PostgreSQL और स्कीमा तक पहुँचता है। इसके बजाय कोई कनेक्शन या प्रमाणीकरण त्रुटि `[repo]` सेक्शन या PostgreSQL सेटअप की ओर इशारा करती है।

### चरण 4: रिपॉज़िटरी स्कीमा इंस्टॉल करें

उसी डायरेक्टरी में चलाएँ:

```bash
digna repo upgrade
```

यह कमांड रिपॉज़िटरी स्कीमा में आवश्यक टेबल इंस्टॉल करती है और इस संदेश के साथ समाप्त होती है:

```text
✅ Repo schema 'dignarepo' is up to date.
```

!!! note "repo upgrade इंस्टॉल और अपग्रेड दोनों करता है"

    रिलीज़ 2026.11 से `repo upgrade` नई रिपॉज़िटरी इंस्टॉल करता है और मौजूदा रिपॉज़िटरी को अपग्रेड करता है।
    `repo install` अब भी उसी कमांड के दूसरे नाम के रूप में काम करता है।

### चरण 5: एक एडमिन यूज़र बनाएं

1. एक **नया** Command Prompt विंडो खोलें
2. अपने digna इंस्टॉलेशन डायरेक्टरी में नेविगेट करें
3. एक एडमिन यूज़र बनाने के लिए निम्न कमांड चलाएँ:

```bash
digna user add <email> <password> "<display_name>" --admin
```

**उदाहरण:**

```bash
digna user add admin@example.com "AdminPassword123!" "Admin User" --admin
```

यह पूरा प्रशासनिक अधिकारों वाला उपयोगकर्ता बना देगा।

!!! tip "सर्वोत्तम अभ्यास"

    ऊपरी-निचले अक्षर, संख्याएँ और विशेष वर्णों का मिश्रण करके मजबूत पासवर्ड का उपयोग करें।

### चरण 6: digna सर्वर शुरू करें

digna इंस्टॉलेशन डायरेक्टरी में, सर्वर शुरू करें:

```bash
digna serve --address <host> --port <port>
```

**पैरामीटर:**
- `--address` — सर्वर होस्टनाम/IP (डिफ़ॉल्ट `127.0.0.1`)
- `--port` — सर्वर पोर्ट (डिफ़ॉल्ट `8000`)

सर्वर चालू होने पर, वह उस पते को प्रिंट करता है जिस पर वह सुनता है:

```text
Server running on http://127.0.0.1:8082
```

!!! note "सर्वर टर्मिनल को व्यस्त रखता है"

    `serve` अग्रभूमि में चलता है और तब तक चलता रहता है जब तक आप इसे ++ctrl+c++ से रोक नहीं देते। सेटअप पूरा करते समय इसे चलता रहने दें; इसके बजाय बूट पर स्वतः प्रारंभ करने के लिए देखें [digna को Windows सेवा के रूप में चलाना](#running-digna-as-a-windows-service).

## डैशबोर्ड कॉन्फ़िगरेशन {: #dashboard-configuration }

### चरण 1: डैशबोर्ड को वेब सर्वर पर तैनात करें

digna डैशबोर्ड अपनी कॉन्फ़िगरेशन `dashboard/dashboard_config.toml` से पढ़ता है। यह फ़ाइल इंस्टॉलेशन के साथ नहीं आती — आप इसे `dashboard/` डायरेक्टरी में डैशबोर्ड फ़ाइलों के साथ बनाते हैं।

इसकी सामग्री [सिंगल साइन-ऑन](../../../sso/overview.md) के अंतर्गत बताई गई है, और वहीं इस फ़ाइल की आवश्यकता भी होती है: इसमें वे लॉगिन विकल्प होते हैं जो डैशबोर्ड प्रदान करता है और, मल्टी-इंस्टेंस तैनाती के लिए, बैकएंड कनेक्शन।

अपना वेब सर्वर चुनें और संबंधित तैनाती चरणों का पालन करें।

#### IIS पर डिप्लॉय करना

1. **IIS Manager खोलें**
   - `Win + R` दबाएँ, टाइप करें `inetmgr`, Enter दबाएँ

2. **नई वेबसाइट बनाएं**
   - बाएँ पैनल में, **Sites** पर राइट-क्लिक करें
   - **Add Website...** चुनें

3. **वेबसाइट कॉन्फ़िगर करें**
   - **Site Name**: एक नाम दर्ज करें (उदा., "dignaDashboard")
   - **Physical Path**: Browse पर क्लिक करें और अपनी `dashboard` फ़ोल्डर चुनें
   - **Binding**: IP पता और पोर्ट सेट करें (HTTP के लिए डिफ़ॉल्ट पोर्ट 80, HTTPS के लिए 443)

4. **वेबसाइट शुरू करें**
   - साइट बनाने के लिए **OK** पर क्लिक करें
   - नई साइट पर राइट-क्लिक करें और **Start** चुनें

5. **इंस्टॉलेशन परीक्षण करें**
   - अपना ब्राउज़र खोलें
   - `http://localhost` (या आपका कॉन्फ़िगर किया गया URL) पर जाएँ
   - आपको digna डैशबोर्ड लॉगिन पेज दिखाई देना चाहिए

#### Apache Tomcat पर डिप्लॉय करना

1. **डैशबोर्ड को Tomcat में कॉपी करें**
   - `dashboard` फ़ोल्डर को अपने Tomcat `webapps` डायरेक्टरी में कॉपी करें
   - आवश्यकता अनुसार नाम बदलें (उदा., `digna`)
   - उदाहरण: `C:\Program Files\Apache Tomcat\webapps\digna`

2. **तैनाती सत्यापित करें**
   - Tomcat प्रबंधन पेज (http://localhost:8080) को रिफ्रेश या रीलोड करें
   - आप "digna" (या आपने जो नाम चुना है) को सूचीबद्ध एप्लीकेशन्स में देखेंगे

3. **डैशबोर्ड एक्सेस करें**
   - अपना ब्राउज़र खोलें
   - `http://localhost:8080/digna` पर जाएँ
   - आपको digna डैशबोर्ड लॉगिन पेज दिखाई देना चाहिए

## digna को Windows सेवा के रूप में चलाना {: #running-digna-as-a-windows-service }

### Windows सेवा क्यों उपयोग करें?

digna बैकएंड को Windows सेवा के रूप में चलाने से यह सुनिश्चित होता है कि यह:
- सर्वर बूट होने पर स्वचालित रूप से शुरू हो जाए
- बैकग्राउंड में खुले Command Prompt के बिना चले
- क्रैश होने पर स्वतः पुनरारंभ हो सके
- Windows Services के माध्यम से प्रबंधित किया जा सके

### `windows` कमांड

सेवा का प्रबंधन स्वयं `digna` executable करता है, `digna windows`
सबकमांड के माध्यम से। कोई बैच फ़ाइल चलाने की आवश्यकता नहीं है।

| कमांड | उद्देश्य |
|---|---|
| `digna windows install` | digna को Windows सेवा के रूप में रजिस्टर करता है |
| `digna windows start` | रजिस्टर की गई सेवा को शुरू करता है |
| `digna windows stop` | चल रही सेवा को रोकता है |
| `digna windows uninstall` | सेवा को अनरजिस्टर करता है |

!!! warning "प्रशासक आवश्यक"

    चारों कमांड Administrator के रूप में खोले गए Command Prompt से चलाए जाने चाहिए।

हर कमांड `--name` लेता है, ताकि गैर-डिफ़ॉल्ट नाम से रजिस्टर की गई सेवा को संबोधित किया जा सके। विकल्पों की पूरी
सूची [CLI संदर्भ](../../../cli/Command_Line_Interface_202611.md) में है।

### सेवा स्थापित करना

1. **Command Prompt को Administrator के रूप में खोलें**
   - Command Prompt पर राइट-क्लिक करें
   - "Run as Administrator" चुनें

2. **अपनी digna इंस्टॉलेशन डायरेक्टरी में नेविगेट करें**
   ```bash
   cd C:\path\to\digna
   ```

3. **सेवा रजिस्टर करें**
   ```bash
   digna windows install
   ```

!!! important "यदि डिफ़ॉल्ट मान उपयुक्त न हों तो पता और पोर्ट निर्दिष्ट करें"

    `install` पता और पोर्ट को सेवा रजिस्ट्रेशन में दर्ज करता है, और सेवा ठीक उसी पर बाइंड होती है जो
    दर्ज किया गया था। डिफ़ॉल्ट मान `127.0.0.1` और `8000` हैं, जो केवल उसी मशीन से कनेक्शन स्वीकार करते
    हैं। किसी अन्य होस्ट पर चल रहा डैशबोर्ड उस तक नहीं पहुँच सकता, इसलिए वह पता दें जिस पर बैकएंड को
    सुनना चाहिए:

    ```bash
    digna windows install --address 0.0.0.0 --port 8082
    ```

    ये मान `config.toml` से नहीं पढ़े जाते। इन्हें बाद में बदलने के लिए सेवा को अनइंस्टॉल करें और
    नए मानों के साथ फिर से इंस्टॉल करें।

सेवा **स्वचालित स्टार्टअप** के साथ रजिस्टर होती है, इसलिए यह Windows के साथ शुरू होगी। यह तुरंत
शुरू नहीं होती — अगला अनुभाग देखें।

#### इंस्टॉल विकल्प

| विकल्प | डिफ़ॉल्ट | उद्देश्य |
|---|---|---|
| `--name` | `digna` | वह नाम जिससे सेवा रजिस्टर की जाती है |
| `--display-name` | `digna` | services.msc में दिखाया जाने वाला नाम |
| `--description` | `digna data quality backend` | services.msc में दिखाया जाने वाला विवरण |
| `--address` | `127.0.0.1` | वह पता जिस पर सेवा अपना API बाइंड करती है |
| `--port` | `8000` | वह पोर्ट जिस पर सेवा अपना API बाइंड करती है |
| `--working-dir` | `digna` executable की डायरेक्टरी | `config.toml` और `license.toml` वाली डायरेक्टरी, जिसे सेवा अपनी वर्किंग डायरेक्टरी बनाती है |
| `--start-type` | `auto` | `auto` Windows के साथ शुरू होती है, `manual` केवल कहने पर शुरू होती है, `disabled` सेवा को रजिस्टर करती है पर उसे शुरू होने नहीं देती |
| `--account` | `LocalSystem` | वह खाता जिसके रूप में चलाना है, उदा. `DOMAIN\user` या `.\user` |
| `--password` | | `--account` का पासवर्ड |

!!! tip "डोमेन खाते के अंतर्गत चलाना"

    `LocalSystem` की कोई नेटवर्क पहचान नहीं होती, इसलिए SQL Server के विरुद्ध Windows Authentication और
    किसी नेटवर्क शेयर तक कोई भी पहुँच विफल होगी। जहाँ सेवा को किसी विशिष्ट उपयोगकर्ता के रूप में संसाधनों तक
    पहुँचना हो, वहाँ `--account` और `--password` के साथ इंस्टॉल करें।

### सेवा शुरू करना और रोकना

#### सेवा शुरू करने के लिए

```bash
digna windows start
```

#### सेवा रोकने के लिए

```bash
digna windows stop
```

!!! tip "सुझाव"

    आवेदन फ़ाइलों को अपडेट करने से पहले हमेशा सेवा को रोकें।

### सेवा को नई डायरेक्टरी में ले जाना

यदि आपको digna इंस्टॉलेशन को स्थानांतरित करने की आवश्यकता है:

1. **वर्तमान सेवा को रोकें और अनरजिस्टर करें**
   ```bash
   cd C:\old\path\digna
   digna windows stop
   digna windows uninstall
   ```

2. **एप्लिकेशन फाइलें स्थानांतरित करें**
   - पूरी digna इंस्टॉलेशन फ़ोल्डर को नई लोकेशन पर ले जाएँ

3. **नई लोकेशन से सेवा को फिर से रजिस्टर करें**
   ```bash
   cd C:\new\path\digna
   digna windows install
   ```

   पहली बार उपयोग किए गए कोई भी `--address`, `--port` या `--account` मान दोहराएँ — पिछला
   रजिस्ट्रेशन हट चुका है।

4. **सेवा शुरू करें**
   ```bash
   digna windows start
   ```

### सेवा अनइंस्टॉल करना

1. **चलती सेवा को रोकें**
   ```bash
   cd C:\path\to\digna
   digna windows stop
   ```

2. **सेवा अनरजिस्टर करें**
   ```bash
   digna windows uninstall
   ```

अब digna सर्वर Windows सेवा के रूप में अनरजिस्टर हो चुका है।

## नई रिलीज़ में उन्नयन {: #upgrading-to-a-new-release }

यह सेक्शन रिलीज़ 2026.06 के इंस्टॉलेशन को रिलीज़ 2026.11 में अपग्रेड करता है। यदि आपका
इंस्टॉलेशन इससे पुराना है, तो पहले [रिलीज़ 2026.06 से पहले की रिलीज़ से अपग्रेड करना](#upgrading-from-a-release-before-2026-06)
पढ़ें।

### अपग्रेड करने से पहले

**digna रिपॉज़िटरी का बैकअप बनाना अनिवार्य है**

digna को अपग्रेड करने से पहले अपने रिपॉज़िटरी (PostgreSQL) का बैकअप लें ताकि डेटा लॉस से बचा जा सके।
बैकअप यह सुनिश्चित करता है कि यदि अपग्रेड के दौरान अनपेक्षित समस्याएँ आयीं तो आप रिकवर कर सकें।

**रिलीज़ 2026.11 के लिए लाइसेंस फ़ाइल का अनुरोध करना**

रिलीज़ 2026.11 को एक नई `license.toml` की आवश्यकता है। शुरू करने से पहले digna टीम से इसका अनुरोध करें, और
इसे [चरण 7](#step-7-replace-the-license-file) के लिए तैयार रखें।

### रिलीज़ 2026.06 से पहले की रिलीज़ से अपग्रेड करना {: #upgrading-from-a-release-before-2026-06 }

रिलीज़ 2026.06 तीन ऐसे बदलाव लाई थी जो तब भी लागू होते हैं जब आप किसी पुराने इंस्टॉलेशन को सीधे
2026.11 में अपग्रेड करते हैं:

- **केवल ODBC।** digna हर स्रोत तकनीक तक ODBC के माध्यम से पहुँचता है। हर वह डेटाबेस कनेक्शन जो अभी
  ODBC का उपयोग नहीं करता, अपग्रेड के बाद ODBC में बदलना होगा; कोई स्वचालित रूपांतरण नहीं है। ODBC
  ड्राइवर पहले से digna होस्ट पर संस्थापित करें, देखें
  [digna होस्ट पर ODBC ड्राइवर संस्थापित करना](../../../databases/overview.md#install-the-driver),
  और हर कनेक्शन के गुण
  [तकनीक-वार मार्गदर्शिकाओं](../../../databases/overview.md#technology-guides) से तैयार रखें। Databricks Legacy
  कनेक्टर अब मौजूद नहीं है; उन कनेक्शनों को
  [Databricks](../../../databases/databricks_connector_guide.md) कनेक्टर पर ले जाएँ।
- **एक ही executable।** `dignabackend` और `dignacli` की जगह एकल `digna` executable ले लेती है,
  जो बैकएंड और CLI को जोड़ती है।
- **config.toml।** `[encryption]` सेक्शन आवश्यक है, और `DIGNA_APP_HOST` तथा
  `DIGNA_APP_PORT` अब नहीं पढ़े जाते: सर्वर अपना पता और पोर्ट `digna serve` से लेता है।
  अपनी फ़ाइल की तुलना [बैकएंड कॉन्फ़िगरेशन](#backend-configuration) से करें।

नीचे दिए गए चरण बताते हैं कि किसी पुराने इंस्टॉलेशन में कहाँ कुछ अलग करना होता है। चरण 8 का रिपॉज़िटरी
अपग्रेड किसी भी पिछली रिलीज़ की रिपॉज़िटरी को सीधे 2026.11 तक ले आता है।

### अपग्रेड प्रक्रिया

#### चरण 1: digna सेवा बंद करें {: #step-1-stop-the-digna-service }

एडमिनिस्ट्रेटर के रूप में Command Prompt खोलें और अपने वर्तमान इंस्टॉलेशन की `digna` executable से
सेवा बंद करें:

```bash
cd C:\path\to\digna
digna windows stop
```

सेवा रजिस्टर्ड रहती है। नई executable उसी डायरेक्टरी में पुरानी की जगह लेती है, इसलिए रजिस्ट्रेशन
सही फ़ाइल की ओर इंगित करता रहता है।

यदि digna फ़ोरग्राउंड में चल रहा है, तो उसकी Command Prompt विंडो में ++ctrl+c++ दबाएँ।

!!! warning "रिलीज़ 2026.06 से पहले की रिलीज़ से अपग्रेड करना"

    रिलीज़ 2026.06 से पहले की रिलीज़ सेवा को बैच फ़ाइलों से रजिस्टर करती थीं। चरण 2 में किसी भी चीज़ का
    नाम बदलने से **पहले**, अपने वर्तमान इंस्टॉलेशन की बैच फ़ाइलों से सेवा को बंद और अनरजिस्टर करें:

    ```bash
    cd C:\path\to\digna\bin
    stop_service.bat
    uninstall_service.bat
    ```

    वह खाता नोट कर लें जिसके अंतर्गत सेवा चलती थी, और वह पता और पोर्ट जिस पर वह सेवा देती थी। आप
    चरण 9 में सेवा को फिर से रजिस्टर करेंगे।

#### चरण 2: वर्तमान इंस्टॉलेशन का बैकअप लें {: #step-2-backup-current-installation }

अपनी digna इंस्टॉलेशन डायरेक्टरी में वर्तमान इंस्टॉलेशन की executable और डैशबोर्ड फ़ोल्डर के नाम बदलें,
ताकि नई रिलीज़ उनके साथ डिप्लॉय की जा सके:

```bash
cd C:\path\to\digna
ren digna.exe digna_old.exe
ren dashboard dashboard_old
```

`digna_old.exe` को तब तक रखें जब तक आप अपग्रेड की पुष्टि न कर लें, और `dashboard_old` को तब तक जब तक आप उससे
अपनी कॉन्फ़िगरेशन फ़ाइलें पुनर्स्थापित न कर लें (चरण 4 देखें)। उसके बाद आप दोनों को हटा सकते हैं।

!!! info "रिलीज़ 2026.06 से पहले की रिलीज़ से अपग्रेड करना"

    executable के बजाय `dignabackend` और `dignacli` फ़ोल्डरों के नाम बदलें:
    `ren dignabackend dignabackend_old` और `ren dignacli dignacli_old`। रिलीज़ 2026.11 न तो इनमें से किसी फ़ोल्डर का उपयोग करती है, न ही बैच फ़ाइलों वाले `bin` फ़ोल्डर का।

#### चरण 3: नया वर्शन निकालें और डिप्लॉय करें {: #step-3-extract-and-deploy-new-version }

1. नई digna इंस्टॉलेशन ZIP फ़ाइल निकालें
2. नई `digna` executable और `dashboard` फ़ोल्डर को अपनी इंस्टॉलेशन डायरेक्टरी में कॉपी करें

!!! warning "महत्वपूर्ण"

    न तो `config.toml` और न ही `dashboard/dashboard_config.toml` कभी भी
    इंस्टॉलेशन ZIP में शामिल की जाती है — digna टीम इनमें से कोई भी फ़ाइल कभी नहीं भेजती। इसलिए अपग्रेड से
    आपकी मौजूदा कॉन्फ़िगरेशन अप्रभावित रहती है, और नाम बदले गए `*_old` फ़ोल्डरों में मौजूद प्रतियाँ ही
    आपके पास एकमात्र प्रतियाँ हैं।

#### चरण 4: अपनी कॉन्फ़िगरेशन फ़ाइलें पुनर्स्थापित करें {: #step-4-restore-your-configuration-files }

```bash
copy dashboard_old\dashboard_config.toml dashboard\dashboard_config.toml
```

रिलीज़ 2026.11 को `config.toml` में किसी बदलाव की आवश्यकता नहीं है: जो फ़ाइल रिलीज़ 2026.06 के साथ काम करती है,
वह काम करती रहती है। दो बदलाव वैकल्पिक हैं:

- यदि डेटाबेस कनेक्शनों को digna Engine का उपयोग करना है और उसके डिफ़ॉल्ट आपके होस्ट के अनुकूल नहीं हैं, तो
  एक [`[duckdb]` सेक्शन](#duckdb-section) जोड़ें।
- यदि कोई रिवर्स प्रॉक्सी डैशबोर्ड और बैकएंड को एक ही origin के अंतर्गत सर्व करता है, तो `[app]` सेक्शन
  छोड़ दें।

!!! warning "वे सेटिंग्स जिन्हें digna नहीं पढ़ता"

    इस गाइड के पुराने संस्करणों में कुछ ऐसी सेटिंग्स दिखाई गई थीं जिन्हें digna नहीं पढ़ता। उनका कोई
    प्रभाव नहीं होता, और चरण 6 में `config check` उन्हें **Unknown keys** के अंतर्गत सूचीबद्ध करता है। उन्हें
    हटाएँ या ठीक करें:

    - `DIGNA_SCHEDULER_MAX_DELAY`, `DIGNA_CLEANUP_TIME`, `digna_COOKIE_PATH`,
      `digna_COOKIE_SAME_SITE`, `digna_APP_CORS_ALLOW_METHODS`, `digna_APP_CORS_ALLOW_HEADERS` और
      `digna_LOGGING_BACKUP_COUNT` मौजूद नहीं हैं। उन्हें हटाएँ।
    - सेटिंग के नाम केस-संवेदी हैं। digna `DIGNA_REPO_HOST` पढ़ता है, `digna_REPO_HOST` नहीं।
      हर नाम बड़े अक्षरों में लिखें, जैसा [बैकएंड कॉन्फ़िगरेशन](#backend-configuration) में है।

!!! warning "सिंगल साइन-ऑन: [[oidc_clients]] बनाए रखें"

    digna सिंगल साइन-ऑन प्रदाताओं को `[[oidc_clients]]` प्रविष्टियों की सूची के रूप में पढ़ता है, जिनमें से
    हर एक का अपना `DIGNA_OIDC_KEY` होता है। यदि आपने अपने प्रदाताओं को `[oidc_clients.<key>]` सेक्शनों में
    बदल दिया था, जैसा इस गाइड के एक पुराने संस्करण में दिखाया गया था, तो उन्हें वापस बदलें। जब तक वह रूप
    बना रहता है, `config check` `OIDC config(s)` को FAILED बताता है:

    ```toml
    [[oidc_clients]]
    DIGNA_OIDC_KEY = 'microsoft'
    DIGNA_OIDC_CLIENT_ID = '<client_id>'
    DIGNA_OIDC_CLIENT_SECRET = '<client_secret>'
    DIGNA_OIDC_REDIRECT_URI = 'http://localhost:3000/oidc/callback'
    DIGNA_OIDC_CONFIGURATION_URL = 'https://login.microsoftonline.com/<tenant_id>/v2.0/.well-known/openid-configuration'
    ```

    हर प्रदाता के लिए प्रविष्टि दोहराएँ, और हर `DIGNA_OIDC_KEY` को `dashboard_config.toml` की `key` के समान
    रखें। यह केवल उन इंस्टॉलेशनों को प्रभावित करता है जो सिंगल साइन-ऑन का उपयोग करते हैं।

#### चरण 5: वेब सर्वर रीलोड करें {: #step-5-reload-the-web-server }

डैशबोर्ड स्टैटिक फ़ाइलों का एक सेट है, इसलिए आपका वेब सर्वर — और ब्राउज़र — अभी भी
पिछला वर्शन दिखा सकते हैं। जो भी वेब सर्वर `dashboard` फ़ोल्डर को होस्ट करता है, उसे रीलोड या रीस्टार्ट करें,
फिर हार्ड रिफ़्रेश (++ctrl+f5++) के साथ पेज रीलोड करें।

#### चरण 6: कॉन्फ़िगरेशन जाँचें {: #step-6-validate-the-configuration }

रिपॉज़िटरी को छूने से पहले पुष्टि करें कि `config.toml` पूर्ण है:

```bash
digna config check
```

प्रत्येक सेक्शन को OK बताना चाहिए। जो कुछ भी FAILED बताया जाए उसे ठीक करें, **Unknown keys** के अंतर्गत
सूचीबद्ध कुंजियाँ हटाएँ, और आगे बढ़ने से पहले कमांड फिर चलाएँ।

#### चरण 7: लाइसेंस फ़ाइल बदलें {: #step-7-replace-the-license-file }

सामान्यतः लाइसेंस फ़ाइल एक रिलीज़ से अगली रिलीज़ में भी काम करती रहती है। रिलीज़ 2026.11 इसका अपवाद है: यह
दो लाइसेंस वाले मॉड्यूल जोड़ती है, digna Data Reconciliation और digna Agentic, और 2026.11 से पहले जारी किए गए
लाइसेंस में ये शामिल नहीं हैं। digna टीम द्वारा रिलीज़ 2026.11 के लिए दी गई `license.toml` को
इंस्टॉलेशन डायरेक्टरी में कॉपी करें, जिससे पुरानी फ़ाइल बदल जाए:

```bash
copy /Y C:\path\to\new\license.toml license.toml
```

!!! warning "पिछला लाइसेंस न रखें"

    पिछले लाइसेंस के साथ digna फिर भी शुरू होता है, लेकिन digna Data Reconciliation और digna
    MCP Server बंद रहते हैं। लाइसेंस की जाँच करने वाला हर कमांड — `user`,
    `inspection`, `repo` — जाँच विफल होने पर रिपॉज़िटरी को छूने से पहले ही रुक जाता है। आगे बढ़ने से
    पहले नए लाइसेंस को सत्यापित करें:

    ```bash
    digna license check
    ```

#### चरण 8: रिपॉज़िटरी स्कीमा अपग्रेड करें {: #step-8-upgrade-the-repository-schema }

अपनी digna इंस्टॉलेशन डायरेक्टरी में चलाएँ:

```bash
digna repo upgrade
```

रिलीज़ 2026.11 रिपॉज़िटरी स्कीमा को संस्करणबद्ध माइग्रेशनों से प्रबंधित करती है। किसी पिछली रिलीज़ से पहला
अपग्रेड स्कीमा को पिछली पद्धति के अंतिम संस्करण तक लाता है, उसे अपने प्रारंभिक बिंदु के रूप में दर्ज करता है,
और फिर रिलीज़ 2026.11 के माइग्रेशन लागू करता है। यह इस संदेश के साथ समाप्त होता है:

```text
✅ Baseline migration recorded as applied.
✅ Repo schema 'dignarepo' is up to date.
```

सभी मौजूदा डेटा संरक्षित रहता है। किसी भी समय रिपॉज़िटरी की स्थिति देखने के लिए
`digna repo check` चलाएँ: यह अंतिम लागू माइग्रेशन और कोई भी लंबित माइग्रेशन सूचीबद्ध करता है।

!!! warning "पुरानी रिपॉज़िटरी पर digna शुरू नहीं होता"

    रिलीज़ 2026.11 से, जब तक रिपॉज़िटरी को अपग्रेड की आवश्यकता है, सर्वर शुरू होने से इनकार करता है और
    इसकी सूचना देता है, उदाहरण के लिए:

    ```text
    Error: Legacy repo version 3.0.2 installed. Use the 'digna repo upgrade' command to upgrade it.
    ```

    सर्वर या सेवा शुरू करने से पहले `repo upgrade` चलाएँ।

#### चरण 9: सेवाएँ पुनः प्रारंभ करें {: #step-9-restart-services }

यदि digna Windows सेवा के रूप में चलता है, तो उसे फिर से शुरू करें:

```bash
cd C:\path\to\digna
digna windows start
```

यदि आपने रिलीज़ 2026.06 से पहले की रिलीज़ से अपग्रेड किया है और चरण 1 में सेवा को अनरजिस्टर किया था, तो
पहले उसे `digna` executable से फिर से रजिस्टर करें:

```bash
cd C:\path\to\digna
digna windows install --address <address> --port <port>
digna windows start
```

`--address` और `--port` को वही मान दें जिन पर पुरानी सेवा चलती थी, जब तक कि आप डिफ़ॉल्ट
`127.0.0.1` और `8000` नहीं चाहते। यदि पुरानी सेवा किसी डोमेन खाते के अंतर्गत चलती थी, तो `--account` और
`--password` जोड़ें। विकल्पों की पूरी सूची के लिए
[digna को Windows सेवा के रूप में चलाना](#running-digna-as-a-windows-service) देखें।

यदि आप मैन्युअली चला रहे हैं, तो सर्वर को फिर से शुरू करें:

```bash
cd C:\path\to\digna
digna serve --address <address> --port <port>
```

यदि आप IIS या Tomcat का उपयोग कर रहे हैं, तो संबंधित वेब सर्वर को पुनरारंभ करें।

#### चरण 10: अपग्रेड सत्यापित करें {: #step-10-verify-the-upgrade }

1. नई executable की रिलीज़ की पुष्टि करें:

    ```bash
    digna version
    ```

    पहली पंक्ति में `Release: 2026.11` होना चाहिए।

2. digna डैशबोर्ड एक्सेस करें और सुनिश्चित करें कि इंटरफ़ेस सही ढंग से लोड हो रहा है।
3. त्रुटियों के लिए इंस्टॉलेशन की `logs` डायरेक्टरी की फ़ाइलें जाँचें।
4. अपने डेटाबेस कनेक्शनों का परीक्षण करें — देखें
   [कनेक्शन का परीक्षण](../../../databases/overview.md#testing-a-connection)। रिलीज़ 2026.06 से पहले की रिलीज़
   से अपग्रेड के बाद, पहले हर उस कनेक्शन को ODBC में बदलें जो अभी तक ODBC का उपयोग नहीं करता था।

नए मॉड्यूल के साथ शुरुआत करने के लिए देखें [digna Data Reconciliation](../../../platform/data_reconciliation/Introduction.md),
digna MCP Server के लिए [AI एजेंट कनेक्ट करना](../../../platform/agentic/connect_ai_agent.md), और
digna Engine के लिए [प्रोफाइलिंग लोकेशन](../../../platform/profiling/profiling_location.md)।
