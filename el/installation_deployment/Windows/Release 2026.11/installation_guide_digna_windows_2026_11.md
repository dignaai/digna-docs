## Εισαγωγή {: #introduction }

### Σχετικά με το digna

Το digna είναι μια ολοκληρωμένη πλατφόρμα με AI που έχει σχεδιαστεί για να βελτιστοποιεί τη διαχείριση ποιότητας δεδομένων σε διάφορα περιβάλλοντα δεδομένων όπως warehouses, lakes και lakehouses. Χτισμένο για υψηλή κλιμάκωση και προσαρμοστικότητα, το digna αντιμετωπίζει τις σύγχρονες προκλήσεις δεδομένων μέσω αυτοματισμού, παρακολούθησης σε πραγματικό χρόνο και ανίχνευσης ανωμαλιών.

Το digna αποτελείται από δύο κύρια συστατικά:

- **digna**: ο πυρήνας της εφαρμογής, υπεύθυνος για την επεξεργασία δεδομένων και την εκτέλεση ελέγχων ποιότητας. Ενοποιεί το backend και τη διεπαφή γραμμής εντολών σε ένα μόνο εκτελέσιμο αρχείο, αντικαθιστώντας τα ξεχωριστά προγράμματα `dignabackend` και `dignacli` των προηγούμενων εκδόσεων.
- **dignadashboard**: Μια web διεπαφή που φιλοξενείται σε web server, παρέχοντας έναν φιλικό τρόπο αλληλεπίδρασης με την πλατφόρμα digna και οπτικοποίησης μετρικών ποιότητας δεδομένων.

### Τι νέο υπάρχει στην Έκδοση 2026.11

Αυτή η έκδοση προσθέτει το digna Data Reconciliation, το digna Agentic με τον digna MCP Server και το digna Engine, το οποίο μπορεί να κάνει profiling δεδομένων μέσα στο digna και να ελέγχει την ακεραιότητα αναφορών μεταξύ διαφορετικών τεχνολογιών βάσεων δεδομένων. Δείτε τις [σημειώσεις έκδοσης](../../../changelog/Release_202611.md) για πλήρεις λεπτομέρειες.

Για μια εγκατάσταση, η έκδοση φέρνει έναν νέο μηχανισμό migrations για το repository, μια προαιρετική ενότητα `[duckdb]` στο `config.toml` για το digna Engine και ένα νέο αρχείο άδειας. Η [ενότητα αναβάθμισης](#upgrading-to-a-new-release) καλύπτει καθένα από αυτά.

### Ψάχνετε για macOS ή Linux;

Αυτός ο οδηγός καλύπτει τα Windows. Για άλλες πλατφόρμες, δείτε τον [Οδηγό Εγκατάστασης για macOS](../../macOS/Release%202026.11/installation_guide_digna_macos_2026_11.md) ή τον [Οδηγό Εγκατάστασης για Linux](../../Linux/Release%202026.11/installation_guide_digna_linux_2026_11.md).

## Απαιτήσεις Συστήματος {: #system-requirements }

Πριν ξεκινήσετε την εγκατάσταση, βεβαιωθείτε ότι το σύστημά σας πληροί τις παρακάτω ελάχιστες απαιτήσεις:

| Απαίτηση | Προδιαγραφή |
|---|---|
| **Λειτουργικό Σύστημα** | Windows Server ή Windows 10/11 |
| **Μνήμη (Ελάχιστη Εγκατάσταση)** | 16 GB RAM |
| **Χώρος Δίσκου** | 10 GB διαθέσιμου χώρου |
| **Βάση Δεδομένων** | PostgreSQL Server 12 ή νεότερο |
| **Web Server** | IIS, Apache Tomcat, ή αντίστοιχο |

!!! info "digna Engine"

    Για τις συνδέσεις βάσεων δεδομένων που χρησιμοποιούν το digna Engine ως τοποθεσία profiling, το profiling εκτελείται στον ίδιο τον host του digna. Προβλέψτε επιπλέον μνήμη και χώρο στον δίσκο για αυτές, δείτε την [ενότητα \[duckdb\]](#duckdb-section).

### Επιλογές Εγκατάστασης Βάσης Δεδομένων

**Αν το PostgreSQL είναι ήδη εγκατεστημένο:**
Μπορείτε να προσθέσετε μια νέα βάση δεδομένων για το digna στον υπάρχοντα PostgreSQL Server.

**Αν θα εγκαταστήσετε το PostgreSQL στο ίδιο μηχάνημα με το digna:**

!!! info "Συνιστώμενες Προδιαγραφές"

    - **Μνήμη**: 32 GB RAM (αντί για 16 GB)
    - **Χώρος Δίσκου**: 50 GB διαθέσιμος χώρος (αντί για 10 GB)

    Αυτές οι υψηλότερες προδιαγραφές υποστηρίζουν τόσο το digna όσο και τη βάση δεδομένων PostgreSQL που τρέχουν ταυτόχρονα.

## Διαμόρφωση PostgreSQL Server {: #postgresql-server-setup }

### Αν έχετε ήδη PostgreSQL

Αν το PostgreSQL είναι ήδη εγκατεστημένο και λειτουργεί τοπικά ή χρησιμοποιείτε διαχειριζόμενο απομακρυσμένο PostgreSQL server, μπορείτε να μεταβείτε στην [επόμενη ενότητα](#web-server-configuration).

### Εγκατάσταση PostgreSQL

Ακολουθήστε αυτά τα βήματα για να εγκαταστήσετε το PostgreSQL σε Windows:

#### Βήμα 1: Κατεβάστε το PostgreSQL

1. Επισκεφτείτε τη σελίδα [PostgreSQL Downloads](https://www.postgresql.org/download/)
2. Επιλέξτε **Windows**
3. Κατεβάστε τον πιο πρόσφατο installer

#### Βήμα 2: Εκτελέστε τον Installer

1. Κάντε διπλό κλικ στο αρχείο installer που κατεβάσατε
2. Ακολουθήστε τα βήματα του οδηγού εγκατάστασης

#### Βήμα 3: Επιλογή Καταλόγου Εγκατάστασης

Επιλέξτε τον κατάλογο όπου θα εγκατασταθεί το PostgreSQL. Η προεπιλεγμένη τοποθεσία είναι συνήθως κατάλληλη.

#### Βήμα 4: Επιλογή Στοιχείων Εγκατάστασης

Για μία τυπική εγκατάσταση, κρατήστε τις προεπιλεγμένες επιλογές των συστατικών.

#### Βήμα 5: Ορισμός Κωδικού του Superuser του PostgreSQL

Εισάγετε και επιβεβαιώστε έναν κωδικό για τον superuser του PostgreSQL (`postgres`). **Αποθηκεύστε αυτόν τον κωδικό με ασφάλεια** — θα τον χρειαστείτε αργότερα.

#### Βήμα 6: Διαμόρφωση Αριθμού Θύρας

Η προεπιλεγμένη θύρα του PostgreSQL είναι `5432`. Μπορείτε να χρησιμοποιήσετε την προεπιλογή ή να ορίσετε άλλη θύρα εάν χρειάζεται.

!!! tip "Συμβουλή"

    Αν η θύρα 5432 χρησιμοποιείται ήδη, επιλέξτε μια εναλλακτική θύρα και σημειώστε την για μελλοντικές ρυθμίσεις.

#### Βήμα 7: Επιλογή Locale

Επιλέξτε το locale για τη βάση δεδομένων σας. Η προεπιλογή είναι συνήθως κατάλληλη για τις περισσότερες εγκαταστάσεις.

#### Βήμα 8: Ολοκλήρωση Εγκατάστασης

Κάντε κλικ στο **Next** για τα υπόλοιπα βήματα και τέλος **Finish**.

#### Βήμα 9: Επαλήθευση Εγκατάστασης

Ανοίξτε το Command Prompt και επαληθεύστε ότι το PostgreSQL είναι εγκατεστημένο:

```bash
psql --version
```

Θα δείτε την έκδοση του PostgreSQL αν η εγκατάσταση ήταν επιτυχής.

## Διαμόρφωση Web Server {: #web-server-configuration }

Το digna απαιτεί έναν web server για να φιλοξενήσει το dashboard. Επιλέξτε μία από τις ακόλουθες επιλογές:

- [Internet Information Services (IIS)](#iis-setup)
- [Apache Tomcat](#apache-tomcat-setup)

Χρειάζεται να εγκαταστήσετε και να ρυθμίσετε **έναν** μόνο από αυτούς τους servers.

### Ρύθμιση IIS {: #iis-setup }

#### Επισκόπηση

Το Internet Information Services (IIS) είναι ο web server της Microsoft για τη φιλοξενία ιστοτόπων και web εφαρμογών.

#### Ενεργοποίηση IIS

1. **Άνοιγμα Πίνακα Ελέγχου**
   - Πατήστε `Win + R`
   - Πληκτρολογήστε `control` και πατήστε Enter

2. **Μετάβαση σε Windows Features**
   - Κάντε κλικ στο **Programs**
   - Επιλέξτε **Turn Windows features on or off**

3. **Ενεργοποίηση Internet Information Services**
   - Κάντε κύλιση και βρείτε **Internet Information Services (IIS)**
   - Επιλέξτε το checkbox για να το ενεργοποιήσετε
   - Κάντε κλικ στο **+** για να επεκτείνετε και επαληθεύστε ότι έχουν επιλεγεί τα εξαρτήματα:
     - **Web Management Tools**
     - **World Wide Web Services**

4. **Κλικ στο OK** για να εφαρμοστούν οι αλλαγές

5. **Επαλήθευση Εγκατάστασης IIS**
   - Ανοίξτε τον browser σας
   - Μεταβείτε στο `http://localhost`
   - Πρέπει να δείτε τη σελίδα καλωσορίσματος του IIS

#### Απαιτείται: URL Rewrite Module

Το IIS χρειάζεται το component URL Rewrite. Κατεβάστε και εγκαταστήστε το από τη [επίσημη σελίδα της Microsoft](https://www.iis.net/downloads/microsoft/url-rewrite).

#### Απαιτείται: MIME Type για Αρχεία Markdown

Για να διασφαλίσετε ότι τα αρχεία Markdown (`.md`) σερβίρονται σωστά από το IIS:

1. Ανοίξτε το **IIS Manager** (πατήστε `Win + R`, πληκτρολογήστε `inetmgr`, πατήστε Enter)
2. Πλοηγηθείτε στο **Your Site > MIME Types**
3. Κάντε κλικ στο **Add...**
4. Διαμορφώστε:
   - **File name extension**: `.md`
   - **MIME type**: `text/markdown`

!!! warning "Σημαντικό"

    Χωρίς αυτήν τη ρύθμιση, τα αρχεία `.md` ενδέχεται να μην σερβίρονται σωστά.

### Ρύθμιση Apache Tomcat {: #apache-tomcat-setup }

#### Επισκόπηση

Το Apache Tomcat είναι ένας open-source servlet container και web server Java.

#### Εγκατάσταση

1. **Κατεβάστε το Apache Tomcat**
   - Επισκεφτείτε [Apache Tomcat Downloads](https://tomcat.apache.org/download-90.cgi)
   - Κατεβάστε τη διανομή ZIP για Windows

2. **Αποσυμπιέστε το αρχειο**
   - Αποσυμπιέστε το ZIP σε έναν κατάλογο στο σύστημά σας
   - Παράδειγμα: `C:\Program Files\Apache Tomcat`

3. **Επαληθεύστε ότι το Tomcat τρέχει**
   - Ανοίξτε τον browser σας
   - Μεταβείτε στο `http://localhost:8080`
   - Πρέπει να δείτε τη σελίδα καλωσορίσματος του Apache Tomcat

!!! tip "Συμβουλή"

    Το Apache Tomcat συνήθως ξεκινά αυτόματα μετά την εγκατάσταση. Αν δεν ξεκίνησε, πλοηγηθείτε στο φάκελο `bin` και τρέξτε `startup.bat`.

## Αρχική Εγκατάσταση {: #initial-installation }

### Βήμα 1: Ρύθμιση του Repository του digna

Το repository του digna αποθηκεύει όλες τις μετρικές που υπολογίζει το digna. Λειτουργεί ως κεντρική βάση δεδομένων για αναλυτικά και δεδομένα απόδοσης.

#### Δημιουργία Schema και Χρήστη για το Repository

Ανοίξτε τον PostgreSQL client σας (pgAdmin, psql ή παρόμοιο) και εκτελέστε τις ακόλουθες εντολές SQL:

```sql
CREATE SCHEMA <digna_repo_schema>;

CREATE USER <digna_repo_user> WITH PASSWORD '<digna_repo_password>';

GRANT ALL PRIVILEGES ON SCHEMA <digna_repo_schema> TO <digna_repo_user>;
```

**Αντικαταστήστε τα παρακάτω placeholders:**

- `<digna_repo_schema>` — Το όνομα του schema που επιθυμείτε (π.χ., `dignarepo`)
- `<digna_repo_user>` — Το όνομα χρήστη που επιθυμείτε (π.χ., `digna_user`)
- `<digna_repo_password>` — Ένας ασφαλής κωδικός για αυτόν τον χρήστη

**Παράδειγμα:**

```sql
CREATE SCHEMA dignarepo;

CREATE USER digna_user WITH PASSWORD 'YourSecurePassword123!';

GRANT ALL PRIVILEGES ON SCHEMA dignarepo TO digna_user;
```

!!! tip "Καλύτερη Πρακτική"

    Χρησιμοποιήστε ισχυρούς, πολύπλοκους κωδικούς για τους χρήστες της βάσης δεδομένων. Αποφύγετε εύκολα μαντεύσιμες διαπιστεύσεις.

---

### Βήμα 2: Εξαγωγή του Πακέτου Εγκατάστασης του digna

1. Εντοπίστε το αρχείο ZIP εγκατάστασης του digna που σας παρασχέθηκε
2. Εξαγάγετέ το στην επιθυμητή τοποθεσία εγκατάστασης
3. Μετά την εξαγωγή, θα δείτε τα εξής στοιχεία:
   - `dashboard/` — Web διεπαφή dashboard
   - `digna` — Κύριο εκτελέσιμο (backend + CLI σε ένα)

!!! info "Τα αρχεία διαμόρφωσης και άδειας δεν περιλαμβάνονται στο πακέτο"

    Ούτε το `config.toml` ούτε το `dashboard/dashboard_config.toml` παρέχονται με την εγκατάσταση — τα δημιουργείτε και τα δύο εσείς, στις ενότητες [Διαμόρφωση Backend](#backend-configuration) και [Διαμόρφωση Dashboard](#dashboard-configuration). Ούτε το `license.toml` παρέχεται με το πακέτο· η digna το παρέχει ξεχωριστά, όπως περιγράφεται στο Βήμα 3.

### Βήμα 3: Εγκατάσταση του Αρχείου Άδειας

!!! warning "Σημαντικό"

    Το αρχείο άδειας **δεν** περιλαμβάνεται στο πακέτο εγκατάστασης και θα σας παρασχεθεί χωριστά από την digna.

1. Εντοπίστε το αρχείο `license.toml` που σας παρασχέθηκε
2. Αντιγράψτε το στον ριζικό κατάλογο εγκατάστασης του digna (όπου βρίσκονται το `config.toml` και το εκτελέσιμο `digna`)

**Γιατί είναι σημαντικό:**
Το αρχείο άδειας περιέχει τις πληροφορίες πελάτη, την ημερομηνία λήξης της άδειας και την ψηφιακή υπογραφή. **Μην τροποποιήσετε αυτό το αρχείο** — οποιαδήποτε αλλαγή θα το ακυρώσει.

**Δομή καταλόγων μετά τη ρύθμιση:**

```
digna_installation/
├── config.toml         (configuration file)
├── license.toml        (YOUR LICENSE FILE - copy here)
├── digna               (main executable)
└── dashboard/          (web interface)
    └── (dashboard files)
```

## Διαμόρφωση Backend {: #backend-configuration }

### Βήμα 1: Δημιουργία και Επεξεργασία του Αρχείου Διαμόρφωσης

Το αρχείο `config_template.toml` παρέχεται στον κατάλογο εγκατάστασης του digna. Απλώς μετονομάστε το σε `config.toml`.

**Τοποθεσία:** `digna_installation/config.toml`

Ανοίξτε το `config.toml` σε έναν επεξεργαστή κειμένου και διαμορφώστε κάθε ενότητα όπως παρακάτω.

#### Ενότητα [app]

Αυτή η ενότητα διαμορφώνει την κοινή χρήση πόρων μεταξύ διαφορετικών origins (CORS) ανάμεσα στο dashboard και το backend:

```toml
[app]
DIGNA_APP_CORS_ALLOW_ORIGINS = ["http://localhost:5173"]
DIGNA_APP_CORS_ALLOW_CREDENTIALS = true
```

| Παράμετρος | Τιμή | Σημειώσεις |
|---|---|---|
| `DIGNA_APP_CORS_ALLOW_ORIGINS` | URL του dashboard | Τα URL από τα οποία σερβίρεται το dashboard. Αιτήματα του browser από οποιοδήποτε άλλο origin απορρίπτονται |
| `DIGNA_APP_CORS_ALLOW_CREDENTIALS` | `true` | Απαραίτητο, ώστε ο browser να στέλνει το cookie συνεδρίας με κάθε αίτημα |

!!! info "Η ενότητα [app] είναι προαιρετική"

    Από την Έκδοση 2026.11, και τα δύο κλειδιά, καθώς και ολόκληρη η ενότητα `[app]`, μπορούν να παραλειφθούν. Αυτή είναι η σωστή ρύθμιση όταν ένας reverse proxy σερβίρει το dashboard και το backend κάτω από ένα origin: ο browser τότε δεν κάνει αιτήματα μεταξύ διαφορετικών origins, και από προεπιλογή δεν επιτρέπεται κανένα.

#### Ενότητα [repo]

Αυτή η ενότητα διαμορφώνει τη σύνδεση με τη βάση δεδομένων PostgreSQL:

```toml
[repo]
DIGNA_REPO_HOST = "localhost"
DIGNA_REPO_PORT = 5432
DIGNA_REPO_DB = "postgres"
DIGNA_REPO_SCHEMA = "dignarepo"
DIGNA_REPO_USER = "digna_user"
DIGNA_REPO_PASSWORD = "YourSecurePassword123!"
DIGNA_REPO_SSLMODE = "prefer"
DIGNA_REPO_NUM_CONNS = 16
```

| Παράμετρος | Τιμή | Σημειώσεις |
|---|---|---|
| `DIGNA_REPO_HOST` | `localhost` ή IP | Hostname/IP του PostgreSQL server |
| `DIGNA_REPO_PORT` | `5432` (προεπιλογή) | Θύρα PostgreSQL |
| `DIGNA_REPO_DB` | `postgres` | Όνομα βάσης |
| `DIGNA_REPO_SCHEMA` | `dignarepo` | Το schema που δημιουργήθηκε νωρίτερα |
| `DIGNA_REPO_USER` | `digna_user` | Ο χρήστης που δημιουργήθηκε στη ρύθμιση του PostgreSQL |
| `DIGNA_REPO_PASSWORD` | Ο κωδικός σας | Κωδικός που ορίσατε κατά τη δημιουργία του schema |
| `DIGNA_REPO_SSLMODE` | `prefer` (προεπιλογή) | Προαιρετικό. Λειτουργία SSL του PostgreSQL: `disable`, `allow`, `prefer`, `require`, `verify-ca` ή `verify-full` |
| `DIGNA_REPO_NUM_CONNS` | `16` (προεπιλογή) | Προαιρετικό. Αριθμός συνδέσεων που διατηρεί ανοιχτές το digna προς το repository |

#### Ενότητα [base]

Αυτή η ενότητα περιέχει ρυθμίσεις ασφάλειας, cookies και επιθεωρήσεων:

```toml
[base]
DIGNA_FERNET_KEY = "DU4a0yJ-OqvbKCL4hNQn_CsknH-V1vWmHZqBUl-AY44="
DIGNA_COOKIE_DOMAIN = "localhost"
DIGNA_COOKIE_SECURE = false
DIGNA_COOKIE_HTTPONLY = true
DIGNA_TOKEN_EXPIRES_IN = 86400
DIGNA_MAX_WORKERS = 4
DIGNA_FRONTEND_BASEURL = "http://localhost/"
DIGNA_SOURCE_QUERY_TIMEOUT_SEC = 3600
DIGNA_SOURCE_LOGIN_TIMEOUT_SEC = 30
```

| Παράμετρος | Τιμή | Σημειώσεις |
|---|---|---|
| `DIGNA_FERNET_KEY` | Η τιμή που φαίνεται παραπάνω | Κλειδί της κρυπτογράφησης που χρησιμοποιούσαν οι προηγούμενες εκδόσεις. Πρέπει να υπάρχει· διατηρήστε την τιμή που φαίνεται |
| `DIGNA_COOKIE_DOMAIN` | `localhost` | Ο host μέσω του οποίου προσεγγίζεται το dashboard. Το `""` δεν ορίζει domain, κάτι που είναι σωστό πίσω από proxy που σερβίρει το dashboard και το backend κάτω από ένα origin |
| `DIGNA_COOKIE_SECURE` | `false` (HTTP) / `true` (HTTPS) | Πρέπει να είναι `true` όποτε το digna σερβίρεται μέσω HTTPS |
| `DIGNA_COOKIE_HTTPONLY` | `true` | Κρατά το cookie συνεδρίας εκτός πρόσβασης από scripts |
| `DIGNA_TOKEN_EXPIRES_IN` | `86400` (24 ώρες) | Χρόνος λήξης συνεδρίας σε δευτερόλεπτα |
| `DIGNA_MAX_WORKERS` | Αριθμός CPU cores - 1 | Αριθμός επιθεωρήσεων που μπορούν να εκτελούνται ταυτόχρονα |
| `DIGNA_FRONTEND_BASEURL` | URL του dashboard | Υποχρεωτικό. Χρησιμοποιείται για τους συνδέσμους στα μηνύματα ειδοποιήσεων, οπότε πρέπει να είναι URL που μπορούν να ανοίξουν οι παραλήπτες |
| `DIGNA_SOURCE_QUERY_TIMEOUT_SEC` | `3600` (προεπιλογή) | Προαιρετικό. Δευτερόλεπτα που μπορεί να εκτελείται ένα μεμονωμένο ερώτημα σε βάση δεδομένων πηγής πριν διακοπεί· το `0` απενεργοποιεί το χρονικό όριο |
| `DIGNA_SOURCE_LOGIN_TIMEOUT_SEC` | `30` (προεπιλογή) | Προαιρετικό. Δευτερόλεπτα αναμονής για σύνδεση με βάση δεδομένων πηγής· το `0` περιμένει επ' αόριστον |

#### Ενότητα [encryption]

Αυτή η ενότητα περιέχει το κλειδί που χρησιμοποιείται για την κρυπτογράφηση ευαίσθητων τιμών που αποθηκεύονται στο repository. Είναι **υποχρεωτική** — το `config check` αναφέρει την ενότητα `[encryption]` ως FAILED αν λείπει το κλειδί.

```toml
[encryption]
DIGNA_ENCRYPTION_KEY = 'ycELf6IbcO55dYIZHpPv6kQv/bbnUXoIaHLh2bh1kMg='
```

| Παράμετρος | Τιμή | Σημειώσεις |
|---|---|---|
| `DIGNA_ENCRYPTION_KEY` | Κλειδί κωδικοποιημένο σε Base64 | Κρυπτογραφεί ευαίσθητες τιμές που αποθηκεύονται στο repository digna |

!!! warning "Προστατέψτε το config.toml"

    Αυτό το κλειδί είναι σταθερή τιμή, ίδια σε όλες τις εγκαταστάσεις digna, και είναι αυτό που αποκρυπτογραφεί τις ευαίσθητες τιμές του repository σας. Περιορίστε το `config.toml` στον λογαριασμό που εκτελεί το digna, κρατήστε το αρχείο εκτός συστήματος ελέγχου εκδόσεων και κοινόχρηστων δίσκων και εξαιρέστε το από κάθε αντίγραφο ασφαλείας που φυλάσσεται λιγότερο ασφαλώς από το ίδιο το repository.

#### Ενότητα [logging]

Αυτή η ενότητα διαμορφώνει τη συμπεριφορά logging:

```toml
[logging]
DIGNA_LOGGING_MODE = "INFO"
DIGNA_LOGGING_DIR = "logs"
DIGNA_LOGGING_MAX_FILES = 30
```

| Παράμετρος | Τιμή | Σημειώσεις |
|---|---|---|
| `DIGNA_LOGGING_MODE` | `INFO` ή `DEBUG` | `INFO` για παραγωγή, `DEBUG` για αντιμετώπιση προβλημάτων. Γίνονται επίσης δεκτά τα `TRACE`, `WARN` και `ERROR` |
| `DIGNA_LOGGING_DIR` | `logs` (προεπιλογή) | Προαιρετικό. Κατάλογος για τα εναλλασσόμενα αρχεία log, σχετικά με τον κατάλογο εργασίας |
| `DIGNA_LOGGING_MAX_FILES` | `30` (προεπιλογή) | Προαιρετικό. Αριθμός εναλλασσόμενων αρχείων log που διατηρούνται |

!!! warning "Διατηρήστε τον κατάλογο log όταν εκτελείται ως υπηρεσία"

    Μια υπηρεσία Windows δεν έχει κονσόλα, οπότε τα αρχεία log είναι η μόνη καταγραφή του τι κάνει η υπηρεσία. Μην ορίσετε το `DIGNA_LOGGING_DIR` σε κενή συμβολοσειρά, κάτι που απενεργοποιεί τα αρχεία log.

#### Ενότητα [duckdb] (Προαιρετική) {: #duckdb-section }

Νέο στην Έκδοση 2026.11. Αυτή η ενότητα ορίζει τους πόρους του **digna Engine**, το οποίο κάνει profiling δεδομένων μέσα στο digna για συνδέσεις βάσεων δεδομένων με τοποθεσία profiling **digna Engine**, και εκτελεί ελέγχους ακεραιότητας αναφορών μεταξύ πηγών δεδομένων σε διαφορετικές συνδέσεις βάσεων δεδομένων. Δείτε [Τοποθεσία Profiling](../../../platform/profiling/profiling_location.md).

Η ενότητα είναι προαιρετική. Χωρίς αυτήν ισχύουν οι παρακάτω προεπιλογές.

```toml
[duckdb]
DIGNA_DUCKDB_MEMORY_LIMIT_MB = 1024
DIGNA_DUCKDB_TEMP_DIRECTORY = "C:\\path\\to\\digna\\tmp"
```

| Παράμετρος | Τιμή | Σημειώσεις |
|---|---|---|
| `DIGNA_DUCKDB_MEMORY_LIMIT_MB` | `1024` (προεπιλογή) | Μνήμη, σε MB, που μπορεί να χρησιμοποιήσει μία εκτέλεση του digna Engine. Έως `DIGNA_MAX_WORKERS` εκτελέσεις μπορούν να είναι ενεργές ταυτόχρονα |
| `DIGNA_DUCKDB_TEMP_DIRECTORY` | Προεπιλογή: ο προσωρινός κατάλογος του λογαριασμού που εκτελεί το digna (`%TEMP%`) | Κατάλογος για προσωρινά αρχεία όταν τα δεδομένα δεν χωρούν στη μνήμη |

!!! tip "Διαστασιολόγηση του digna Engine"

    Προβλέψτε έως `DIGNA_MAX_WORKERS` × `DIGNA_DUCKDB_MEMORY_LIMIT_MB` μνήμης στον host του digna, επιπλέον όσης χρησιμοποιεί το ίδιο το digna, και αρκετό ελεύθερο χώρο στον δίσκο του προσωρινού καταλόγου ώστε να χωρά η μεγαλύτερη επιθεωρούμενη ημερομηνία των πηγών δεδομένων που χρησιμοποιούν το digna Engine. Ορίστε το `DIGNA_DUCKDB_TEMP_DIRECTORY` σε δίσκο με αυτόν τον χώρο, εγγράψιμο από τον λογαριασμό που εκτελεί το digna:

    ```cmd
    mkdir C:\path\to\digna\tmp
    ```

    Χρειάζεστε αυτή την ενότητα μόνο αν τουλάχιστον μία σύνδεση βάσης δεδομένων χρησιμοποιεί το digna Engine ή αν ένας έλεγχος ακεραιότητας αναφορών συγκρίνει πηγές δεδομένων σε διαφορετικές συνδέσεις.

Πριν αρχικοποιήσετε το repository, ελέγξτε ότι το `config.toml` είναι πλήρες και σωστά δομημένο. Στον κατάλογο εγκατάστασης digna εκτελέστε:

```bash
digna config check
```

Κάθε ενότητα επικυρώνεται ξεχωριστά, ώστε ένα μεμονωμένο σφάλμα να μην κρύβει την κατάσταση των υπολοίπων:

```text
Configuration validation report (source: config.toml):
 - App config: OK
 - Repository config: OK
 - Base config: OK
 - Logging config: OK
 - Encryption config: OK
 - OIDC config(s): OK
 - Template overrides: OK
 - Unknown keys: OK

Overall: OK
```

Διορθώστε ό,τι αναφέρεται ως FAILED και εκτελέστε ξανά την εντολή πριν συνεχίσετε. Ένα WARNING κάτω από το **Unknown keys** παραθέτει κλειδιά του `config.toml` που το digna δεν διαβάζει· δεν έχουν καμία επίδραση, οπότε αφαιρέστε τα ή διορθώστε τη γραφή τους. Ο πλήρης κατάλογος επιλογών βρίσκεται στην [αναφορά CLI](../../../cli/Command_Line_Interface_202611.md).

### Βήμα 3: Αρχικοποίηση του Repository

1. Ανοίξτε Command Prompt
2. Πλοηγηθείτε στον κατάλογο εγκατάστασης του digna (όπου βρίσκονται `config.toml` και το εκτελέσιμο `digna`)
3. Εκτελέστε τον έλεγχο σύνδεσης:

```bash
digna repo check
```

Σε ένα νέο schema, η εντολή συνδέεται και στη συνέχεια αναφέρει ότι δεν έχει εγκατασταθεί ακόμη repository:

```text
Error: No repo installed. Use the 'digna repo upgrade' command to install it.
```

Σε αυτό το σημείο αυτό είναι το αναμενόμενο αποτέλεσμα: επιβεβαιώνει ότι το digna φτάνει στο PostgreSQL και στο schema. Ένα σφάλμα σύνδεσης ή ελέγχου ταυτότητας, αντίθετα, παραπέμπει στην ενότητα `[repo]` ή στη ρύθμιση του PostgreSQL.

### Βήμα 4: Εγκατάσταση του Schema του Repository

Στον ίδιο κατάλογο, εκτελέστε:

```bash
digna repo upgrade
```

Αυτή η εντολή εγκαθιστά τους απαραίτητους πίνακες στο schema του repository και ολοκληρώνεται με:

```text
✅ Repo schema 'dignarepo' is up to date.
```

!!! note "Το repo upgrade εγκαθιστά και αναβαθμίζει"

    Από την Έκδοση 2026.11, το `repo upgrade` εγκαθιστά ένα νέο repository και αναβαθμίζει ένα υπάρχον. Το `repo install` εξακολουθεί να λειτουργεί ως άλλο όνομα για την ίδια εντολή.

### Βήμα 5: Δημιουργία Χρήστη Διαχειριστή

Ο χρήστης διαχειριστή δημιουργείται απευθείας στο schema του repository, οπότε ο server δεν χρειάζεται ακόμη να εκτελείται. Στον κατάλογο εγκατάστασης της digna, εκτελέστε:

```bash
digna user add <email> <password> "<display_name>" --admin
```

**Παράδειγμα:**

```bash
digna user add admin@example.com "AdminPassword123!" "Admin User" --admin
```

Αυτό δημιουργεί έναν χρήστη με πλήρη δικαιώματα διαχειριστή.

!!! tip "Καλύτερη Πρακτική"

    Χρησιμοποιήστε έναν ισχυρό κωδικό με μείγμα κεφαλαίων, πεζών, αριθμών και ειδικών χαρακτήρων.

### Βήμα 6: Εκκίνηση του digna Server

Στον κατάλογο εγκατάστασης του digna, ξεκινήστε τον server με:

```bash
digna serve --address <host> --port <port>
```

**Παράμετροι:**
- `--address` — Hostname/IP του server (προεπιλογή `127.0.0.1`)
- `--port` — Θύρα του server (προεπιλογή `8000`)

Όταν ο server είναι σε λειτουργία, εμφανίζει τη διεύθυνση στην οποία ακούει:

```text
Server running on http://127.0.0.1:8082
```

!!! note "Ο διακομιστής δεσμεύει το τερματικό"

    Το `serve` εκτελείται στο προσκήνιο και συνεχίζει μέχρι να το σταματήσετε με ++ctrl+c++. Αφήστε το να εκτελείται όσο ολοκληρώνετε την εγκατάσταση· για αυτόματη εκκίνηση κατά την εκκίνηση του συστήματος, δείτε [Εκτέλεση του digna ως υπηρεσίας Windows](#running-digna-as-a-windows-service).

## Διαμόρφωση Dashboard {: #dashboard-configuration }

### Βήμα 1: Ανάπτυξη του Dashboard στον Web Server

Το digna dashboard διαβάζει τη δική του διαμόρφωση από το `dashboard/dashboard_config.toml`. Το αρχείο αυτό δεν παρέχεται με την εγκατάσταση — το δημιουργείτε στον κατάλογο `dashboard/`, δίπλα στα αρχεία του dashboard.

Το περιεχόμενό του περιγράφεται στην ενότητα [Ενιαία Σύνδεση (SSO)](../../../sso/overview.md), όπου και χρειάζεται το αρχείο: περιέχει τις επιλογές σύνδεσης που προσφέρει το dashboard και, για αναπτύξεις πολλαπλών instances, τη σύνδεση με το backend.

Επιλέξτε τον web server σας και ακολουθήστε τα αντίστοιχα βήματα ανάπτυξης.

#### Ανάπτυξη στο IIS

1. **Άνοιγμα IIS Manager**
   - Πατήστε `Win + R`, πληκτρολογήστε `inetmgr`, πατήστε Enter

2. **Δημιουργία Νέου Website**
   - Στο αριστερό πάνελ, κάντε δεξί κλικ στο **Sites**
   - Επιλέξτε **Add Website...**

3. **Διαμόρφωση του Website**
   - **Site Name**: Εισάγετε ένα όνομα (π.χ., "dignaDashboard")
   - **Physical Path**: Κάντε κλικ στο Browse και επιλέξτε τον φάκελο `dashboard`
   - **Binding**: Ορίστε διεύθυνση IP και θύρα (προεπιλεγμένη θύρα 80 για HTTP, 443 για HTTPS)

4. **Έναρξη του Website**
   - Κάντε κλικ στο **OK** για να δημιουργήσετε τον ιστότοπο
   - Κάντε δεξί κλικ στο νέο site και επιλέξτε **Start**

5. **Έλεγχος Εγκατάστασης**
   - Ανοίξτε τον browser σας
   - Μεταβείτε στο `http://localhost` (ή στο ρυθμισμένο URL)
   - Πρέπει να δείτε τη σελίδα εισόδου του digna dashboard

#### Ανάπτυξη σε Apache Tomcat

1. **Αντιγραφή Dashboard στο Tomcat**
   - Αντιγράψτε το φάκελο `dashboard` στον κατάλογο `webapps` του Tomcat
   - Μετονομάστε τον αν χρειάζεται (π.χ., σε `digna`)
   - Παράδειγμα: `C:\Program Files\Apache Tomcat\webapps\digna`

2. **Επαλήθευση Ανάπτυξης**
   - Ανανέωση ή φόρτωση της διαχειριστικής σελίδας του Tomcat (http://localhost:8080)
   - Θα πρέπει να δείτε το "digna" (ή το όνομα που επιλέξατε) στη λίστα των αναπτυγμένων εφαρμογών

3. **Πρόσβαση στο Dashboard**
   - Ανοίξτε τον browser σας
   - Μεταβείτε στο `http://localhost:8080/digna`
   - Πρέπει να δείτε τη σελίδα εισόδου του digna dashboard

## Εκτέλεση του digna ως Υπηρεσία Windows {: #running-digna-as-a-windows-service }

### Γιατί να χρησιμοποιήσετε Υπηρεσία Windows;

Η εκτέλεση του digna backend ως υπηρεσία Windows διασφαλίζει ότι:
- Ξεκινά αυτόματα όταν κάνει boot ο server
- Τρέχει στο παρασκήνιο χωρίς ανοιχτό παράθυρο Command Prompt
- Επανεκκινείται αυτόματα αν παρουσιαστεί σφάλμα
- Μπορεί να διαχειρίζεται μέσω των Windows Services

### Οι Εντολές `windows`

Η υπηρεσία διαχειρίζεται από το ίδιο το εκτελέσιμο `digna`, μέσω των υποεντολών `digna windows`. Δεν υπάρχουν αρχεία batch προς εκτέλεση.

| Εντολή | Σκοπός |
|---|---|
| `digna windows install` | Εγγράφει το digna ως υπηρεσία Windows |
| `digna windows start` | Ξεκινά την εγγεγραμμένη υπηρεσία |
| `digna windows stop` | Σταματά την υπηρεσία που εκτελείται |
| `digna windows uninstall` | Αφαιρεί την εγγραφή της υπηρεσίας |

!!! warning "Απαιτούνται δικαιώματα διαχειριστή"

    Και οι τέσσερις εντολές πρέπει να εκτελούνται από Command Prompt που έχει ανοιχτεί ως Administrator.

Κάθε εντολή δέχεται την επιλογή `--name` για να απευθυνθεί σε υπηρεσία εγγεγραμμένη με μη προεπιλεγμένο όνομα. Η πλήρης λίστα επιλογών βρίσκεται στην [αναφορά του CLI](../../../cli/Command_Line_Interface_202611.md).

### Εγκατάσταση της Υπηρεσίας

1. **Άνοιγμα Command Prompt ως Administrator**
   - Δεξί κλικ στο Command Prompt
   - Επιλέξτε "Run as Administrator"

2. **Πλοήγηση στον κατάλογο εγκατάστασης του digna**
   ```bash
   cd C:\path\to\digna
   ```

3. **Εγγραφή της υπηρεσίας**
   ```bash
   digna windows install
   ```

!!! important "Ορίστε τη διεύθυνση και τη θύρα, εκτός αν σας καλύπτουν οι προεπιλογές"

    Η `install` καταγράφει τη διεύθυνση και τη θύρα στην εγγραφή της υπηρεσίας, και η υπηρεσία δεσμεύεται ακριβώς σε ό,τι καταγράφηκε. Οι προεπιλογές είναι `127.0.0.1` και `8000`, οι οποίες δέχονται συνδέσεις μόνο από το ίδιο το μηχάνημα. Ένα dashboard σε άλλον host δεν μπορεί να συνδεθεί εκεί, οπότε δώστε τη διεύθυνση στην οποία θα ακούει το backend:

    ```bash
    digna windows install --address 0.0.0.0 --port 8082
    ```

    Οι τιμές αυτές δεν διαβάζονται από το `config.toml`. Για να τις αλλάξετε αργότερα, απεγκαταστήστε την υπηρεσία και εγκαταστήστε την ξανά με τις νέες τιμές.

Η υπηρεσία εγγράφεται με **αυτόματη εκκίνηση**, οπότε θα ξεκινά μαζί με τα Windows. Δεν ξεκινά αμέσως — δείτε την επόμενη ενότητα.

#### Επιλογές Εγκατάστασης

| Επιλογή | Προεπιλογή | Σκοπός |
|---|---|---|
| `--name` | `digna` | Όνομα με το οποίο εγγράφεται η υπηρεσία |
| `--display-name` | `digna` | Όνομα που εμφανίζεται στο services.msc |
| `--description` | `digna data quality backend` | Περιγραφή που εμφανίζεται στο services.msc |
| `--address` | `127.0.0.1` | Διεύθυνση στην οποία η υπηρεσία δεσμεύει το API της |
| `--port` | `8000` | Θύρα στην οποία η υπηρεσία δεσμεύει το API της |
| `--working-dir` | ο κατάλογος του εκτελέσιμου `digna` | Κατάλογος που περιέχει τα `config.toml` και `license.toml`, τον οποίο η υπηρεσία χρησιμοποιεί ως κατάλογο εργασίας |
| `--start-type` | `auto` | Το `auto` ξεκινά με τα Windows, το `manual` ξεκινά μόνο όταν ζητηθεί, το `disabled` εγγράφει την υπηρεσία αλλά αρνείται να την ξεκινήσει |
| `--account` | `LocalSystem` | Λογαριασμός με τον οποίο εκτελείται, π.χ. `DOMAIN\user` ή `.\user` |
| `--password` | | Κωδικός πρόσβασης του `--account` |

!!! tip "Εκτέλεση με λογαριασμό domain"

    Ο `LocalSystem` δεν έχει ταυτότητα δικτύου, οπότε ο Windows Authentication προς τον SQL Server και κάθε πρόσβαση σε κοινόχρηστο φάκελο δικτύου θα αποτύχουν. Εγκαταστήστε με `--account` και `--password` όταν η υπηρεσία πρέπει να έχει πρόσβαση σε πόρους ως συγκεκριμένος χρήστης.

### Εκκίνηση και Σταμάτημα της Υπηρεσίας

#### Για να ξεκινήσετε την υπηρεσία

```bash
digna windows start
```

#### Για να σταματήσετε την υπηρεσία

```bash
digna windows stop
```

!!! tip "Συμβουλή"

    Πάντα σταματάτε την υπηρεσία πριν ενημερώσετε αρχεία της εφαρμογής.

### Μετακίνηση της Υπηρεσίας σε Νέο Κατάλογο

Αν χρειαστεί να μετακινήσετε την εγκατάσταση του digna:

1. **Σταματήστε και αφαιρέστε την εγγραφή της τρέχουσας υπηρεσίας**
   ```bash
   cd C:\old\path\digna
   digna windows stop
   digna windows uninstall
   ```

2. **Μετακίνηση των αρχείων της εφαρμογής**
   - Μετακινήστε ολόκληρο τον φάκελο εγκατάστασης του digna στη νέα τοποθεσία

3. **Εγγράψτε ξανά την υπηρεσία από τη νέα τοποθεσία**
   ```bash
   cd C:\new\path\digna
   digna windows install
   ```

   Επαναλάβετε όσες τιμές `--address`, `--port` ή `--account` χρησιμοποιήσατε την πρώτη φορά — η προηγούμενη εγγραφή δεν υπάρχει πλέον.

4. **Εκκίνηση της υπηρεσίας**
   ```bash
   digna windows start
   ```

### Απεγκατάσταση της Υπηρεσίας

1. **Σταματήστε την Τρέχουσα Υπηρεσία**
   ```bash
   cd C:\path\to\digna
   digna windows stop
   ```

2. **Αφαιρέστε την Εγγραφή της Υπηρεσίας**
   ```bash
   digna windows uninstall
   ```

Η υπηρεσία digna έχει πλέον αφαιρεθεί από τις υπηρεσίες των Windows.

## Αναβάθμιση σε Νέα Έκδοση {: #upgrading-to-a-new-release }

Αυτή η ενότητα αναβαθμίζει μια εγκατάσταση της Έκδοσης 2026.06 στην Έκδοση 2026.11. Αν η εγκατάστασή σας είναι παλαιότερη, διαβάστε πρώτα την ενότητα [Αναβάθμιση από Έκδοση Πριν από την 2026.06](#upgrading-from-a-release-before-2026-06).

### Πριν την Αναβάθμιση

**Η δημιουργία αντιγράφου ασφαλείας (backup) του digna Repository είναι υποχρεωτική**

Πριν αναβαθμίσετε την digna, δημιουργήστε backup του repository σας (PostgreSQL) για προστασία από απώλεια δεδομένων. Ένα backup εξασφαλίζει ότι μπορείτε να ανακτήσετε σε περίπτωση απρόβλεπτων προβλημάτων κατά την αναβάθμιση.

**Αίτηση για το Αρχείο Άδειας της Έκδοσης 2026.11**

Η Έκδοση 2026.11 χρειάζεται νέο `license.toml`. Ζητήστε το από την ομάδα της digna πριν ξεκινήσετε και έχετέ το έτοιμο για το [Βήμα 7](#step-7-replace-the-license-file).

### Αναβάθμιση από Έκδοση Πριν από την 2026.06 {: #upgrading-from-a-release-before-2026-06 }

Η Έκδοση 2026.06 έφερε τρεις αλλαγές που εξακολουθούν να ισχύουν όταν αναβαθμίζετε μια παλαιότερη εγκατάσταση απευθείας στην 2026.11:

- **Μόνο ODBC.** Το digna προσεγγίζει κάθε τεχνολογία πηγής μέσω ODBC. Κάθε σύνδεση βάσης δεδομένων που δεν χρησιμοποιεί ακόμη ODBC πρέπει να μεταφερθεί σε ODBC μετά την αναβάθμιση· δεν υπάρχει αυτόματη μετατροπή. Εγκαταστήστε εκ των προτέρων τα προγράμματα οδήγησης ODBC στον host του digna, δείτε [Εγκατάσταση του ODBC Driver στον Host του digna](../../../databases/overview.md#install-the-driver), και έχετε έτοιμες τις ιδιότητες κάθε σύνδεσης από τους [οδηγούς ανά τεχνολογία](../../../databases/overview.md#technology-guides). Ο σύνδεσμος Databricks Legacy δεν υπάρχει πλέον· μεταφέρετε αυτές τις συνδέσεις στον σύνδεσμο [Databricks](../../../databases/databricks_connector_guide.md).
- **Ένα εκτελέσιμο.** Τα `dignabackend` και `dignacli` αντικαθίστανται από το ενιαίο εκτελέσιμο `digna`, που ενοποιεί το backend και το CLI.
- **config.toml.** Η ενότητα `[encryption]` είναι υποχρεωτική, και τα `DIGNA_APP_HOST` και `DIGNA_APP_PORT` δεν διαβάζονται πλέον: ο server λαμβάνει τη διεύθυνση και τη θύρα του από το `digna serve`. Συγκρίνετε το αρχείο σας με την ενότητα [Διαμόρφωση Backend](#backend-configuration).

Τα παρακάτω βήματα επισημαίνουν πού μια παλαιότερη εγκατάσταση χρειάζεται κάτι διαφορετικό. Η αναβάθμιση του repository στο Βήμα 8 φέρνει ένα repository οποιασδήποτε προηγούμενης έκδοσης απευθείας στην 2026.11.

### Διαδικασία Αναβάθμισης

#### Βήμα 1: Σταματήστε την υπηρεσία digna {: #step-1-stop-the-digna-service }

Ανοίξτε ένα Command Prompt ως Administrator και σταματήστε την υπηρεσία με το εκτελέσιμο `digna` της τρέχουσας εγκατάστασής σας:

```bash
cd C:\path\to\digna
digna windows stop
```

Η υπηρεσία παραμένει καταχωρημένη. Το νέο εκτελέσιμο παίρνει τη θέση του παλιού στον ίδιο κατάλογο, οπότε η καταχώρηση συνεχίζει να δείχνει στο σωστό αρχείο.

Εάν η digna τρέχει σε πρώτο πλάνο, πατήστε ++ctrl+c++ στο παράθυρο Command Prompt της.

!!! warning "Αναβάθμιση από έκδοση πριν από την 2026.06"

    Οι εκδόσεις πριν από την 2026.06 καταχωρούσαν την υπηρεσία με αρχεία batch. Σταματήστε την και καταργήστε την καταχώρησή της με τα αρχεία batch της τρέχουσας εγκατάστασής σας, **πριν** μετονομάσετε οτιδήποτε στο Βήμα 2:

    ```bash
    cd C:\path\to\digna\bin
    stop_service.bat
    uninstall_service.bat
    ```

    Σημειώστε τον λογαριασμό με τον οποίο εκτελούνταν η υπηρεσία, καθώς και τη διεύθυνση και τη θύρα στις οποίες εξυπηρετούσε. Θα καταχωρήσετε ξανά την υπηρεσία στο Βήμα 9.

#### Βήμα 2: Δημιουργήστε αντίγραφο της τρέχουσας εγκατάστασης {: #step-2-backup-current-installation }

Στον κατάλογο εγκατάστασης digna, μετονομάστε το εκτελέσιμο και τον φάκελο του dashboard της τρέχουσας εγκατάστασης, ώστε η νέα έκδοση να μπορεί να αναπτυχθεί δίπλα τους:

```bash
cd C:\path\to\digna
ren digna.exe digna_old.exe
ren dashboard dashboard_old
```

Κρατήστε το `digna_old.exe` μέχρι να επαληθεύσετε την αναβάθμιση και τον `dashboard_old` μέχρι να επαναφέρετε από αυτόν τα αρχεία διαμόρφωσής σας (δείτε το Βήμα 4). Μετά μπορείτε να διαγράψετε και τα δύο.

!!! info "Αναβάθμιση από έκδοση πριν από την 2026.06"

    Μετονομάστε τους φακέλους `dignabackend` και `dignacli` αντί για το εκτελέσιμο: `ren dignabackend dignabackend_old` και `ren dignacli dignacli_old`. Η Έκδοση 2026.11 δεν χρησιμοποιεί κανέναν από αυτούς τους φακέλους, ούτε τον φάκελο `bin` με τα αρχεία batch.

#### Βήμα 3: Αποσυμπίεση και Ανάπτυξη της Νέας Έκδοσης {: #step-3-extract-and-deploy-new-version }

1. Αποσυμπιέστε το νέο πακέτο εγκατάστασης digna ZIP
2. Αντιγράψτε το νέο εκτελέσιμο `digna` και τον φάκελο `dashboard` στον κατάλογο εγκατάστασης

!!! warning "Σημαντικό"

    Ούτε το `config.toml` ούτε το `dashboard/dashboard_config.toml` περιλαμβάνονται ποτέ στο ZIP εγκατάστασης — η ομάδα της digna δεν παρέχει ποτέ κανένα από τα δύο αρχεία. Η υπάρχουσα διαμόρφωσή σας επομένως δεν επηρεάζεται από την αναβάθμιση, και τα αντίγραφα στους μετονομασμένους φακέλους `*_old` είναι τα μόνα που έχετε.

#### Βήμα 4: Επαναφορά των Αρχείων Διαμόρφωσης {: #step-4-restore-your-configuration-files }

```bash
copy dashboard_old\dashboard_config.toml dashboard\dashboard_config.toml
```

Η Έκδοση 2026.11 δεν απαιτεί καμία αλλαγή στο `config.toml`: ένα αρχείο που λειτουργεί με την Έκδοση 2026.06 συνεχίζει να λειτουργεί. Δύο αλλαγές είναι προαιρετικές:

- Προσθέστε μια [ενότητα `[duckdb]`](#duckdb-section) αν οι συνδέσεις βάσεων δεδομένων πρόκειται να χρησιμοποιούν το digna Engine και οι προεπιλογές του δεν ταιριάζουν στον host σας.
- Παραλείψτε την ενότητα `[app]` αν ένας reverse proxy σερβίρει το dashboard και το backend κάτω από ένα origin.

!!! warning "Ρυθμίσεις που το digna δεν διαβάζει"

    Προηγούμενες εκδόσεις αυτού του οδηγού έδειχναν ορισμένες ρυθμίσεις που το digna δεν διαβάζει. Δεν έχουν καμία επίδραση, και το `config check` τις παραθέτει κάτω από το **Unknown keys** στο Βήμα 6. Αφαιρέστε ή διορθώστε τες:

    - Τα `DIGNA_SCHEDULER_MAX_DELAY`, `DIGNA_CLEANUP_TIME`, `digna_COOKIE_PATH`, `digna_COOKIE_SAME_SITE`, `digna_APP_CORS_ALLOW_METHODS`, `digna_APP_CORS_ALLOW_HEADERS` και `digna_LOGGING_BACKUP_COUNT` δεν υπάρχουν. Αφαιρέστε τα.
    - Τα ονόματα των ρυθμίσεων κάνουν διάκριση πεζών-κεφαλαίων. Το digna διαβάζει `DIGNA_REPO_HOST`, όχι `digna_REPO_HOST`. Γράψτε κάθε όνομα με κεφαλαία, όπως στην ενότητα [Διαμόρφωση Backend](#backend-configuration).

!!! warning "Ενιαία σύνδεση: διατηρήστε το [[oidc_clients]]"

    Το digna διαβάζει τους παρόχους ενιαίας σύνδεσης ως λίστα καταχωρήσεων `[[oidc_clients]]`, καθεμία με το δικό της `DIGNA_OIDC_KEY`. Αν αλλάξατε τους παρόχους σας σε ενότητες `[oidc_clients.<key>]`, όπως έδειχνε μια προηγούμενη έκδοση αυτού του οδηγού, επαναφέρετέ τους. Το `config check` αναφέρει το `OIDC config(s)` ως FAILED όσο υπάρχει αυτή η μορφή:

    ```toml
    [[oidc_clients]]
    DIGNA_OIDC_KEY = 'microsoft'
    DIGNA_OIDC_CLIENT_ID = '<client_id>'
    DIGNA_OIDC_CLIENT_SECRET = '<client_secret>'
    DIGNA_OIDC_REDIRECT_URI = 'http://localhost:3000/oidc/callback'
    DIGNA_OIDC_CONFIGURATION_URL = 'https://login.microsoftonline.com/<tenant_id>/v2.0/.well-known/openid-configuration'
    ```

    Επαναλάβετε την καταχώρηση για κάθε πάροχο και διατηρήστε κάθε `DIGNA_OIDC_KEY` ίδιο με το `key` στο `dashboard_config.toml`. Επηρεάζονται μόνο οι εγκαταστάσεις που χρησιμοποιούν ενιαία σύνδεση.

#### Βήμα 5: Επαναφόρτωση του Web Server {: #step-5-reload-the-web-server }

Το dashboard είναι ένα σύνολο στατικών αρχείων, οπότε ο web server σας — και ο browser — μπορεί να εξακολουθούν να σερβίρουν την προηγούμενη έκδοση. Επαναφορτώστε ή επανεκκινήστε τον web server που φιλοξενεί τον φάκελο `dashboard` και στη συνέχεια φορτώστε ξανά τη σελίδα με πλήρη ανανέωση (++ctrl+f5++).

#### Βήμα 6: Επικυρώστε τη διαμόρφωση {: #step-6-validate-the-configuration }

Βεβαιωθείτε ότι το `config.toml` είναι πλήρες πριν αγγίξετε το repository:

```bash
digna config check
```

Κάθε ενότητα πρέπει να αναφέρει OK. Διορθώστε ό,τι αναφέρεται ως FAILED, αφαιρέστε τα κλειδιά που παρατίθενται κάτω από το **Unknown keys** και εκτελέστε ξανά την εντολή πριν συνεχίσετε.

#### Βήμα 7: Αντικατάσταση του Αρχείου Άδειας {: #step-7-replace-the-license-file }

Ένα αρχείο άδειας κανονικά μεταφέρεται από τη μία έκδοση στην επόμενη. Η Έκδοση 2026.11 αποτελεί εξαίρεση: προσθέτει δύο αδειοδοτούμενα modules, το digna Data Reconciliation και το digna Agentic, και μια άδεια που εκδόθηκε πριν από την 2026.11 δεν τα περιέχει. Αντιγράψτε το `license.toml` που σας παρείχε η ομάδα της digna για την Έκδοση 2026.11 στον κατάλογο εγκατάστασης, αντικαθιστώντας το παλιό:

```bash
copy /Y C:\path\to\new\license.toml license.toml
```

!!! warning "Μην κρατήσετε την προηγούμενη άδεια"

    Με την προηγούμενη άδεια το digna εξακολουθεί να ξεκινά, αλλά το digna Data Reconciliation και ο digna MCP Server παραμένουν απενεργοποιημένα. Κάθε εντολή που ελέγχει την άδεια — `user`, `inspection`, `repo` — διακόπτεται πριν αγγίξει το repository όταν ο έλεγχος αποτύχει. Επαληθεύστε τη νέα άδεια πριν προχωρήσετε:

    ```bash
    digna license check
    ```

#### Βήμα 8: Αναβάθμιση του Σχήματος Repository {: #step-8-upgrade-the-repository-schema }

Στον κατάλογο εγκατάστασης της digna, εκτελέστε:

```bash
digna repo upgrade
```

Η Έκδοση 2026.11 διαχειρίζεται το schema του repository με migrations που φέρουν αριθμό έκδοσης. Η πρώτη αναβάθμιση από προηγούμενη έκδοση φέρνει το schema στην τελευταία έκδοση του προηγούμενου μηχανισμού, την καταγράφει ως σημείο εκκίνησης και στη συνέχεια εφαρμόζει τα migrations της Έκδοσης 2026.11. Ολοκληρώνεται με:

```text
✅ Baseline migration recorded as applied.
✅ Repo schema 'dignarepo' is up to date.
```

Όλα τα υπάρχοντα δεδομένα διατηρούνται. Για να δείτε την κατάσταση του repository οποιαδήποτε στιγμή, εκτελέστε `digna repo check`: παραθέτει το πιο πρόσφατο εφαρμοσμένο migration και όσα εκκρεμούν.

!!! warning "Το digna δεν ξεκινά με παρωχημένο repository"

    Από την Έκδοση 2026.11, ο server αρνείται να ξεκινήσει όσο το repository χρειάζεται αναβάθμιση, και το αναφέρει, για παράδειγμα:

    ```text
    Error: Legacy repo version 3.0.2 installed. Use the 'digna repo upgrade' command to upgrade it.
    ```

    Εκτελέστε το `repo upgrade` πριν ξεκινήσετε τον server ή την υπηρεσία.

#### Βήμα 9: Επανεκκίνηση των Υπηρεσιών {: #step-9-restart-services }

Εάν η digna τρέχει ως υπηρεσία Windows, ξεκινήστε την ξανά:

```bash
cd C:\path\to\digna
digna windows start
```

Εάν αναβαθμίσατε από έκδοση πριν από την 2026.06 και καταργήσατε την καταχώρηση της υπηρεσίας στο Βήμα 1, καταχωρήστε την πρώτα ξανά με το εκτελέσιμο `digna`:

```bash
cd C:\path\to\digna
digna windows install --address <address> --port <port>
digna windows start
```

Δώστε στα `--address` και `--port` τις τιμές στις οποίες εξυπηρετούσε η παλιά υπηρεσία, εκτός αν θέλετε τις προεπιλογές `127.0.0.1` και `8000`. Προσθέστε `--account` και `--password` αν η παλιά υπηρεσία εκτελούνταν με λογαριασμό domain. Δείτε [Εκτέλεση του digna ως Υπηρεσία Windows](#running-digna-as-a-windows-service) για την πλήρη λίστα επιλογών.

Εάν τρέχετε χειροκίνητα, επανεκκινήστε τον server:

```bash
cd C:\path\to\digna
digna serve --address <address> --port <port>
```

Εάν χρησιμοποιείτε IIS ή Tomcat, επανεκκινήστε τον αντίστοιχο web server.

#### Βήμα 10: Επαλήθευση της Αναβάθμισης {: #step-10-verify-the-upgrade }

1. Επιβεβαιώστε την έκδοση του νέου εκτελέσιμου:

    ```bash
    digna version
    ```

    Η πρώτη γραμμή πρέπει να είναι `Release: 2026.11`.

2. Ανοίξτε το digna dashboard και επιβεβαιώστε ότι η διεπαφή φορτώνει σωστά.
3. Ελέγξτε τα αρχεία στον κατάλογο `logs` της εγκατάστασης για σφάλματα.
4. Δοκιμάστε τις συνδέσεις βάσεων δεδομένων σας — δείτε [Δοκιμή σύνδεσης](../../../databases/overview.md#testing-a-connection). Μετά από αναβάθμιση από έκδοση πριν από την 2026.06, μεταφέρετε πρώτα σε ODBC κάθε σύνδεση που δεν το χρησιμοποιούσε ήδη.

Για να ξεκινήσετε με τα νέα modules, δείτε [digna Data Reconciliation](../../../platform/data_reconciliation/Introduction.md), [Σύνδεση ενός AI Agent](../../../platform/agentic/connect_ai_agent.md) για τον digna MCP Server και [Τοποθεσία Profiling](../../../platform/profiling/profiling_location.md) για το digna Engine.
