# チェンジログ – リリース 2026.11  

Release 2026.11 は、3 つの主要な追加機能を中心に構成されています:

- **digna Data Reconciliation (Beta)**: システム間を移動するデータの一貫性が保たれていることをチェックします  
- **digna Agentic (Beta)**: digna MCP Server を通じて digna を AI エージェントに開放します  
- **digna Engine**: オプションで digna 内部でデータをプロファイリングし、異なるデータベース技術間の参照整合性チェックを可能にします  

---

## 新機能  

### digna Data Reconciliation (Beta) – ソースからターゲットまでの一貫性  
データはレポートに届くまでに、複数のシステムを経由することがよくあります。digna Data Reconciliation (Beta) は、**ターゲット**のデータソースを、その作成元となった**ソース**と比較し、両者が一致しなくなったときにアラートを出します。

- ターゲットデータソースの新しい **Data Reconciliation** タブで、名前付きルールとして設定します  
- Data Reconciliation を有効にしたプロジェクト内のどのデータソースもソースにできます  
- 標準的な照合手続きや、ETL プロセスの結果の検証などに利用できます  
- ルールは **Exact** と **AI** の 2 種類です  

**Exact ルール – データ品質ルールとしての照合**: データ品質ルールと同じように、1 つのソースと 1 つのターゲットの間で何が一致すべきかを正確に定義します。

  - 1 つのソースデータソースと 1 つのターゲットデータソースを比較  
  - 統計量と属性によって、ターゲットのチェックとソースのチェックを対応付け（例: 行数や金額列の合計）  
  - **absolute** の許容差（例: ± 10）または **relative** の許容差（例: ソースの ± 0.5 %）で差異を許容  
  - タイムラインに、日ごとの差異が許容差と並べて表示されます  

**AI ルール – データオブザーバビリティとしての照合**: digna は、他のモジュールでデータを観測するのと同じ方法で、ターゲットがソースにどのように追従するかを学習し、その関係が崩れたときにアラートを出します。

  - 複数のソースデータソースのチェックを、1 つのターゲットのチェックと組み合わせ  
  - 両者の間のロジック（結合、フィルター、集計）を知る必要も、書き出す必要もありません  
  - モデルが履歴から、ターゲットが同じ日のソースにどう追従するかを学習  
  - 各ターゲットチェックはその日のソースの値から予測され、ターゲットがルール自身の過去の誤差の帯から外れると digna がアラートを出します  
  - 各ルールには独自の **Model settings**（**Sensitivity**、**Memory**、**Model Complexity**）があります  

照合チェックは、ルールごとのタイムラインとともにダッシュボードに表示されます。全体のインスペクションステータスに反映され、通知もトリガーします。

**影響:** 照合の両面をカバーします。Exact ルールはソースとターゲットの間の既知のコントロールを適用し、AI ルールは ETL プロセスのような複雑なフローを監視します。そのため、途中で失われたり変更されたりしたデータを、手書きの照合 SQL なしで検出できます。

---

### digna Agentic (Beta) – AI エージェントのための digna  
digna Agentic (Beta) の最初のバージョンです。AI エージェントが digna と連携し、データに関するビジネス上の質問に答え、設定の改善を支援できるようになりました。

**digna MCP Server**: Claude などの AI エージェントが、Model Context Protocol を通じて digna と連携できるようにします。

  - プロジェクト、データソース、ルール、インスペクションスケジュール、サブスクリプションを管理  
  - アラートを調査するため、インスペクションステータスを個々のチェックまで読み取り  

**データソースと属性の説明**: データソースや属性に何が含まれているかを平易な言葉で記述します。

  - AI エージェントは説明を使ってデータを解釈します  
  - データについてビジネス上の質問をすると、digna が監視している内容をもとに AI エージェントが回答します  
  - digna の現在の設定では質問に答えられない場合、AI エージェントは可能な範囲でデータソースとその属性の変更（例: 新しいデータセットの追加）を提案します  

**影響:** データに関するビジネス上の質問を平易な言葉で行えるようになり、AI エージェントが digna の設定やデータ品質の問題の調査を支援できるようになります。

---

### digna Engine – プロファイリングの場所を選択  
digna はデフォルトで、データが存在する場所、つまりソースデータベース内でデータをプロファイリングします。digna Engine はもう 1 つの選択肢を追加します。digna がソースからデータをエクスポートし、digna Engine 内でプロファイリングします。

- 必須ではなくオプションです。ソースデータベースでのプロファイリングも引き続き利用できます  
- データベース接続ごとに **プロファイリングの場所**（profiling location）として **Source Database** または **digna Engine** を選択します  
- サポートされているすべてのソース技術で利用できます  

**接続をまたぐ参照整合性**: 一部のチェックでは、データのエクスポートが必要です。digna Engine は、こうしたケースに向けて **digna Data Validation** を拡張します。

  - **異なるデータベース接続**上のデータソース間での **参照整合性チェック**。異なるデータベース技術（例: Oracle と PostgreSQL）間にも対応  
  - どちらのプロファイリングの場所でも動作します。Source Database の場合は、キー列だけが digna Engine にエクスポートされます  
  - チェックが 2 つの接続をまたいで実行される場合、ダッシュボードにその旨が表示されます  

**影響:** データをどこでプロファイリングするかを選択できるようになり、異なるデータベース技術で動作するシステム間の関係を担保できます。

## プロファイリングの強化  

本リリースでは、何をどのようにプロファイリングするかについても、ユーザーがより細かく制御できるようになりました。

### クエリ属性（Query Attributes） – ユーザー定義の列  
- 人工的な列を定義: データソースの 1 つ以上の列に対する SQL 式  
- 各クエリ属性には独自の名前があります  
- 他の属性と同じようにプロファイリング・チェックされます  

### DATE 列カテゴリ  
- 属性向けの新しい **Date** カテゴリ  
- インスペクション対象日を基準にしたメトリクス  

### オンデマンドプロファイリング  
- インスペクションを実行せずに、任意の属性を 1 日分の完全なスナップショットに対してプロファイリング  
- 属性の列タイプ（**Numerical**、**Categorical**、**Date**、**Unspecified**）の設定に役立ちます

- **データ品質＆ガバナンスチーム:** digna Engine によるデータベース技術をまたいだ参照整合性  
- **ビジネスユーザー:** digna Agentic (Beta) を使った AI エージェントによる、データに関するビジネス上の質問への回答  
- **AI・自動化チーム:** digna Agentic (Beta) を通じて digna と連携する AI エージェント
