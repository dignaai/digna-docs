## Введение {: #introduction }

### О digna

digna — это полнофункциональная платформа с поддержкой ИИ, разработанная для оптимизации управления качеством данных в различных средах хранения данных, таких как хранилища, data lakes и lakehouses. Платформа создана с учетом масштабируемости и адаптируемости и решает современные задачи с помощью автоматизации, мониторинга в реальном времени и обнаружения аномалий.

digna состоит из двух основных компонентов:

- **dignabackend**: основной движок приложения, отвечающий за обработку данных и выполнение проверок качества.
- **dignadashboard**: веб-интерфейс, размещаемый на веб-сервере, обеспечивающий удобный способ взаимодействия с платформой digna и визуализации метрик качества данных.

### Что нового в Release 2026.06

В этом релизе возможности наблюдаемости данных (data observability) интегрированы непосредственно в ваш код, что позволяет разработчикам отслеживать качество данных у источника. См. [заметки к выпуску](http://docs.digna.ai/changelog/Release_202606/) для полного списка изменений.

### Ищете macOS или Linux?

Это руководство охватывает Windows. Для других платформ смотрите [Руководство по установке для macOS](../../macOS/Release%202026.06/installation_guide_digna_macos_2026_06.md) или [Руководство по установке для Linux](../../Linux/Release%202026.06/installation_guide_digna_linux_2026_06.md).

## Требования к системе {: #system-requirements }

Перед началом установки убедитесь, что ваша система соответствует следующим минимальным требованиям:

| Требование | Характеристика |
|---|---|
| **Операционная система** | Windows Server или Windows 10/11 |
| **Память (минимальная конфигурация)** | 16 ГБ ОЗУ |
| **Место на диске** | 10 ГБ свободного пространства |
| **База данных** | PostgreSQL Server 12 или выше |
| **Веб-сервер** | IIS, Apache Tomcat или эквивалент |

### Варианты установки базы данных

**Если PostgreSQL уже установлен:**
Вы можете добавить новую базу данных для digna в ваш существующий сервер PostgreSQL.

**Если вы устанавливаете PostgreSQL на той же машине, что и digna:**

!!! info "Рекомендуемые характеристики"

    - **Память**: 32 ГБ ОЗУ (вместо 16 ГБ)
    - **Место на диске**: 50 ГБ свободного пространства (вместо 10 ГБ)

    Эти увеличенные характеристики учитывают одновременную работу digna и сервера PostgreSQL.

## Настройка PostgreSQL сервера {: #postgresql-server-setup }

### Если PostgreSQL уже установлен

Если PostgreSQL уже установлен и запущен на вашей локальной машине или если вы используете управляемый удалённый сервер PostgreSQL, вы можете перейти к следующему разделу — [настройка веб-сервера](#web-server-configuration).

### Установка PostgreSQL

Выполните следующие шаги для установки PostgreSQL на Windows:

#### Шаг 1: Загрузите PostgreSQL

1. Перейдите на [страницу загрузок PostgreSQL](https://www.postgresql.org/download/)
2. Выберите **Windows**
3. Скачайте последний установщик

#### Шаг 2: Запустите установщик

1. Дважды щёлкните по загруженному файлу установщика
2. Следуйте подсказкам мастера установки

#### Шаг 3: Выберите каталог установки

Выберите каталог, в который будет установлен PostgreSQL. Обычно местоположение по умолчанию подходит.

#### Шаг 4: Выберите компоненты

Для стандартной установки оставьте выбранными компоненты по умолчанию.

#### Шаг 5: Задайте пароль суперпользователя PostgreSQL

Введите и подтвердите пароль для суперпользователя PostgreSQL (`postgres`). **Храните этот пароль в надёжном месте** — он понадобится вам позже.

#### Шаг 6: Настройте номер порта

Порт PostgreSQL по умолчанию — `5432`. Вы можете оставить значение по умолчанию или указать другой порт при необходимости.

!!! tip "Совет"

    Если порт 5432 уже занят, выберите альтернативный порт и запомните его для последующей конфигурации.

#### Шаг 7: Выберите локаль

Выберите локаль для вашей базы данных. Обычно значение по умолчанию подходит.

#### Шаг 8: Завершите установку

Нажимайте **Далее** до конца, затем **Готово**.

#### Шаг 9: Проверьте установку

Откройте Command Prompt и проверьте установку PostgreSQL:

```bash
psql --version
```

Если установка прошла успешно, вы увидите версию PostgreSQL.

## Настройка веб-сервера {: #web-server-configuration }

digna требует веб-сервер для размещения dashboard. Выберите один из следующих вариантов:

- [Internet Information Services (IIS)](#iis-setup)
- [Apache Tomcat](#apache-tomcat-setup)

Вам нужно установить и настроить только **один** из этих серверов.

### Настройка IIS {: #iis-setup }

#### Обзор

Internet Information Services (IIS) — веб-сервер Microsoft для размещения веб-сайтов и веб-приложений.

#### Включение IIS

1. **Откройте Панель управления**
   - Нажмите `Win + R`
   - Введите `control` и нажмите Enter

2. **Перейдите к компонентам Windows**
   - Нажмите **Программы**
   - Выберите **Включение или отключение компонентов Windows**

3. **Включите Internet Information Services**
   - Пролистайте вниз и найдите **Internet Information Services (IIS)**
   - Установите флажок для его включения
   - Нажмите **+**, чтобы развернуть и убедиться, что выбраны следующие подсистемы:
     - **Web Management Tools**
     - **World Wide Web Services**

4. **Нажмите OK**, чтобы применить изменения

5. **Проверьте установку IIS**
   - Откройте браузер
   - Перейдите по адресу `http://localhost`
   - Вы должны увидеть страницу приветствия IIS

#### Требуется: модуль URL Rewrite

IIS требует компонента URL Rewrite. Скачайте и установите его с [официальной страницы Microsoft](https://www.iis.net/downloads/microsoft/url-rewrite).

#### Требуется: MIME-тип для файлов Markdown

Чтобы файлы Markdown (`.md`) корректно отдавались через IIS:

1. Откройте **IIS Manager** (нажмите `Win + R`, введите `inetmgr`, нажмите Enter)
2. Перейдите к **Ваш сайт > MIME Types**
3. Нажмите **Add...**
4. Настройте:
   - **File name extension**: `.md`
   - **MIME type**: `text/markdown`

!!! warning "Важно"

    Без этой настройки файлы `.md` могут не обслуживаться корректно.

### Настройка Apache Tomcat {: #apache-tomcat-setup }

#### Обзор

Apache Tomcat — это open-source контейнер сервлетов Java и веб-сервер.

#### Установка

1. **Скачайте Apache Tomcat**
   - Перейдите на [страницу загрузок Apache Tomcat](https://tomcat.apache.org/download-90.cgi)
   - Скачайте ZIP-распространение для Windows

2. **Распакуйте архив**
   - Распакуйте ZIP-файл в каталог на вашей системе
   - Пример: `C:\Program Files\Apache Tomcat`

3. **Проверьте запуск Tomcat**
   - Откройте браузер
   - Перейдите по адресу `http://localhost:8080`
   - Вы должны увидеть страницу приветствия Apache Tomcat

!!! tip "Совет"

    Apache Tomcat обычно запускается автоматически после установки. Если этого не произошло, перейдите в папку `bin` и запустите `startup.bat`.

## Первоначальная установка {: #initial-installation }

### Шаг 1: Настройка репозитория digna

Репозиторий digna хранит все метрики, вычисляемые digna. Он служит центральной базой данных для аналитических и служебных данных.

#### Создание схемы репозитория и пользователя

Откройте ваш клиент PostgreSQL (pgAdmin, psql или аналогичный) и выполните следующие SQL-команды:

```sql
CREATE SCHEMA <digna_repo_schema>;

CREATE USER <digna_repo_user> WITH PASSWORD '<digna_repo_password>';

GRANT ALL PRIVILEGES ON SCHEMA <digna_repo_schema> TO <digna_repo_user>;
```

**Замените следующие заполнители:**

- `<digna_repo_schema>` — желаемое имя схемы (например, `dignarepo`)
- `<digna_repo_user>` — желаемое имя пользователя (например, `digna_user`)
- `<digna_repo_password>` — надёжный пароль для этого пользователя

**Пример:**

```sql
CREATE SCHEMA dignarepo;

CREATE USER digna_user WITH PASSWORD 'YourSecurePassword123!';

GRANT ALL PRIVILEGES ON SCHEMA dignarepo TO digna_user;
```

!!! tip "Рекомендация"

    Используйте сложные пароли для пользователей базы данных. Избегайте легко угадываемых учётных данных.

---

### Шаг 2: Распакуйте установочный пакет digna

1. Найдите ZIP-файл установщика digna, предоставленный вам
2. Распакуйте его в желаемый каталог установки
3. После распаковки вы должны увидеть следующие элементы:
   - `dashboard/` — веб-интерфейс
   - `digna` — основной исполняемый файл (backend + CLI в одном)
   - `config.toml` — файл конфигурации
   - `license.toml` — файл лицензии (скопируйте ваш сюда)

### Шаг 3: Установите файл лицензии

!!! warning "Важно"

    Файл лицензии **не** включён в установочный пакет и предоставляется отдельно компанией digna.

1. Найдите предоставленный вам файл `license.toml`
2. Скопируйте его в корневой каталог установки digna (где находятся `config.toml` и исполняемый файл `digna`)

**Почему это важно:**
Файл лицензии содержит информацию о заказчике, дате окончания лицензии и цифровую подпись. **Не изменяйте этот файл** — любые изменения сделают его недействительным.

**Структура каталогов после настройки:**

```
digna_installation/
├── config.toml         (configuration file)
├── license.toml        (YOUR LICENSE FILE - copy here)
├── digna               (main executable)
└── dashboard/          (web interface)
    └── (dashboard files)
```

## Конфигурация backend {: #backend-configuration }

### Шаг 1: Создание и редактирование файла конфигурации

Файл `config_template.toml` поставляется в каталоге установки digna. Вам нужно переименовать его в `config.toml`.

**Расположение:** `digna_installation/config.toml`

Откройте `config.toml` в текстовом редакторе и настройте каждый из разделов ниже.

#### Раздел [app]

Этот раздел настраивает параметры приложения backend digna:

```toml
[app]
digna_APP_HOST = "localhost"
digna_APP_PORT = 8082
digna_APP_CORS_ALLOW_ORIGINS = ["http://localhost:5173"]
digna_APP_CORS_ALLOW_CREDENTIALS = true
digna_APP_CORS_ALLOW_METHODS = ["*"]
digna_APP_CORS_ALLOW_HEADERS = ["*"]
```

| Параметр | Значение | Примечания |
|---|---|---|
| `digna_APP_HOST` | `localhost` или IP-адрес | Хост или IP, где развернут dignabackend |
| `digna_APP_PORT` | `8082` (по умолчанию) | Порт для REST API |
| `digna_APP_CORS_ALLOW_ORIGINS` | URL фронтенда | Если dashboard находится на другом сервере, добавьте его URL |
| `digna_APP_CORS_ALLOW_CREDENTIALS` | `true` | Требуется при использовании CORS с учётными данными |
| `digna_APP_CORS_ALLOW_METHODS` | `["*"]` | Разрешить все HTTP-методы |
| `digna_APP_CORS_ALLOW_HEADERS` | `["*"]` | Разрешить все заголовки |

#### Раздел [repo]

Этот раздел настраивает подключение к базе данных PostgreSQL:

```toml
[repo]
digna_REPO_HOST = "localhost"
digna_REPO_PORT = 5432
digna_REPO_DB = "postgres"
digna_REPO_SCHEMA = "dignarepo"
digna_REPO_USER = "digna_user"
digna_REPO_PASSWORD = "YourSecurePassword123!"
```

| Параметр | Значение | Примечания |
|---|---|---|
| `digna_REPO_HOST` | `localhost` или IP | Хост/IP сервера PostgreSQL |
| `digna_REPO_PORT` | `5432` (по умолчанию) | Порт PostgreSQL |
| `digna_REPO_DB` | `postgres` | Имя базы данных |
| `digna_REPO_SCHEMA` | `dignarepo` | Ранее созданная схема |
| `digna_REPO_USER` | `digna_user` | Пользователь, созданный при настройке PostgreSQL |
| `digna_REPO_PASSWORD` | Ваш пароль | Пароль, заданный при создании пользователя |

#### Раздел [base]

Этот раздел содержит настройки безопасности и cookie:

```toml
[base]
digna_FERNET_KEY = "your-fernet-key"
digna_COOKIE_DOMAIN = "localhost"
digna_COOKIE_PATH = "/"
digna_COOKIE_SECURE = false
digna_COOKIE_HTTPONLY = true
digna_COOKIE_SAME_SITE = "lax"
digna_TOKEN_EXPIRES_IN = 86400
digna_MAX_WORKERS = 4
```

| Параметр | Значение | Примечания |
|---|---|---|
| `digna_FERNET_KEY` | Ключ шифрования | Используется для шифрования токенов и cookie (по умолчанию предоставлен) |
| `digna_COOKIE_DOMAIN` | `localhost` | Соответствует домену фронтенда |
| `digna_COOKIE_SECURE` | `false` (локально) / `true` (в проде) | Используйте `true` при HTTPS |
| `digna_COOKIE_HTTPONLY` | `true` | Всегда включено для безопасности |
| `digna_COOKIE_SAME_SITE` | `lax` | Защищает от CSRF атак |
| `digna_TOKEN_EXPIRES_IN` | `86400` (24 часа) | Время жизни сессии в секундах |
| `digna_MAX_WORKERS` | Количество ядер CPU - 1 | Количество параллельных задач инспекции |

#### Раздел [logging]

Этот раздел настраивает поведение логирования:

```toml
[logging]
digna_LOGGING_MODE = "INFO"
digna_LOGGING_BACKUP_COUNT = 10
```

| Параметр | Значение | Примечания |
|---|---|---|
| `digna_LOGGING_MODE` | `INFO` или `DEBUG` | `INFO` для продакшена, `DEBUG` для отладки |
| `digna_LOGGING_BACKUP_COUNT` | `10` | Количество сохраняемых ежедневных резервных логов |

### Шаг 3: Инициализируйте репозиторий

1. Откройте Command Prompt
2. Перейдите в каталог установки digna (где находятся `config.toml` и исполняемый файл `digna`)
3. Проверьте подключение:

```bash
digna repo check
```

Вы должны увидеть подтверждение того, что подключение установлено (сам репозиторий ещё не инициализирован).

### Шаг 4: Установите схему репозитория

В том же каталоге выполните:

```bash
digna repo install
```

Эта команда создаст необходимые таблицы и схему в вашей базе данных PostgreSQL.

### Шаг 5: Запустите сервер digna

В каталоге установки digna запустите сервер:

```bash
digna serve --address <host> --port <port>
```

**Параметры:**
- `--address` — имя хоста или IP сервера
- `--port` — порт сервера

Вы должны увидеть сообщения при старте, подтверждающие запуск сервера:

```
INFO:     Started server process [1234]
INFO:     Waiting for application startup.
INFO:     Application startup complete
INFO:     Uvicorn running on http://localhost:8082
```

### Шаг 6: Создайте пользователя с правами администратора

1. Откройте **новое** окно Command Prompt
2. Перейдите в каталог установки digna
3. Выполните команду для создания администратора:

```bash
digna user add <username> "<full_name>" <password> --su
```

**Пример:**

```bash
digna user add admin "Admin User" AdminPassword123! --su
```

Это создаст пользователя с полными административными правами.

!!! tip "Рекомендация"

    Используйте надёжный пароль, содержащий большие и малые буквы, цифры и специальные символы.

## Конфигурация Dashboard {: #dashboard-configuration }

### Шаг 1: Разверните Dashboard на веб-сервере

В каталоге `dashboard/` находится отдельный файл `config.toml` для dashboard. Эта конфигурация уже предоставлена и в большинстве случаев не требует изменений на этапе первоначальной установки. Изменять её нужно только в случае необходимости настроек подключения к backend или для мультиинстансных развертываний.

Если требуется изменить конфигурацию dashboard, обратитесь к документации dashboard.

Выберите ваш веб-сервер и выполните соответствующие шаги развертывания.

#### Развёртывание в IIS

1. **Откройте IIS Manager**
   - Нажмите `Win + R`, введите `inetmgr`, нажмите Enter

2. **Создайте новый веб-сайт**
   - В левой панели правой кнопкой щёлкните **Sites**
   - Выберите **Add Website...**

3. **Настройте сайт**
   - **Site Name**: Введите имя (например, "dignaDashboard")
   - **Physical Path**: Нажмите Browse и выберите папку `dashboard`
   - **Binding**: Укажите IP-адрес и порт (по умолчанию 80 для HTTP, 443 для HTTPS)

4. **Запустите сайт**
   - Нажмите **OK**, чтобы создать сайт
   - Правой кнопкой щёлкните новый сайт и выберите **Start**

5. **Проверьте установку**
   - Откройте браузер
   - Перейдите по `http://localhost` (или по вашему URL)
   - Вы должны увидеть страницу входа в digna dashboard

#### Развёртывание в Apache Tomcat

1. **Скопируйте Dashboard в Tomcat**
   - Скопируйте папку `dashboard` в директорию `webapps` вашего Tomcat
   - При необходимости переименуйте (например, в `digna`)
   - Пример: `C:\Program Files\Apache Tomcat\webapps\digna`

2. **Проверьте развёртывание**
   - Обновите или перезагрузите страницу управления Tomcat (http://localhost:8080)
   - Вы должны увидеть "digna" (или выбранное имя) в списке развернутых приложений

3. **Доступ к Dashboard**
   - Откройте браузер
   - Перейдите по адресу `http://localhost:8080/digna`
   - Вы должны увидеть страницу входа в digna dashboard

## Запуск digna как службы Windows {: #running-digna-as-a-windows-service }

### Почему использовать службу Windows?

Запуск backend digna как службы Windows обеспечивает:
- Автоматический старт при загрузке сервера
- Фоновый режим работы без открытого окна командной строки
- Автоматический перезапуск при падении
- Управление через оснастку Windows Services

### Файлы управления службой

Все необходимые файлы находятся в каталоге установки digna в подкаталоге: `bin/`

Доступные batch-файлы:
- `install_service.bat` — регистрирует digna как службу Windows
- `uninstall_service.bat` — удаляет регистрацию службы
- `start_service.bat` — запускает службу
- `stop_service.bat` — останавливает службу

!!! warning "Требуются права администратора"

    Все batch-файлы должны выполняться с правами администратора.

### Установка службы

1. **Откройте Command Prompt от имени администратора**
   - Правой кнопкой щёлкните Command Prompt
   - Выберите "Запуск от имени администратора"

2. **Перейдите в папку bin**
   ```bash
   cd C:\path\to\digna\bin
   ```

3. **Запустите скрипт установки**
   ```bash
   install_service.bat
   ```

Сервер digna зарегистрирован как служба Windows с настройкой **автоматического запуска**. Сама служба при этом не запускается автоматически — см. следующий раздел о её запуске.

### Запуск и остановка службы

#### Чтобы запустить службу

1. Откройте Command Prompt от имени администратора
2. Перейдите в `digna\bin`
3. Выполните:
   ```bash
   start_service.bat
   ```

#### Чтобы остановить службу

1. Откройте Command Prompt от имени администратора
2. Перейдите в `digna\bin`
3. Выполните:
   ```bash
   stop_service.bat
   ```

!!! tip "Совет"

    Всегда останавливайте службу перед обновлением файлов приложения.

### Перенос службы в новый каталог

Если требуется переместить установку digna:

1. **Удалите текущую службу**
   ```bash
   cd C:\old\path\digna\bin
   uninstall_service.bat
   ```

2. **Переместите файлы приложения**
   - Перенесите весь каталог установки digna в новое расположение

3. **Переустановите службу**
   ```bash
   cd C:\new\path\digna\bin
   install_service.bat
   ```

4. **Запустите службу**
   ```bash
   start_service.bat
   ```

### Удаление службы

1. **Остановите работающую службу**
   ```bash
   cd C:\path\to\digna\bin
   stop_service.bat
   ```

2. **Удалите регистрацию службы**
   ```bash
   uninstall_service.bat
   ```

Сервер digna теперь удалён из списка служб Windows.

## Обновление до новой версии {: #upgrading-to-a-new-release }

### Перед обновлением

**Обязательно создайте резервную копию репозитория digna**

Перед обновлением выполните резервное копирование вашей базы данных (PostgreSQL), чтобы защитить данные от потери.
Резервная копия позволит восстановиться в случае непредвиденных проблем при обновлении.

### Процесс обновления

#### Шаг 1: Остановите службу digna

Если digna работает как служба Windows, сначала остановите её:

```bash
cd C:\path\to\digna\bin
stop_service.bat
```

#### Шаг 2: Резервное переименование текущей установки backend

В каталоге установки digna выполните:

```bash
# Переименовать папку с dignabackend
ren dignabackend dignabackend_old
```
```bash
# Переименовать dashboard
ren dashboard dashboard_old
```

#### Шаг 3: Распакуйте и разверните новую версию

1. Распакуйте новый ZIP-файл установки digna
2. Скопируйте новый исполняемый файл `digna` и папку `dashboard` в каталог установки

!!! warning "Важно"

    Файл `config.toml` **никогда** не включается в ZIP-архив установки. Ваша существующая конфигурация остаётся в безопасности.

### Шаг 4: Восстановите файлы конфигурации

```bash
copy dashboard_old\dashboard_config.toml dashboard\dashboard_config.toml
```

### Шаг 5: Обновите схему репозитория

Перейдите в каталог установки digna и выполните:

```bash
digna repo upgrade
```

Эта команда обновит схему PostgreSQL до последней версии, сохранив все существующие данные.

### Шаг 6: Перезапустите службы

Если вы используете службу Windows:

```bash
cd C:\path\to\digna\bin
start_service.bat
```

Если вы запускаете вручную, перезапустите сервер:

```bash
cd C:\path\to\digna
digna serve --address <address> --port <port>
```

Если вы используете IIS или Tomcat, перезапустите соответствующий веб-сервер.

#### Шаг 7: Проверьте корректность обновления

1. Откройте digna dashboard
2. Убедитесь, что интерфейс загружается корректно
3. Проверьте логи сервера на наличие ошибок
